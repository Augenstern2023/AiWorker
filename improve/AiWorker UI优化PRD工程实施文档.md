# AiWorker UI 优化 PRD 工程实施文档

**版本**：V1.0  
**依据**：[UI优化方案.md](UI优化方案.md)  
**产品范围**：WebGUI 本地协作工作平台  
**目标读者**：产品、前端、后端、测试、短剧运营与制作负责人

## 1. 背景与目标

AiWorker 已具备选品、策划、编剧、审核、项目协作、Worker、用户与角色授权等业务能力。当前问题不在于缺少功能，而在于这些能力分散在多个页面，加载和任务反馈不一致，部分页面在等待接口、生成任务或权限受限时缺少连续、可理解的体验。

本期将 WebGUI 升级为面向短剧生产协作的响应式工作台：用户进入页面后，应立即看见当前工作上下文、可执行的下一步和可信的系统状态；页面在慢接口或后台任务运行时仍保持可操作。

### 1.1 本期目标

1. 统一应用壳、导航、页面标题、上下文工具栏、通知和状态组件。
2. 优化已有选品、策划、编剧、审核、项目与系统管理页面，不改变业务链路。
3. 以异步分区渲染、请求取消、去重和精确缓存减少重复加载与主线程阻塞。
4. 让加载、空数据、权限不足、表单错误、后台任务失败和重试均有一致的可访问反馈。
5. 在桌面、平板和手机上保持核心任务可完成，并完整支持键盘与 `prefers-reduced-motion`。

### 1.2 非目标

- 不改变 `creative/`、`workflow/`、`identity/`、`runtime/` 的业务状态机、数据库模型和接口语义。
- 不新增与当前短剧生产流程无关的营销首页、个人作品集、通用 CRM 或全局搜索能力。
- 不替换 Bootstrap、Bootstrap Icons、Alpine.js 和现有原生 JavaScript 技术路线。
- 不引入 WebGL、Three.js、背景视频、外部字体、重型动画库或重型前端框架。
- 不把 UI 改造作为修改用户、角色、Worker、审批或审计权限的理由。

## 2. 现有实现与复用约束

| 层级 | 当前实现 | 本期要求 |
| --- | --- | --- |
| 应用壳 | `templates/layouts/base.html` | 保留服务端渲染、CSRF Meta、动态导航和权限提示；扩展为可折叠、可访问的响应式工作区壳。 |
| 样式 | `static/css/workspaces.css` | 沿用深色 token 和 Bootstrap 基础，收敛颜色、间距、状态、焦点及断点规则。 |
| 页面状态 | `static/js/common/tasks.js` 的 `appData()` | 不迁移现有工作流状态；拆出可复用的 UI 请求、缓存和通知能力，按页面按需初始化。 |
| 请求封装 | `static/js/common/api.js` | 保留 Cookie、CSRF、401 跳转和 403 事件；补充统一错误对象、请求 ID、取消和可选缓存辅助。 |
| 路由与导航 | `web/page_routes.py`、`web/navigation_service.py`、`identity/permission_catalog.py` | 只使用登记路由和现有授权决策；不得以前端隐藏代替后端鉴权。 |
| 业务接口 | `/api/creative/*`、`/api/workflow/*`、`/api/jobs*`、`/api/admin/*` | 最大化复用。仅当现有接口无法提供页面必需聚合信息时，增加只读、权限校验明确的最小接口。 |
| 测试 | `tests/test_webgui_ui_changes.py`、权限与工作流测试 | 新增页面结构、状态逻辑、权限和缓存失效测试；不破坏现有源码级 UI 断言。 |

### 2.1 必须保留的权限边界

- 导航仍由 `NavigationService` 依据页面访问授权生成。
- API 的权限和项目范围仍由 `current_principal`、`require_permission`、`PageAccessService` 与各 Repository/Service 决定。
- UI 仅依据服务端返回的 `can_*` 字段和权限结果控制操作可见性；服务端仍是最终裁决者。
- 403、401、404、409、422、503 应分别映射到用户能理解的说明，不得统一显示为“系统错误”。

| --- | --- | --- |

| 创意策划 | 领取任务、编辑 Brief/人物关系、提交审批 | 可区分草稿、保存中、已保存、生成中、已提交和已退回；失败不丢编辑内容。 |

## 4. 信息架构与页面规范

### 4.1 导航与应用壳

保留以下已有导航域，按现有权限动态显示：我的任务、选品工作台、创意策划、编剧工作台、审核中心、项目管理、团队管理、系统管理。

桌面端侧栏宽度维持约 248px；平板端可收窄为图标导航；小于 768px 时变为可打开/关闭的导航抽屉。导航抽屉必须：

- 有可见的打开和关闭按钮，按钮包含 `aria-label`。
- 打开后将键盘焦点移入抽屉；Escape 关闭并将焦点返回菜单按钮。
- 关闭后不遮挡主内容，不依赖 hover 展开。
- 当前路由必须有文本、图标和可见激活状态。

工作区页在主内容第一行使用统一上下文栏：

- 左侧：面包屑/工作域、页面标题、最多一行状态说明。
- 中间：仅放页面已有能力支持的筛选、项目选择或搜索摘要；不虚构全局搜索接口。
- 右侧：页面刷新、主操作和必要的次级操作。一个页面只有一个视觉主按钮。

### 4.2 页面优先级

| 级别 | 页面 | UI 交付 |
| --- | --- | --- |
| P0 | 基础布局、我的任务、选品工作概览 | 统一壳、移动导航、状态通知、异步分区、工作概览和任务操作反馈。 |
| P0 | 策划/编剧项目与编辑页 | 项目阶段、编辑/保存/生成状态、侧栏上下文、响应式编辑布局。 |
| P1 | 审核中心、项目管理、Worker/机器任务 | 筛选、任务详情抽屉、进度、失败重试、日志摘要。 |
| P1 | 选品列表（榜单、爆款、选题库） | 筛选摘要、表格移动端回退、骨架、空/错状态、请求去重。 |
| P2 | 用户、角色、组织、审计、数据与交付 | 管理表格体验、受限状态、高风险确认与增量加载。 |

### 4.3 页面状态合同

每个异步区域必须在以下状态中恰有一种可见状态。区域高度和关键控件位置在 `loading` 与 `ready` 之间保持稳定。

| 状态 | 呈现 | 必须提供 |
| --- | --- | --- |
| `idle` | 首次尚未请求 | 页面壳和区域标题。 |
| `loading` | 与最终布局同几何的 Skeleton；短动作可用局部 Spinner | `aria-busy="true"`，不能遮住其他区域。 |
| `ready` | 正常数据 | 最近刷新时间或数据源时间（接口提供时）。 |
| `empty` | 说明没有什么、为何为空、下一步 | 创建/清除筛选/前往上游页面等一个明确操作。 |
| `error` | 友好错误卡，不清空旧数据 | 原因、影响说明、Retry；含请求 ID 时可复制。 |
| `forbidden` | 权限受限说明 | 返回可访问模块或联系项目负责人提示。 |
| `stale` | 继续显示最近成功数据 | “当前显示最近一次成功加载的数据”与刷新操作。 |

## 5. 功能需求

### 5.1 工作概览与我的任务

#### 工作概览

当前 `/selection/dashboard` 同时由 `static/js/selection/dashboard.js` 与 `appData()` 发起选题请求，且前者读取 `limit=500`。本期改为一个页面控制器负责数据加载，消除重复请求。

- 指标区按“待处理/风险 -> 今日选题 -> 参考数据”排序。
- P0 仅复用现有选题和分析接口；若要展示跨项目待办、失败工作流或项目动态，新增一个只读聚合接口，而非在浏览器端串行扫描多个列表。
- 统计卡必须可跳转到已存在的页面或该页面已有的筛选状态；没有可用路由时仅显示指标，不伪造按钮。
- 数据加载失败时各区单独降级，参考统计失败不应阻塞待办/选题区。

#### 我的任务

- 使用现有 `/api/workflow/tasks` 与服务端返回的 `can_claim`、`can_start`、`can_assign`。
- 每行至少展示任务类型、项目、状态、负责人、最近更新和下一步动作。
- 领取、开始、分配、改派、取消操作只在服务端已授权时呈现；提交时按钮显示 loading 并防止重复点击。
- 点击任务打开上下文抽屉；抽屉失败时保留列表，局部显示 Retry。

### 5.2 策划与编剧工作区

- 项目列表优先展示项目名、当前阶段、负责人、最近更新和下一任务，不用大面积图片替代生产信息。
- Brief、人物关系、全剧大纲、Beats 和剧本页面采用桌面双栏：主编辑区 + 次级上下文；上下文包括项目阶段、当前版本、任务状态、负责人和审核摘要。
- 小于 1200px 时次级上下文移动到编辑区下方；小于 768px 时将关键操作固定在不遮挡编辑内容的底部操作条或标题行。
- 自动保存、手动保存、生成、提交必须使用不同文案和状态：`未保存`、`保存中`、`已保存`、`生成中`、`已提交`、`已退回`。
- 保存/生成错误不得清空 textarea 或已编辑结构化字段。离开含未保存编辑的页面时使用浏览器离开提示或页面内确认。
- 版本选择使用 tabs/下拉等同级导航；状态不可编辑的版本仍可查看和下载，编辑入口应说明锁定原因。

### 5.3 审核、项目管理与后台任务

- 审核页以待审核、需修改、已通过为同级筛选，显示计数和当前筛选摘要。
- 项目页优先显示阶段、阻塞项、成员任务、提交/审核状态；活动历史折叠展示，避免挤占首屏。
- 机器任务和 Worker 页必须区分 `queued`、`running`、`succeeded`、`failed`、`cancelled` 等既有状态，并同时显示文字、图标和颜色。
- 可计算进度显示进度条、百分比和阶段文案；无法计算的短操作仅在触发区域显示 Spinner。
- 失败任务提供既有重试能力或“查看日志摘要”。如果后端没有可重试接口，UI 只展示日志和说明，不生成无效 Retry 按钮。
- 停止任务、删除任务、撤销访问、修改角色等高风险操作使用确认对话框，明确对象、不可逆后果和确认按钮文本。

### 5.4 选品与管理列表

- 榜单、爆款与选题库使用一致工具栏：平台、时间、状态等筛选；已生效筛选必须可见并可逐项清除。
- 桌面表格使用粘性表头和固定操作列。手机端优先转为单项列表；确需横向滚动时，只保留最小必要列并提示可滚动。
- 数据、审计、用户、角色和交付列表必须分页或游标加载；列表的刷新、翻页、筛选和搜索均可取消旧请求。
- 搜索文本输入使用 300ms 防抖；请求参数、游标和筛选条件组成稳定缓存键。

### 6.2 公共前端接口

`static/js/common/ui-state.js` 需提供以下无框架 API；全部在浏览器中运行，不改变后端接口。

```js
window.aiworkerUi = {
  requestKey(key, factory),
  cancelRequest(key),
  readCache(key),
  writeCache(key, value, {ttlMs}),
  invalidateCache(prefix),
  announce(message, {priority: 'polite'}),
  showToast({kind, title, message}),
  setButtonLoading(button, {loading, label}),
};
```

- `requestKey` 为同一 `key` 维护一个 `AbortController`，新的请求先取消旧请求；`factory(signal)` 必须将 `signal` 传给 `aiworkerApi.request`。
- `readCache` 返回 `{value, stale}` 或 `null`；缓存仅放非敏感、已在当前会话获得授权的数据。
- `writeCache` 使用内存为默认存储。仅筛选偏好可写入 `sessionStorage`；不得把用户、权限、任务详情、日志或创作正文写入 `localStorage`。
- `announce` 更新唯一 live region；`showToast` 同时提供视觉 Toast 和非阻塞文本通知。
- `setButtonLoading` 保存并恢复原 `disabled`、文案和 `aria-busy`，避免重复提交。

`aiworkerApi.request` 保持既有参数兼容，并补充以下接口约束：

```text
ApiError extends Error
  status: number
  message: string
  requestId: string | null
  response: Response

request(input: RequestInfo | URL, options?: RequestInit & {signal?: AbortSignal}): Promise<Response>
```

错误消息优先读取 JSON 的 `detail` 或 `message`，请求 ID 读取 `X-Request-ID`。401 继续跳转 `/login`；403 继续触发 `aiworker:permission-denied`，同时抛出 `PermissionError` 使页面可收束自己的 loading 状态。

### 6.3 缓存与失效

| 数据 | 存储 | TTL | 写操作后的失效前缀 |
| --- | --- | ---: | --- |
| 页面筛选、折叠面板偏好 | `sessionStorage` | 当前会话 | 本人清除筛选或显式重置。 |
| 选题列表/概览统计 | 内存 SWR | 30 秒 | `creative:topics`，于采纳、生成、归档或刷新成功后失效。 |
| 工作流任务列表/详情 | 内存 SWR | 15 秒 | `workflow:tasks`，于领取、开始、分配、改派、取消后失效。 |
| 项目摘要/资源版本 | 当前页面内存 | 30 秒 | `creative:project:{id}`，于保存、提交、审批、退回或版本切换后失效。 |
| 运行中 Job | 内存 | 5 秒 | `jobs`，于停止、完成、失败或重试后失效。 |
| 用户、角色、导航 | 不持久化的会话内存 | 60 秒 | `identity:`/`navigation:`，于登录、登出、权限或导航更新后失效。 |

所有缓存键必须包含当前页面权限上下文或在用户切换/登出时整体清空。缓存刷新失败且有旧值时，页面显示旧值并标记 `stale`；没有旧值时显示 Error State。

### 6.4 后端最小扩展

P0 不强制新接口。仅在工作概览需要跨域聚合且现有接口不能以两个并行请求满足时，新增：

```text
GET /api/workspace/overview
```

返回只包含当前 `Principal` 已有权限可查看的聚合信息：

```json
{
  "pending_task_count": 3,
  "blocked_project_count": 1,
  "candidate_topic_count": 12,
  "recent_activity": [],
  "generated_at": "2026-08-11T10:00:00+08:00"
}
```

要求：接口使用 `current_principal`；Repository 层按当前可见范围查询；不得在响应中包含无权项目、用户、文件路径、Cookie、Token 或完整日志。若该接口新增，需在 `web/page_access_catalog.py` 登记其 GET 权限映射，并为角色/项目可见性添加测试。

## 7. 交互、错误与无障碍要求

### 7.1 统一错误映射

| HTTP/场景 | 用户文案 | 处理 |
| --- | --- | --- |
| 401 | 登录已失效，请重新登录后继续。 | 跳转登录；保留本页可恢复草稿到内存。 |
| 403 | 你没有执行此操作的权限，请联系项目负责人。 | 保留只读内容；不显示重试。 |
| 404 | 该内容可能已被删除或你已无权查看。 | 返回列表或刷新当前区域。 |
| 409 | 当前内容已被其他操作更新，请刷新后再试。 | 保留输入，提示刷新/比较。 |
| 422 | 请检查标记的字段后重新提交。 | 聚焦第一个无效字段。 |
| 503/网络失败 | 暂时无法完成操作，已保留当前内容。 | 局部 Retry 与 request ID。 |
| AbortError | 已停止过期请求。 | 静默，不显示失败 Toast。 |

### 7.2 表单、对话框与通知

- 字段在失焦或提交后校验，错误放在字段邻近位置，并以 `aria-describedby` 关联。
- 写操作使用 Loading Button；同一操作的请求进行中不可重复发起。
- 短操作使用局部 Spinner，后台生成使用进度条/阶段文本；不得用全页遮罩阻止阅读或导航。
- Bootstrap modal 继续用于明确阻塞的确认操作；打开时管理焦点，Escape 与关闭按钮可用，关闭后焦点返回触发元素。
- Toast 用于成功、已在后台继续等暂态信息；错误区域必须保留，不能只闪现 Toast。

### 7.3 动效

- 仅使用 `opacity` 和 `transform`，时长不超过 180ms；进入位移不超过 16px，hover 位移不超过 2px。
- 必须在 `@media (prefers-reduced-motion: reduce)` 关闭过渡、进入动画与自动滚动，确保内容立即出现。
- 动画、hover 和鼠标指针不承载关键信息，也不作为操作前提。

## 8. 分阶段实施计划

### Phase UI-1：基础工作台壳与请求能力（P0）

**交付目标**：任何工作空间页面均有一致布局、响应式导航、live region、Toast、焦点样式和可取消请求能力。

**修改范围**：`base.html`、`workspaces.css`、`api.js`、新增 `ui-state.js`、`tasks.js`、相关 UI 测试。

**验收**：

- 侧栏在手机端可键盘打开/关闭，焦点行为正确。
- 401/403 保持既有安全行为；接口错误可被页面捕获并结束 loading。
- 任何页面不再无条件执行 `fetchJobs()`；仅任务/后台需要时加载。
- 页面包含一个 `aria-live="polite"` 状态区域和可复用 Toast 容器。

### Phase UI-2：工作概览、任务与选品列表（P0/P1）

**交付目标**：工作概览变为可行动的入口；任务和选品页面具备 Skeleton、空/错/过期缓存状态、筛选摘要和取消旧请求。

**修改范围**：`selection/dashboard.html`、`selection/dashboard.js`、任务模板/脚本、选品列表模板/脚本；只有无法满足聚合需求时新增只读 overview API。

**验收**：

- `/selection/dashboard` 对每种数据只发起一次加载请求，不使用 `limit=500` 只为统计总数。
- 选题加载失败不影响分析统计展示，反之亦然。
- 领取/开始/分配任务时可防重复提交，成功后精确失效 `workflow:tasks`。
- 列表筛选切换不会因旧请求回写新的筛选结果。

### Phase UI-3：策划、编剧、审核与项目协作（P0/P1）

**交付目标**：编辑型页面清楚表达项目、阶段、版本、保存和生成状态；审核与项目管理页面聚焦待处理项和阻塞信息。

**修改范围**：`templates/planning/*`、`templates/writing/*`、`templates/review/*`、`static/js/common/creative.js`、`static/js/review/*` 与页面专属样式。

**验收**：

- 编辑失败不丢失输入，用户可重试或安全离开。
- 已锁定/审批版本为只读状态，页面说明不可编辑原因并保留查看/下载。
- 后台生成仅占用相关动作；用户仍可查看项目上下文和切换页面。
- 审核、退回、通过、改派和取消遵从既有服务端权限与任务状态。

### Phase UI-4：系统管理、性能收口与视觉回归（P1/P2）

**交付目标**：管理页面的长列表、错误、高风险操作和小屏体验一致；完成性能与可访问性回归。

**修改范围**：`templates/admin/*`、`static/js/admin/*`、`workspaces.css`、测试与浏览器回归脚本。

**验收**：

- 用户、角色、审计、数据、交付、后台任务可分页/增量加载，并有独立 Empty/Error/Retry。
- 删除、停止、授权变更等操作有明确影响说明和确认文本。
- 桌面 1440px、平板 1024px、手机 390px 下无文本遮挡、控制项溢出或不可访问操作。
- reduced motion、Tab、Escape、焦点可见性和屏幕阅读器通知均通过检查。

## 9. 测试与质量门禁

### 9.1 单元与接口测试

- 为 `ui-state.js` 的缓存 TTL、前缀失效、请求取消、去重和 AbortError 静默处理添加浏览器或可执行的脚本级测试。
- 为 `api.js` 覆盖 JSON `detail` 解析、`X-Request-ID`、401、403 和 signal 透传。
- 扩展 `tests/test_webgui_ui_changes.py`：验证基础模板包含 live region/导航控件、工作概览不再重复请求、关键页面具有稳定 Skeleton 与状态容器。
- 如新增 `/api/workspace/overview`，覆盖匿名、无权限、项目范围过滤和管理员返回结果。
- 保持 `tests/test_page_authorization.py`、`tests/test_page_api_authorization.py`、`tests/test_workflow_api.py`、`tests/test_creative_workflow_integration.py` 通过。

### 9.2 浏览器回归

- 使用具备页面访问授权的选品运营、创意策划、编剧、项目负责人和系统管理员账号验证导航差异。
- 在 1440px、1024px、390px 宽度截图检查：侧栏、工具栏、表格、抽屉、弹窗、按钮和长中文文本。
- 验证键盘 Tab 顺序、focus-visible、Escape 关闭和关闭后焦点返回。
- 使用 reduced-motion 模式确认内容不被动画隐藏。
- 在慢网络或模拟 503 下确认局部加载/失败不会使整页白屏或冻结。

### 9.3 性能预算

| 项目 | 预算/约束 |
| --- | --- |
| 首屏资源 | 只加载当前路由的必需资源；不新增外部字体、WebGL、背景视频。 |
| 新增依赖 | 默认 0；若必须新增，需给出体积、替代方案和首屏影响。 |
| 后台请求 | 不可见页面不高频轮询；运行中任务以 5 秒起始、指数退避轮询。 |
| 长列表 | 分页、游标或虚拟化；禁止一次渲染全部历史记录。 |
| 图片/预览 | 明确尺寸或 `aspect-ratio`；非首屏 `loading="lazy"`。 |
| 响应反馈 | 预计超过 300ms 的操作立即显示局部 loading；可计量任务显示进度。 |

## 10. 发布、回滚与观测

- 以阶段为单位发布，每阶段独立可验收、可回滚，不与工作流/权限迁移绑在同一发布中。
- 新增前端缓存默认只在内存或 `sessionStorage`，移除脚本或清缓存即可回退；不得依赖难以清理的持久化数据。
- 所有 API 错误 UI 保留 `X-Request-ID` 供管理员在 `logs/webgui.log` 和审计记录中定位。
- Phase UI-1 发布后记录：页面首次加载请求数、重复请求数、失败重试率、任务操作重复提交率和关键页面的交互耗时。
- 若发生权限展示与服务端拒绝不一致、缓存越权、编辑内容丢失或页面不可操作，立即关闭相关前端优化开关/缓存路径并回退至直接请求模式。

## 11. 总体验收清单

- [ ] 现有后端接口、Worker、工作流、用户、角色和权限分配逻辑未被 UI 改造破坏。
- [ ] 各角色只看见其已有授权范围内的导航、数据和操作；直接访问仍由服务端拦截。
- [ ] 任何工作区页面都有清晰标题、上下文、一个主操作及 loading/empty/error/forbidden/stale 状态。
- [ ] 任务、生成、保存和审批操作不重复提交，失败不丢数据，成功和失败均有可理解反馈。
