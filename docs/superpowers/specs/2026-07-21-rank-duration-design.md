# 今日榜单在榜时长设计

## 目标

在今日榜单的“热评”右侧新增“在榜时长”字段，同时展示剧目在同一平台、同一榜单中的连续在榜天数和累计在榜天数。

## 计算口径

- 统计身份由平台、榜单分组和剧目标识共同组成；同一剧目在不同榜单分别计算。
- 连续在榜从最近一次重新上榜开始计算。某天存在同一榜单分组的数据、但该剧目不在其中时，中断连续记录；如果该天没有该榜单分组的数据，则视为未知而不是下榜。
- 缺少整天榜单快照时不视为下榜；连续天数使用连续区间起止日期的自然日差加一。
- 累计在榜按剧目实际出现过的自然日去重统计，同一天存在多份快照只计一天。
- 当前首次上榜显示“连续在榜1天 / 累计在榜1天”。
- 下榜记录保留其上一期最后一次出现时的连续和累计天数。
- 统计只使用所选快照及之前的历史数据，查看历史日期时不得引用未来快照。

## 数据流

`TodayRankService` 在完成快照选择后，对所选快照及上一期快照的记录附加：

```json
{
  "continuous_rank_days": 3,
  "cumulative_rank_days": 8
}
```

历史计算按榜单分组建立每日出现集合。同一天多份快照合并出现集合；然后按日期顺序为每个身份累计出现日期，并在每个存在榜单数据的日期检查是否明确缺席，以确定最近一次连续区间。

## 展示

- 后端列定义在 `hot_comment` 后固定追加 `rank_duration`。
- 前端兜底列定义保持相同顺序。
- 单元格显示：`连续在榜3天 / 累计在榜8天`。
- 数据缺失时显示 `-`，不使用推测值。
- 列宽保持紧凑但允许完整显示最长的常规文案。

## 测试与验收

- 连续三天出现时显示连续 3 天、累计 3 天。
- 中途明确缺席后重新出现时，连续天数重置，累计天数继续增加。
- 同一天多份快照只增加一个累计天数。
- 历史日期查询不会计入未来出现日期。
- “在榜时长”列位于“热评”右侧，并在红果与抖音榜单共用。
