# 今日爆款状态操作设计

## 目标

今日爆款列表的操作按钮必须同时反映选题状态和拆解进度，避免已采纳剧目仍出现“不跟进”，也避免已拆解剧目继续显示成首次“拆解”。

## 状态规则

| 拆解状态 | 选题状态 | 可见操作 |
| --- | --- | --- |
| 未拆解 | `pending_review` | 采纳、拆解、不跟进 |
| 未拆解 | `adopted` | 拆解 |
| 未拆解 | `rejected` | 重新采纳 |
| 拆解草稿 | 非 `archived` | 继续拆解、归档 |
| 已有锁定拆解 | 非 `archived` | 再次拆解、归档 |
| 任意 | `archived` | 不提供操作 |

“已拆解”指选题存在任意草稿或锁定拆解版本。选题列表接口除现有的 `locked_breakdown_id` 外，返回 `latest_breakdown_id`、`latest_breakdown_version` 和 `latest_breakdown_status`，供列表准确区分未拆解、拆解草稿和已锁定拆解。

“继续拆解”和“再次拆解”沿用普通拆解入口，优先加载最新版本并打开编辑器，不直接触发模型重新生成。用户需要重新分析脚本时，在编辑器内明确点击“重新生成”。“归档”和“重新采纳”继续调用现有选题状态更新接口。

选题库的拆解列必须显示三态：`未拆解`、`草稿 vN · 待锁定`、`已锁定 vN`。如果最新版本是草稿但还存在较早的锁定版本，则显示 `草稿 vN · 已有锁定版`，避免把草稿误报成未生成。

创作项目仍只允许从锁定拆解创建，但已采纳选题下拉框必须展示全部已采纳选题。没有锁定版本的选项置为不可选，并在名称后标注 `未拆解` 或 `草稿 vN，需先锁定`；已有锁定版本的选项保持可选。这样用户能看见选题及其不可用原因，而不是让选题直接消失。

## 交互与验收

- 已采纳行不显示“采纳”和“不跟进”。
- 不跟进行不重复显示“不跟进”，只显示“重新采纳”。
- 待评估行保持现有三个操作。
- 最新拆解为草稿的行显示“继续拆解”和“归档”；已有锁定拆解的行显示“再次拆解”和“归档”。
- 选题库不再把拆解草稿显示为“未生成”。
- 创作项目选题下拉框可见全部已采纳选题，只有存在锁定拆解的选题可被选择。
- 归档后该行不再提供候选操作。
- 状态更新后按钮立即随本地记录状态切换，不要求手动刷新页面。
