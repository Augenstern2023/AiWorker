# 壹凡短剧选品平台改进方案

## 1. 总体定位

壹凡短剧选品平台应从“榜单采集与数据分析工具”升级为“短剧爆款选题与仿制创作中台”。

平台的核心差异化不应是直接替代 Runway、可灵、即梦、海螺、Sora、Veo 等通用视频生成工具，而是利用自身掌握的真实短剧榜单、评论、热度变化和分析报告，完成以下闭环：

```text
榜单采集 -> 爆款识别 -> 爆款拆解 -> 选题评分 -> 仿制方向 -> 剧本大纲 -> 人物/情节/场景 -> 分镜与制作包
```

也就是说，平台最重要的能力不是“凭空生成视频”，而是“基于真实市场反馈，自动发现可仿制爆款，并生成可落地的短剧创作方案”。

## 2. 市面方案观察

当前市面已有方案大致可分为几类：

| 类型 | 代表方案 | 强项 | 对本平台的启发 |
| --- | --- | --- | --- |
| AI 视频生成 | Runway、Luma、可灵、即梦、海螺、Sora、Veo | 文生视频、图生视频、镜头生成、角色和场景一致性 | 后续可作为分镜生成后的执行层，不宜一开始正面竞争 |
| AI 影视工作流 | LTX Studio、Google Flow/Veo | 脚本、分镜、镜头、场景、视频预演 | 平台应补齐“脚本到分镜”的结构化工作流 |
| 剪辑与模板化生产 | 剪映、CapCut | 脚本转视频、字幕、配音、模板剪辑 | 可学习其低门槛交互和制作包导出 |
| 配音与声音生成 | ElevenLabs 等 | 角色声音、旁白、配音 | 后续可接入分镜制作包，生成配音 prompt 或音频 |
| 通用写作/Agent | ChatGPT、Claude、Gemini 等 | 文本创作、结构化生成、推理 | 可作为剧本、人物、分镜生成的 LLM 底座 |

这些方案普遍缺少垂类短剧市场数据，不天然知道：

- 今天哪些短剧正在爆；
- 哪个题材开始增长；
- 哪些钩子和爽点更容易引发评论共鸣；
- 哪些剧目适合低成本仿制；
- 哪些爆款元素已经过热或有抄袭风险。

这正是壹凡短剧选品平台的机会点。

## 3. 当前平台基础

当前项目已经具备以下基础能力：

- dy/hg 榜单采集；
- 今日榜单与上一期榜单对比；
- 数据资产页；
- 分析看板；
- RAG 问答；
- dy/hg 分析报告；
- 评论、ASR、Markdown/TXT/JSON 等数据进入统一分析链路；
- OpenAI-compatible LLM 配置基础。

这些能力可以继续沉淀为“短剧创作智能体”的数据底座。

## 4. 核心改进模块

### 4.1 爆款拆解卡

对每个上榜短剧生成结构化拆解卡，字段建议包括：

- 剧名；
- 平台；
- 榜单排名；
- 热度、点赞、收藏、评论；
- 一句话卖点；
- 题材标签；
- 目标人群；
- 主角身份；
- 反派/阻力来源；
- 核心冲突；
- 前 3 集钩子；
- 爽点类型；
- 情绪曲线；
- 关键反转节点；
- 评论共鸣点；
- 可仿制元素；
- 不建议照抄的风险点；
- 制作难度评估。

爆款拆解卡应成为后续选题、仿制、剧本、分镜生成的最小业务单元。

### 4.2 选题评分系统

平台需要给每个剧目或候选选题生成综合评分，建议包含：

| 指标 | 含义 |
| --- | --- |
| 热度分 | 当前榜单热度、排名、点赞、收藏、评论等指标 |
| 增长分 | 与上一期相比的排名、热度、点赞、评论增长 |
| 评论共鸣分 | 评论区高频情绪、争议点、代入感 |
| 新鲜度分 | 题材是否过热，是否有新角度 |
| 可仿制分 | 是否能保留爽点但替换人设、背景、职业、关系 |
| 制作成本分 | 场景数量、人物数量、特效需求、服化道难度 |
| 平台适配分 | 是否适合 dy/hg 的内容形态和受众 |

最终输出：

```text
今日值得跟进选题 Top10
```

每个推荐选题都应给出推荐理由，而不是只给分数。

### 4.3 爆款仿制工坊

输入一个爆款短剧或一个趋势标签，输出 3-5 个差异化仿制方向。

每个仿制方向建议包含：

- 仿制方向标题；
- 借鉴的爆款元素；
- 必须差异化的元素；
- 新主角设定；
- 新核心冲突；
- 新故事背景；
- 前 3 集钩子；
- 主要爽点；
- 预期受众；
- 制作难度；
- 与原爆款的相似度风险；
- 推荐优先级。

仿制工坊的原则是：

```text
借鉴爽点，不复制表达；
借鉴结构，不复制剧情；
借鉴人群，不复制人设。
```

### 4.4 剧本工坊

不要一开始做“直接生成全集剧本”，容易失控。建议拆成可编辑工作流：

1. 选题 brief；
2. 世界观设定；
3. 人物小传；
4. 人物关系图；
5. 分集大纲；
6. 单集剧情 beats；
7. 正文剧本；
8. 台词润色；
9. 爽点增强；
10. 反转增强。

每一步都要支持：

- 重新生成；
- 手动编辑；
- 锁定当前版本；
- 基于当前版本继续生成；
- 导出 Markdown/JSON。

### 4.5 人物与关系库

人物生成不应只输出名字，而要输出可拍摄、可复用的角色卡：

- 角色名；
- 年龄段；
- 身份；
- 外在标签；
- 内在欲望；
- 核心秘密；
- 与主角关系；
- 与反派关系；
- 角色成长线；
- 高频台词风格；
- 造型参考 prompt；
- 声音参考 prompt。

人物关系库应沉淀常见短剧关系模板，例如：

- 隐婚/错认；
- 替嫁/真假千金；
- 重生复仇；
- 霸总追妻；
- 豪门继承；
- 玄学逆袭；
- 底层翻身；
- 师徒/养成；
- 双强博弈；
- 先婚后爱。

### 4.6 情节与场景库

情节库应沉淀可复用剧情积木：

- 开场羞辱；
- 身份误认；
- 关键证据出现；
- 反派陷害；
- 主角反击；
- 关系反转；
- 高能打脸；
- 情绪崩溃；
- 亲情/爱情确认；
- 结尾悬念。

场景库应沉淀低成本可拍场景：

- 办公室；
- 医院；
- 家中客厅；
- 酒店房间；
- 婚礼现场；
- 公司会议室；
- 豪门宴会；
- 学校走廊；
- 地下车库；
- 古风庭院；
- 修仙宗门大厅。

每个场景应标注：

- 制作成本；
- 适合题材；
- 可承载冲突；
- 常见镜头；
- 道具需求；
- AI 视频 prompt 模板。

### 4.7 分镜工坊

分镜工坊负责把剧本转成可执行镜头表。

每条分镜建议包含：

- 集数；
- 场次；
- 镜头序号；
- 场景；
- 出场人物；
- 镜头类型；
- 景别；
- 机位；
- 人物动作；
- 台词；
- 情绪目标；
- 道具；
- 光线/氛围；
- 时长建议；
- 视频生成 prompt；
- 配音 prompt；
- 字幕文本。

后续可对接外部视频生成工具，用分镜 prompt 批量生成预演素材。

## 5. 建议新增产品页面

### 5.1 今日爆款

基于今日榜单和榜单对比，展示：

- 新上榜；
- 排名上升；
- 点赞增长；
- 评论增长；
- 热度增长；

展示单个剧目的结构化拆解卡，并支持一键生成仿制方向。

### 5.3 选题库

展示所有候选选题：

- 选题标题；
- 来源剧目；
- 题材；
- 推荐分；
- 可仿制分；
- 制作难度；
- 状态：待评估、已采纳、已生成大纲、已生成分镜。

### 5.4 仿制工坊

输入爆款剧或选题，生成差异化仿制方案。

### 5.5 剧本工坊

分阶段生成和编辑：

- brief；
- 人物；
- 大纲；
- 单集；
- 正文。

### 5.6 分镜工坊

展示分镜表，支持导出制作包。

### 5.7 创意资产库

沉淀：

- 人设模板；
- 关系模板；
- 爽点模板；
- 钩子模板；

## 6. 技术架构建议

建议新增 `creative/` 子系统，保持业务逻辑不要继续堆进 `WebGUI.py`。

建议模块：

```text
creative/
  __init__.py
  schema.py
  repository.py
  topic_service.py
  hit_breakdown.py
  imitation_service.py
  script_service.py
  storyboard_service.py
  prompt_templates.py
  api.py
```

建议 SQLite 文件：

```text
.runtime/creative/creative.db
```

建议数据表：

- `creative_topics`
- `creative_breakdowns`
- `creative_blueprints`
- `creative_characters`
- `creative_relationships`
- `creative_episodes`
- `creative_scenes`
- `creative_shots`
- `creative_exports`

```text

```

## 7. 与现有模块的关系

### 7.1 今日榜单

今日榜单负责发现趋势：

```text
新上榜、排名上升、热度增长、点赞增长、评论增长
```

它应作为选题生成的入口。

### 7.2 分析看板

分析看板负责宏观统计：

```text
题材分布、热度趋势、评论情绪、高频卖点、剧目指标
```

它应为选题评分提供指标。

### 7.3 RAG 问答

RAG 负责引用证据：

```text
榜单文件、评论文件、分析报告、ASR 文本
```

生成选题、仿制方案、剧本时应尽量附带数据依据。

### 7.4 分析报告

分析报告负责深度拆解单个剧目。

后续应把 Markdown 报告升级为结构化 JSON：

```text
summary、selling_points、hook_points、plot_tags、character_roles、scene_patterns、imitation_notes
```

## 8. 生成质量控制

短剧仿制场景必须控制以下风险：

### 8.1 避免抄袭

生成结果应强制包含：

- 借鉴点；
- 差异点；
- 相似度风险；
- 修改建议。

### 8.2 避免空泛

每个选题都必须引用来源：

- 来源榜单；
- 来源剧目；
- 来源评论；
- 来源分析报告；
- 相关热度指标。

### 8.3 避免不可拍

每个方案都应评估：

- 场景数量；
- 主要人物数量；
- 特效需求；
- 服化道难度；
- 拍摄成本；
- 是否适合短剧节奏。

### 8.4 避免模型一次性失控

剧本生成应采用分步生成：

```text
选题 -> brief -> 人物 -> 大纲 -> 单集 beats -> 正文 -> 分镜
```

不要直接从榜单一步生成完整剧本。

## 9. 阶段路线图

### Phase 3：选题与爆款拆解

目标：从“看榜单”升级到“自动给选题建议”。

交付：

- 爆款拆解卡；
- 选题评分；
- 今日可跟进选题 Top10；
- 选题库页面；
- `/api/creative/topics/generate`；
- `/api/creative/breakdown`。

### Phase 4：仿制与剧本大纲

目标：从“选题建议”升级到“可执行创作方案”。

交付：

- 仿制工坊；
- 差异化仿制方案；
- 人物设定；
- 人物关系；
- 分集大纲；
- 单集剧情 beats；
- `/api/creative/imitation`；
- `/api/creative/script-outline`。

### Phase 5：分镜与制作包

目标：从“剧本方案”升级到“可进入制作环节”。

交付：

- 分镜工坊；
- 场景库；
- 镜头表；
- 视频生成 prompt；
- 配音 prompt；
- 制作包导出；
- `/api/creative/storyboard`；
- `/api/creative/exports`。

### Phase 6：外部生成工具集成

目标：从“制作包”升级到“视频预演与素材生成”。

交付：

- 可灵/即梦/Runway/Veo/Luma 等外部生成服务适配层；
- 角色设定图生成；
- 场景设定图生成；
- 分镜视频预演；
- 配音生成；
- 字幕和剪辑草稿。

## 10. 推荐优先级

最建议优先做：

1. 爆款拆解卡；
2. 选题评分；
3. 今日可跟进选题 Top10；
4. 仿制方向生成；
5. 人物设定与分集大纲；
6. 分镜 prompt；
7. 制作包导出；
8. 外部视频生成服务对接。

原因是：平台当前已有真实数据底座，应该先把数据转化成“创意决策能力”，再往视频生成和自动制作扩展。

## 11. 最终形态

最终平台应支持如下工作流：

```text
1. 查看今日榜单
2. 发现增长短剧
3. 一键生成爆款拆解卡
4. 生成可仿制选题
5. 选择一个方向生成剧本 brief
6. 生成角色、关系和分集大纲
7. 生成单集剧本
8. 生成场景与分镜
9. 导出制作包
10. 对接外部 AI 视频/配音/剪辑工具生成预演
```

这条路线能把壹凡短剧选品平台从数据看板升级成真正的短剧内容生产中台。
