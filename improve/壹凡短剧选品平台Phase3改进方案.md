# 壹凡短剧选品平台 Phase 3 改进方案

**阶段名称**：选题与爆款拆解 MVP  
**前置文档**：[壹凡短剧选品平台 PRD 实施文档](壹凡短剧选品平台PRD实施文档.md)  
**范围**：今日爆款、爆款拆解卡、选题评分、候选选题 Top10、选题库、来源证据  
**非范围**：仿制方向、剧本工坊、人物/场景资产库、分镜、制作包、外部视频/配音服务

## 1. 阶段目标

将现有“榜单与分析数据展示”升级为“可采纳的选题建议”。运营人员能够从任意已有 dy/hg 榜单快照中获得可解释的候选剧目，查看证据与评分，生成可编辑的爆款拆解卡，并将值得跟进的项目沉淀到选题库。

本阶段完成后，平台应回答三个问题：

1. 今天哪些剧目值得跟进？
2. 推荐它的市场证据是什么？
3. 它的核心卖点、冲突、钩子和制作风险是什么？

## 2. 现有能力与复用边界

| 现有模块 | 可复用内容 | Phase 3 使用方式 | 当前限制 |
| --- | --- | --- | --- |
| `TodayRankService` | dy/hg 当前快照、上一期比较、排名变化、可用热度字段 | 今日爆款入口、增长分和来源快照 | 字段随平台/榜单变化，不能假定全部指标存在 |
| `DramaRepository` | 剧目、题材、摘要、卖点、钩子、点赞/收藏/评论/热度 | 热度分、标签、新鲜度与选题证据 | 数据来自已同步分析产物，可能滞后于最新快照 |
| 分析报告 | `summary`、卖点、钩子、标签和 LLM 分析文本 | 拆解卡初稿与事实来源 | Markdown 内容不总是结构化；需保留源路径 |
| 评论数据 | 评论量、正文、情绪记录 | 评论共鸣分和共鸣点 | 红果可能只有评论数量，没有正文 |
| ASR/字幕产物 | `transcript.json`、`script.md`、音频/视频来源 | 钩子、情节、场景和台词型证据 | 转写是辅助文本，不等同官方剧本 |
| RAG API | 既有检索与引用能力 | 对分析报告、评论、转写进行证据补充 | 当前前端入口已隐藏；不得依赖页面可见性 |

### 2.1 数据降级规则

| 缺失数据 | 系统行为 | 必须展示的提示 |
| --- | --- | --- |
| 上一期快照 | 不计算增长分，其他分项重新归一化 | 无可比历史数据 |
| 点赞、收藏、热度任一字段 | 使用剩余字段计算热度分 | 部分热度字段缺失 |
| 评论正文 | 评论共鸣分为未知，不用评论数伪造情绪结论 | 仅有评论量指标 |
| ASR/字幕 | 不输出“前三集事实钩子”或引用台词 | 未获得剧集转写 |
| 分析报告 | 只依据快照和指标生成候选项 | 暂无深度分析报告 |
| LLM 不可用 | 保存基于规则的评分和人工空白拆解卡 | AI 拆解未生成，可手工补充 |

## 3. 用户流程与状态

```text
榜单快照 -> 生成候选选题 -> 查看评分/证据 -> 生成拆解卡
-> 编辑并锁定 -> 采纳到选题库 / 标记不跟进 -> 归档
```

### 3.1 选题状态

| 状态 | 说明 | 允许操作 |
| --- | --- | --- |
| `pending_review` | 系统生成，尚未人工判断 | 查看、生成拆解、采纳、不跟进 |
| `adopted` | 已进入后续创作队列 | 编辑标签、生成/查看拆解、归档 |
| `rejected` | 当前不跟进 | 查看原因、恢复待评估 |
| `archived` | 历史选题，仅保留记录 | 查看、恢复待评估 |

### 3.2 拆解卡状态

| 状态 | 说明 |
| --- | --- |
| `draft` | 可自动生成、手工编辑或重新生成 |
| `locked` | 版本不可修改，后续阶段只能引用该版本 |
| `superseded` | 被新锁定版本替代，仍可追溯 |

锁定版本不得原地修改；编辑锁定卡时创建 `draft` 新版本并保留 `parent_version_id`。

## 4. 页面与交互

### 4.1 今日爆款

**入口**：侧栏新增“今日爆款”，今日榜单页面保留“生成候选选题”快捷入口。  
**目标**：展示系统从当前快照筛出的候选项，而不替换原始榜单。

页面结构：

1. 顶部筛选：平台（dy/hg/全部）、快照日期、榜单类型、候选状态、题材、最低推荐分。
2. 摘要区：本次候选数、数据完整度、Top10 生成时间和失败项数量。
3. Top10 表：剧名、平台、排名/变化、推荐分、置信度、题材、推荐理由、状态、操作。
4. 证据抽屉：来源快照、指标明细、报告摘要、评论/转写引用及缺失字段提示。

操作：生成/刷新候选选题、查看证据、生成拆解卡、采纳、标记不跟进、跳转选题库。空态提示用户先抓取或导入榜单；生成中使用标准 Job 状态与日志。

### 4.2 爆款拆解

**入口**：今日爆款和选题库的“生成/查看拆解”。

拆解卡字段：

| 分组 | 字段 |
| --- | --- |
| 基础信息 | 剧名、平台、快照、排名、热度指标、题材、来源证据 |
| 市场表达 | 一句话卖点、目标人群、卖点、评论共鸣点 |
| 结构判断 | 主角身份、阻力来源、核心冲突、前三集钩子、爽点类型、情绪曲线、反转节点 |
| 生产判断 | 场景复杂度、人物复杂度、特效需求、制作难度、可仿制元素、风险点 |
| 质量信息 | 字段来源、推断标记、生成模型/模板版本、版本号、锁定状态 |

字段必须显示来源类型：`snapshot`、`analysis`、`comment`、`transcript`、`manual` 或 `inference`。没有转写/评论正文时，对应事实性字段为空或标记“推断”，不能填充为确定结论。

操作：重新生成、保存草稿、手动编辑、查看来源、锁定版本、基于当前版本新建草稿。锁定前显示数据缺失与风险检查结果。

### 4.3 选题库

**目标**：保存所有候选及人工决策，作为 Phase 4 的唯一选题入口。

字段：选题标题、来源剧目、平台、来源快照、题材、推荐分、置信度、可仿制分、制作成本分、状态、负责人（预留）、最后更新时间、锁定拆解版本。

筛选：状态、平台、题材、日期、分数区间、是否有锁定拆解。操作：采纳、拒绝、恢复、归档、进入拆解、查看证据。无结果时保留筛选条件并提示降低条件或生成候选。

## 5. 评分系统

### 5.1 分项与权重

| 分项 | 默认权重 | 输入 | 计算规则 |
| --- | ---: | --- | --- |
| 热度分 | 25 | 排名、heat、点赞、收藏、评论 | 在同平台、同快照候选集内归一化；优先 heat，缺失时使用互动字段 |
| 增长分 | 20 | 排名变化、热度/互动变化 | 与同榜单上一期比较；新上榜给“新入榜”标识，不虚构增长数值 |
| 评论共鸣分 | 15 | 评论正文、情绪、主题 | 有正文时统计高频情绪/主题；只有数量时分项未知 |
| 新鲜度分 | 10 | 题材、近 30 天题材密度 | 题材密度越高分越低；缺少历史样本时标记未知 |
| 可仿制分 | 15 | 拆解/规则标签 | 有明确爽点、冲突和可替换关系时加分；无拆解时为待评估 |
| 制作成本分 | 10 | 场景、角色、特效、题材 | 场景/人物/特效少且可拍性高得分高；默认中性值并降低置信度 |
| 平台适配分 | 5 | 平台、题材、榜单类型 | 用已验证题材与平台分布计算；样本不足时为待评估 |

### 5.2 归一化与置信度

1. 每个可用分项归一化到 0-100；排名采用反向排名，数值指标使用分位数或截断的 min-max，避免异常值支配结果。
2. 缺失分项的权重从分母中剔除，已知分项按剩余权重重新归一化。
3. `confidence`：可用权重不少于 80% 且含快照/报告证据为高；不少于 50% 为中；其余为低。
4. 总分、原始分项、可用权重、缺失原因和计算版本必须持久化，不能仅保存最终分数。

推荐理由由规则模板生成，至少引用两个已知事实；若事实不足，使用“数据有限，建议人工复核”，而非生成泛化结论。

## 6. 数据模型与模块设计

### 6.1 模块边界

新增 `creative/`，不在 `WebGUI.py` 中堆积业务逻辑：

```text
creative/
  schema.py         # 请求/响应、实体、版本与评分对象
  repository.py     # SQLite、事务、查询与软删除
  topic_service.py  # 快照读取、候选筛选、评分、Top10
  hit_breakdown.py  # 证据归集、规则/LLM 拆解与版本生成
  api.py            # FastAPI 路由
```

`WebGUI.py` 仅注册 `creative.api` 路由。耗时拆解生成使用现有 JobManager 事件/日志规范；评分和普通列表查询可同步返回。

### 6.2 SQLite

数据库：`.runtime/creative/creative.db`。

`creative_topics`：`id`、来源平台、`job_id`、`source_path`、快照时间、标题、题材、状态、最终评分、置信度、评分明细 JSON、推荐理由、证据 JSON、软删除标记、创建/更新时间。

`creative_breakdowns`：`id`、`topic_id`、版本、`parent_version_id`、状态、结构化内容 JSON、字段来源 JSON、风险 JSON、提示模板/模型版本、锁定时间、创建/更新时间。

唯一约束：同一来源快照、平台、`job_id`、源路径和剧目只保留一个活动候选；重新生成更新评分版本，不覆盖人工状态。事务内同时写入评分与证据，避免出现无来源候选。

### 6.3 证据对象

统一结构：

```json
{
  "source_type": "snapshot|analysis|comment|transcript|manual|inference",
  "platform": "dy",
  "job_id": "...",
  "source_path": "data/...",
  "captured_at": "2026-07-16T00:00:00+08:00",
  "field": "hook_points",
  "excerpt": "可验证的原文或指标摘要"
}
```

`inference` 必须同时包含其依赖证据 ID；`manual` 需记录编辑时间和操作者预留字段。

## 7. API 设计

| API | 行为 |
| --- | --- |
| `POST /api/creative/topics/generate` | 指定平台、快照日期、数量和可选重算，生成候选与 Top10 |
| `GET /api/creative/topics` | 分页查询，支持状态、平台、题材、日期和分数过滤 |
| `GET /api/creative/topics/{topic_id}` | 返回候选、评分明细、证据、关联拆解摘要 |
| `PATCH /api/creative/topics/{topic_id}` | 变更采纳/拒绝/归档状态及人工理由 |
| `POST /api/creative/breakdowns` | 创建拆解生成 Job 或基于版本创建新草稿 |
| `GET /api/creative/breakdowns/{breakdown_id}` | 返回指定版本的内容、来源、风险和锁定状态 |
| `PATCH /api/creative/breakdowns/{breakdown_id}` | 保存草稿字段；锁定版本需单独动作 |
| `POST /api/creative/breakdowns/{breakdown_id}/lock` | 校验后锁定当前版本 |

生成接口响应标准 Job 或资源 ID；所有错误响应返回用户可读消息、错误代码和可重试标识，不返回模型密钥、第三方 URL 参数或原始敏感数据。

## 8. 实施里程碑

### M1：数据与评分底座

- 建立 `creative` 数据库、schema、repository 和候选数据读取适配层。
- 从 `TodayRankService` 与 `DramaRepository` 读取 dy/hg 候选，输出评分明细、缺失项和置信度。
- 单元测试覆盖平台字段差异、无上一期、缺热度字段、重复生成与评分可重算。

### M2：拆解与证据

- 实现证据归集、规则拆解卡和可选 LLM 异步生成。
- 连接分析报告、评论与 ASR/字幕资产，标记事实、人工和推断来源。
- 实现拆解草稿、版本、锁定和来源展示 API。

### M3：API 与任务

- 注册 `creative.api`，接入现有 JobManager 日志、失败和取消处理。
- 实现选题状态变更、分页查询、评分明细与证据读取。
- 统一路径校验和 SQLite 事务，避免跨任务读取工作区外文件。

### M4：页面集成

- 新增“今日爆款”“选题库”“爆款拆解”导航与页面。
- 从今日榜单提供“生成候选选题”入口；保持榜单、分析看板、数据管理原行为不变。
- 完成加载、空态、生成中、失败重试、证据抽屉和锁定版本交互。

### M5：测试与验收

- 完成规则、repository、API、Job、页面模板与端到端数据夹具测试。
- 使用一组 dy 和一组 hg 快照验证 Top10、缺失降级、人工采纳及拆解版本。
- 完成来源追溯和路径安全审计。

## 9. 验收标准

1. 任意已有 dy/hg 快照可生成候选 Top10；每条候选至少有一个有效来源证据。
2. 页面能显示总分、分项、缺失字段、置信度和推荐理由；无历史数据时不会展示虚假的增长结果。
3. 运营可以将候选采纳、拒绝、归档并查看状态历史；状态改变不覆盖评分和来源。
4. 拆解卡支持草稿编辑、来源查看和锁定；锁定后创建新版本而非覆盖旧版本。
5. 评论/转写缺失时相关字段明确标记未知或推断，不能输出伪造的评论共鸣、钩子或台词事实。
6. 拆解生成失败、LLM 超时或任务取消后，用户可从 Job 日志定位原因，已保存的候选和历史版本不丢失。

## 10. 风险与决策

- Phase 3 不允许“按爆款直接生成新剧情”，避免提前进入仿制/剧本范围。
- 评分是排序辅助，不是市场结果预测；评分权重、规则和模型版本必须可追溯。
- 红果评论与转写数据不足时，优先显示指标与数据限制，不以 LLM 补写事实。
- 仅使用工作区内已获取的数据产物和现有 API；外部接口凭证不写入 `creative.db`、证据 JSON 或日志。
- 后续 Phase 4 只能从已采纳选题及其锁定拆解版本进入，确保创作链路具有稳定来源。
