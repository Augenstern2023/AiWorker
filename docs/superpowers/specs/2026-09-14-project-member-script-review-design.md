# 项目成员发起剧本审核权限设计

## 目标

项目来源的剧本审核以项目成员关系作为授权依据：系统管理员或项目中状态为 `active` 的成员可以发起审核；已移除、停用成员及非成员不可发起。

## 范围

- 调整 `/api/script-reviews` 创建项目来源审核时的授权判断。
- 保证有效项目成员能够读取自己发起的审核记录和进度，使前端轮询完整运行。
- 文件上传或纯文本审核继续沿用 `script.review.generate` 权限，不受本次变更影响。
- 不改变创作、任务分配、项目管理及其他接口的项目权限语义。

## 授权规则

### 项目来源审核

满足以下任一条件即可发起：

1. 当前账户为系统管理员；
2. 当前账户在对应工作流项目中存在状态为 `active` 的成员记录。

项目成员身份本身就是发起项目审核的充分条件，不再要求账户同时具有“项目已分配”数据范围或项目管理角色。

### 非项目来源审核

文件上传和纯文本审核仍要求 `script.review.generate` 权限。它们没有项目成员关系可作为授权边界，因此不放宽。

### 审核记录访问

- 系统管理员可以访问项目审核记录。
- 有效项目成员可以访问对应项目的正式审核记录。
- 审核发起人可以读取自己发起的记录和进度，避免任务创建成功后轮询被拒绝。
- 已移除、停用成员及无关账户仍返回 403。

确认、删除等后续变更操作继续保留现有操作权限检查；本次只保证项目成员能够发起审核并完成必要的进度读取。

## 实现边界

在身份权限服务中提供不受 `data_scope` 门槛影响的“是否为有效项目成员”查询。剧本审核路由组合该查询与系统管理员判断，不修改现有 `can_access_assigned_project`、`can_access_managed_project` 等全局语义，避免扩大其他模块权限。

项目本地 ID 仍先通过 `CreativeRepository.workflow_project_id()` 转换为工作流项目 ID，再查询成员关系，兼容当前项目 ID 隔离规则。

## 错误处理

- 项目不存在：404，保持现状。
- 自由创作项目首版不支持剧本审核：409，保持现状。
- 非有效项目成员：403，提示仅项目成员可访问。
- 身份权限服务不可用：按未授权处理，不降级放行。

## 测试

回归测试覆盖：

1. `data_scope="task"` 且没有项目管理角色的普通账户，只要是有效项目成员即可成功创建项目审核。
2. 同一账户可读取刚创建的审核进度。
3. 非成员不能创建项目审核。
4. 状态非 `active` 的历史成员不能创建项目审核。
5. 文本或文件审核仍要求原有权限。
6. 现有剧本审核和身份权限测试保持通过。
