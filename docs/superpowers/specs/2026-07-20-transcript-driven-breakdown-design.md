# 基于剧目转写的个性化拆解设计

## 背景

当前“生成拆解”直接调用静态 `build_breakdown`，只能根据榜单快照填充少量字段。编辑器中的示例来自固定字段指南，因此不同剧目会看到相同的剧情示例，容易被误认为真实分析结果。

本次改造要求：只有剧目至少存在一集有效转写时才允许生成拆解；拆解内容、字段证据和编辑器示例必须来自该剧目的已下载脚本。完全没有转写时，不创建模板草稿，而是提示用户先下载剧目脚本。

## 范围

本次包含：

- 发现并校验与选题对应的 `script.md`、`transcript.json` 或兼容文本转写。
- 基于一集或多集转写生成个性化结构化拆解。
- 为每个拆解字段记录来源集数、文件路径和证据摘录。
- 将编辑器字段指南中的“示例”替换为当前拆解的个性化内容。
- 无有效转写时显示阻断弹窗，并可直接进入剧目下载流程。
- 支持后台任务进度、成功回填和失败提示。
- 已存在拆解版本时默认直接打开最新版本，不重复调用模型。
- 在拆解编辑器中提供独立的“重新生成”命令，只有明确触发时才创建新版本。

本次不包含：

- 要求全集下载完毕后才能拆解。
- 自动下载缺失集数。
- 修改已锁定拆解版本；明确重新分析时仍创建新草稿版本。

## 数据发现

新增独立的转写资产解析器，输入选题标题和平台信息，输出标准化剧目脚本包：

```text
TranscriptBundle
  title
  episodes[]
    episode_number
    text
    transcript_source
    script_path
    transcript_path
  searched_paths[]
```

解析器递归检查 `data/{platform}/jobs/*/dramas/**` 下的 `source.json`、`manifest.json`、`script.md` 和 `transcript.json`。剧目匹配优先使用元数据中的正式标题，其次使用规范化目录名；不能只依赖可能被转码或清洗过的目录名称。

有效转写必须包含非空正文。只有视频、音频或 `source.json`，但没有字幕/ASR 文本时，仍判定为“没有转写”。同一集存在多个产物时，优先级为 `script.md`、`transcript.json.text`、兼容 `.txt` 转写，并按更新时间选择最新文件。

## 生成流程

1. 前端点击拆解操作。
2. 后端查询该选题的全部拆解版本，按版本号和 ID 倒序选择最新版本，不区分草稿或已锁定状态。
3. 如果已有版本，直接返回 `status=existing` 和完整拆解记录；前端立即打开编辑器，不检查转写、不创建任务。
4. 如果没有任何版本，后端检查该选题的转写资产。
5. 没有有效转写时返回结构化 `409`：

```json
{
  "code": "transcript_required",
  "message": "请先下载剧目脚本再拆解",
  "topic_id": 1,
  "title": "剧目名称"
}
```

6. 至少存在一集转写时，创建 `creative / breakdown_generate` 后台任务。
7. Worker 按集整理转写；超出单次模型上下文时先分批提取剧情事实，再进行全局合并。
8. 模型输出固定结构，覆盖拆解编辑器的全部字段，并为每个字段返回证据引用。
9. 服务端执行字段类型、必填项、集数引用和证据引用校验；最多进行一次结构修复。
10. 校验通过后创建新的拆解草稿，并记录父版本、覆盖集数、生成任务和模型信息。
11. 前端任务完成后读取新草稿并打开拆解编辑器。

普通拆解操作永远优先复用最新版本。编辑器中的“重新生成”使用同一接口并显式提交 `force_regenerate=true`；此时才重新检查脚本并创建后台任务。重新生成不复制旧内容作为结果，最新锁定版本只作为版本父节点和人工对照，不进入模型事实来源。

接口返回约定：

```json
{
  "status": "existing",
  "breakdown": {"id": 123, "version": 4, "status": "draft"}
}
```

请求显式重新生成时使用：

```json
{"topic_id": 1, "force_regenerate": true}
```

## 个性化字段与示例

模型生成以下字段：剧名、一句话卖点、题材、目标受众、主角身份、阻力来源、核心冲突、前三集钩子、主要爽点、情绪曲线、反转节点、评论共鸣、可借鉴元素、制作难度、风险说明。

字段指南保留通用的“字段说明、写法、证据要求”，但 `example` 在打开编辑器时由当前拆解内容生成：

- 文本字段直接使用当前字段内容。
- 数组字段使用当前剧目的第一项；空数组显示“当前转写证据不足，暂未生成示例”。
- 不再返回固定人物、固定婆媳冲突或固定职场逆袭示例。

`comment_resonance` 只有存在评论正文时才允许生成事实性结论；只有剧本转写时必须明确标记“缺少评论证据”。制作难度和可借鉴元素允许模型基于已识别的场景、人物和结构作分析判断，但必须在风险说明中区分事实与推断。

## 前端交互

- 点击列表中的拆解操作时，已有版本直接打开最新拆解，不出现进度弹窗。
- 没有任何拆解版本时才显示“正在检查剧目脚本”。
- 无转写时使用 Bootstrap 模态框提示“请先下载剧目脚本再拆解”。
- 弹窗提供“取消”和“去下载”两个操作；“去下载”关闭提示并打开现有剧目下载弹窗，自动带入剧名。
- 有转写时显示后台任务进度、已发现集数和当前分析阶段。
- 成功后自动打开新草稿；编辑器标题显示覆盖集数，例如“已分析第 1-3 集”。
- 失败时保留任务和错误信息，不创建半成品拆解。
- 编辑器对草稿继续使用保存和锁定操作；已锁定版本保持只读。
- 编辑器中的“重新生成”是唯一会绕过已有版本并再次调用模型的入口。

## 错误处理

- 标题无法匹配资产：按无转写处理，并返回检索过的路径数量用于日志诊断。
- 转写文件损坏或空文本：跳过该文件；全部无效时按无转写处理。
- 模型响应不合规：一次修复后仍失败则任务失败，不写数据库。
- 部分集数缺失：允许生成，在风险说明和覆盖信息中标明现有集数。
- 任务重复提交：同一选题已有运行中的拆解任务时返回冲突，并把现有任务 ID 返回前端。
- 已有版本读取失败：返回明确错误，不自动降级为重新生成，避免意外消耗模型调用。

## 测试

- 资产解析器能通过元数据匹配中文剧名，并读取 `script.md` 与 `transcript.json`。
- 只有媒体文件、没有转写文本时返回 `transcript_required`。
- 至少一集有效转写时允许创建生成任务。
- 已有草稿或锁定版本时返回版本号最新的拆解，并且不创建生成任务。
- 显式 `force_regenerate=true` 时才允许已有版本的选题再次创建生成任务。
- 多集转写按集数排序并进入模型输入。
- 模型结果产生不同剧目的个性化字段与证据引用。
- 字段指南示例来自当前拆解，不包含固定模板示例。
- 任务失败不创建拆解版本；成功后创建可编辑草稿并保留父版本。
- 前端无转写弹窗可以进入现有下载流程。
- 前端普通拆解操作直接打开已有版本；编辑器的“重新生成”操作进入生成进度流程。

## 验收标准

- 没有转写的剧目点击“生成拆解”时只出现下载提醒，不生成默认模板。
- 有至少一集转写的剧目能够生成与剧情内容一致的个性化拆解。
- 每个事实性字段可以追溯到具体集数和脚本证据。
- 编辑器中的黄色示例与当前剧目一致，不再跨剧复用固定内容。
- 重复点击列表中的拆解操作不会再次运行模型。
- 补充更多转写后，只有明确点击“重新生成”才创建新的草稿版本并更新覆盖范围。
