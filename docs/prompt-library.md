# 编剧提示词模板库

## 当前范围

模板库目前接管 Brief、人物关系、全剧大纲、Beats、场次剧本、正式剧本审核和审核后优化。

模板由四层组成：

1. 系统输出契约：字段、JSON 结构、运行变量和解析要求，只读；
2. 完整风格模板：作品 DNA、七个风格维度、阶段规则和示例；
3. 项目/阶段/单集设置：项目成员保存的默认选择；
4. 单次覆盖：只影响下一次生成，任务创建成功后即清除。

模板参数会以 JSON 形式进入有效创作指令；示例只有显式标记 `include_in_context` 时才会进入模型上下文，未标记的示例只用于模板说明。

模板合成顺序为：系统契约 → 完整风格模板 → 项目要求 → 阶段设置 → 单集设置 → 单次覆盖。创作要求不得覆盖系统输出契约。

## 页面与使用顺序

模板能力分成三个入口，避免把日常选择、模板管理和实验分析混在一个弹窗里：

1. 创作页的“选择生成模板”：只选择本次要用的模板、填写补充要求，并决定仅下次使用、阶段默认或单集默认；
2. “模板中心”：管理我的模板、项目模板和模板市场。个人方法先放在“我的模板”；需要团队共用时另存为项目模板并由负责人审核；需要外部模板时再进入市场；
3. “模板效果”：查看真实任务的调用量、成功率、采纳率、Token、耗时和数据覆盖情况。

“项目模板”页面中的待审核、批准、弃用和归档是团队共享模板的生命周期，不是日常生成步骤。普通项目成员可以查看状态和使用影响；项目负责人负责状态操作。任何审核或市场安装都不会自动替换项目当前使用的模板，仍需回到创作页主动选择或保存默认设置。

模板库会根据项目题材、目标平台、目标受众、Seed 和已锁定 Brief，对模板七个风格维度进行确定性评分。推荐结果包含分数、命中维度、理由和低置信度提示；排序算法不读取当前绑定，不会因已选模板获得隐藏加分，也不会自动绑定推荐项。

外部 `.md`、`.txt` 或粘贴文本可整理为模板草稿。外部内容始终作为不可信资料送入模型，其中的自我指令、工具操作、身份劫持、保存或绑定要求不会被执行。模型必须返回锁定的七维、七阶段、四模式 JSON 结构，服务端再次校验后才显示预览。导入示例默认 `include_in_context=false`，预览不写数据库；只有用户确认“保存为模板”后才调用普通模板创建接口，保存后仍需再次选择是否单次使用或绑定。

项目模板具有独立的治理状态：待审核、已批准、已弃用、已归档。新建项目模板由项目负责人创建，初始为已批准；项目模板保存新版本后自动进入待审核，批准前不能被新绑定或单次选择，但已固定到旧版本的生成不受影响。已弃用模板同样停止接受新绑定，已有固定版本继续工作。归档前必须先把项目默认、阶段和单集绑定迁走；已批准模板需要先弃用再归档。归档恢复后回到待审核，不会自动恢复任何旧绑定。

治理页在操作前展示使用影响，包括项目默认/阶段/单集绑定以及已生成资源、审核和优化记录中的冻结模板引用。治理操作要求项目负责人填写原因，使用乐观版本控制和幂等操作标识，并保存状态变更时的影响快照。普通项目成员可以查看治理状态和影响，但不能批准、弃用、归档或恢复项目模板。

模板可观测性按“模板 key + 不可变版本”汇总项目的真实终态任务，并可按阶段或模板筛选。成功率和失败率只使用成功/失败终态，取消任务单列；耗时来自任务真实开始与结束时间。Token 只读取 Chat Completions 或 Responses API 响应中的供应商 `usage`，不会使用字符数、预检估算或输出长度回填。Worker 在成功和失败终态事件中保存已经发生的 usage；部分调用未返回 usage 时，已报告 Token 仍保留，但完整任务覆盖率会下降。

人工采纳信号按任务结果类型解释：标准创作资源进入锁定/批准状态视为采纳；自由创作资源仍被当前 Head 指向视为当前采用；优化草稿被人工接受视为采纳；审核报告不是创作候选，因此不计算采纳率。个人模板的聚合结果仍只对所有者可见。

回归检测只比较同一模板、同一阶段的相邻版本。两个版本各至少有 3 个终态任务后，失败率上升 20 个百分点、采纳率下降 20 个百分点、平均 Token 上升 30% 或 P50 耗时上升 50% 才产生告警。告警列出指标、基准/当前版本、差值、样本量和数据覆盖率；样本不足时只提示继续观察，不下异常结论。

模板市场分为官方模板和社区模板。官方模板直接投影系统内置模板，标记为“官方内置”，无需安装；点击“立即使用”只影响当前项目该步骤的下一次生成，不修改默认绑定。社区市场采用受控发布而不是直接共享私人模板。只有个人模板的最新不可变版本可以提交；项目模板必须先由有权成员另存为个人模板，避免项目资产被误公开。提交者必须明确确认完整模板内容将在公司内部展示，并提供模板署名和来源权利说明；非原创来源还必须提供可核验的 HTTP(S) 链接。提交后冻结模板内容、版本、哈希、来源和兼容性，源模板的后续编辑不会改变待审或已上架版本。

市场申请必须由系统管理员人工批准后才能被发现和安装。审核、驳回、作者撤回和平台下架都使用乐观版本与幂等操作标识，并保留不可变状态事件。批准前会重新校验模板契约和冻结内容哈希。撤回或下架只停止新的市场安装，不删除也不修改此前已经安装到项目中的副本。

安装仅限项目负责人执行。安装时再次校验当前 `prompt-library-v1` 契约、支持阶段/模式和内容哈希，并在当前项目创建一个已批准的独立项目模板，冻结市场版本、内容哈希和署名来源。安装不自动修改项目默认、阶段或单集绑定，也不跟随市场来源升级；需要更新时必须安装新的已审核版本并由项目成员主动改绑。

市场评分采用“已安装用户、一人一票”：发布者不能自评，评分者所在项目必须已经安装该市场版本，同一登录用户对同一市场版本只能保留一条评分，更新评分必须携带预期版本。聚合只显示这类安装评分的数量、均分和 1–5 分分布；这能减少重复账号之外的常见重复评分，但不宣称是统计显著性或完整的反作弊系统。

## 首发模板

- 通用竖屏短剧；
- 都市身份错位甜宠轻喜剧；
- 弹幕预警型女性复仇爽剧；
- 规则驱动型古装奇幻悬疑。

另有一个不在模板库列表展示的“经典兼容模板”，作为旧项目首次保存默认设置后的内部兼容基线。它不重复叠加旧硬编码提示词已有的创作规则；附件中的具体作品名、人物名和情节不会进入通用模板。

## 数据模型

模板数据保存在创意项目 SQLite 数据库中：

- `creative_prompt_templates`：模板身份、所有权和可见性；
- `creative_prompt_template_revisions`：不可变模板内容版本；
- `creative_project_prompt_settings`：项目是否启用模板系统及固定的默认版本；
- `creative_project_prompt_bindings`：阶段或单集绑定与自定义要求。
- `creative_prompt_templates.governance_*`：项目模板治理状态、乐观版本、批准版本和最近操作信息；
- `creative_prompt_governance_events`：不可变治理事件、操作原因和执行时的使用影响快照；
- `creative_prompt_market_submissions`：内部发布申请、冻结内容、来源权利、兼容性和审核状态；
- `creative_prompt_market_events`：批准、驳回、撤回和下架的不可变状态事件；
- `creative_prompt_market_installations`：市场版本到项目独立模板副本的冻结安装关系；
- `creative_prompt_market_ratings`：已安装用户的一人一票评分及乐观版本；
- `script_reviews.source_payload_json.prompt_snapshot`：正式审核排队时冻结的审核模板快照；
- `script_optimizations.prompt_snapshot_json`：优化任务排队时冻结的优化模板快照。

系统、个人、项目三种模板的边界如下：

- 系统模板只读；官方更新创建新版本，现有项目不会自动升级；
- 个人模板只有所有者可见、可编辑和临时选择；
- 项目模板只在所属项目中可用，由项目负责人管理。

个人模板可由所有者删除。删除采用归档隐藏：模板会从“我的模板”和后续选择列表中消失，但不可变版本、历史生成快照和已经提交的市场冻结副本继续保留。仍被项目默认、阶段或单集绑定引用时，删除界面会列出当前项目的占用位置和兼容替代模板。项目负责人可在同一界面中原子地完成“改绑并删除”；其他项目的引用不会被越权修改，须进入对应项目分别处理。改绑保留原有的自定义要求。

删除项目时，项目绑定和项目模板一并删除；个人模板不随项目删除。

## 生成快照

用户点击生成时，服务端解析模板选择并创建 `prompt_snapshot`。快照包含模板 ID、模板 key、版本、阶段、执行模式、七维标签、有效创作指令和 SHA-256 哈希。

快照与项目、Brief、人物、大纲、Beats 等输入一起冻结。Worker 只读取服务端快照，不接受客户端伪造的快照。生成资源的 `generation_meta` 同时记录模板 ID、版本和哈希，以便追溯和复现。

Brief 单方向生成使用 `single` 规则，多候选方向使用 `series` 规则，派生方向使用 `rewrite` 规则。人物关系按整批生成，使用 `single`。全剧大纲使用 `series`，同一快照约束阶段弧线、分集批次、字段补全和全集概览；单独生成概览或改写字段时使用 `rewrite`。Brief、人物关系、全剧大纲、审核和优化都没有单集模板维度，因此只支持项目级、阶段级和单次覆盖。Beats 与场次剧本的单集生成使用 `single`，全剧批量生成使用 `series`。

正式审核的单集模式使用 `review.single`，多集和合集使用 `review.series`；Writer Agent 的全大纲、全剧本和完整项目审核也使用 `review.series`，同一冻结快照贯穿逐集审核、批次汇总、最终汇总以及失败恢复。粘贴或上传文本的非正式诊断不接项目模板。直接优化使用 `optimization.single`，结构优化（Beats + Script）使用 `optimization.series`。模板只能改变审核关注点、严重度倾向、证据表达和优化风格，不能改变报告/草稿 JSON 契约、AI 建议的人工确认流程、来源新鲜度检查或 `outline_revision_required` 阻断。`repair` 只允许修复结构。

## 项目兼容策略

- 新建项目默认启用模板库，并固定“通用竖屏短剧”的当前版本；
- 旧项目没有 `creative_project_prompt_settings` 记录，因此继续使用原提示词；
- 旧项目选择“仅下次生成使用”时可直接使用所选模板，但不会开启项目级模板设置；
- 旧项目首次“保存默认设置”时，服务端在同一请求内启用兼容基线并保存阶段或单集绑定；
- 模板选择和默认设置都只影响未来生成，不会重新生成、修改或覆盖既有内容；
- `POST /prompt-system/enable` 作为旧客户端的后端兼容接口继续保留，当前界面不再提供独立升级步骤。

## API

项目模板接口位于 `/api/creative/projects/{project_id}` 下：

- `GET /prompt-library`：读取当前用户可用模板；
- `GET /prompt-library/recommendations?stage={stage}`：读取可解释的七维模板推荐；
- `GET /prompt-library/observability?stage={stage}&template_key={key}&limit={n}`：汇总真实任务的成功率、Token、耗时、采纳率、覆盖率和版本回归告警；
- `POST /prompt-library/import-preview`：把外部提示词整理为不落库的待审阅草稿；
- `GET /prompt-library/governance`：读取项目模板治理状态、使用影响和最近治理记录；
- `POST /prompt-library/templates/{template_id}/governance`：受控执行送审、批准、弃用、归档或恢复；
- `POST /prompt-system/enable`：旧客户端显式启用接口（兼容保留）；
- `GET /prompt-modules/{stage}`：读取阶段/单集绑定和有效模板；
- `PUT /prompt-modules/{stage}`：保存阶段或单集绑定；旧项目首次保存时同时启用模板设置；
- `POST /prompt-library/templates`：复制为个人或项目模板；
- `POST /prompt-library/templates/{template_id}/revisions`：保存自定义模板新版本。
- `GET /prompt-library/templates/{template_id}/deletion-impact`：读取删除占用、其他项目引用和兼容替代模板；
- `POST /prompt-library/templates/{template_id}/rebind-and-delete`：项目负责人原子改绑当前项目，在无剩余引用时归档个人模板；
- `DELETE /prompt-library/templates/{template_id}`：归档无活跃引用的个人模板；
- `GET /prompt-marketplace?q={text}&stage={stage}`：发现已审核模板，并读取自己的申请、当前项目安装和管理员审核队列；
- `POST /prompt-library/templates/{template_id}/marketplace-submissions`：冻结个人模板最新版本并提交市场审核；
- `POST /prompt-marketplace/submissions/{submission_id}/review`：管理员批准/驳回/下架，或发布者撤回；
- `POST /prompt-marketplace/listings/{submission_id}/install`：安装为项目独立模板；
- `PUT /prompt-marketplace/listings/{submission_id}/rating`：创建或乐观更新一人一票的已安装评分。

Brief、人物关系、全剧大纲、Beats、剧本生成、正式审核与优化请求可额外传入：

```json
{
  "prompt_template_key": "urban-identity-romcom",
  "prompt_template_revision": 1,
  "prompt_override": {
    "custom_requirements": "本集减少内心独白。"
  }
}
```

这组字段仅作用于当前任务，不修改项目绑定。

## 验证要求

- 模板版本必须不可变，并使用乐观版本检查；
- 私人模板不得被其他用户通过 key 越权使用；
- 项目模板不得跨项目使用；
- 任务排队期间修改模板，不得改变已创建任务的快照；
- JSON 和字段契约错误最多自动修复一次；
- 生成结果仍先保存为草稿，只有人工锁定后才能成为正式下游输入。
- 审核模板不得把 AI 建议自动确认为人工结论；
- 优化模板不得绕过 `outline_revision_required`、审核确认或来源指纹检查。
- 推荐不得泄露其他用户的私人模板，也不得自动改变绑定；
- 外部导入不得存储原文，模型结果必须重新通过模板契约校验，示例默认不得进入模型上下文。
- 项目模板新版本必须显式批准后才能新使用；弃用和待审核不得破坏已固定版本，仍有绑定时不得归档。
- 模板治理操作必须进行项目负责人鉴权、乐观版本检查、幂等校验并保留影响快照。
- 真实 Token 必须来自供应商 usage；缺失或部分上报不得用预估值补齐，并必须降低覆盖率。
- 回归告警必须在同模板、同阶段、相邻版本且满足最低样本后触发，并携带样本量和覆盖率。
- 市场不得直接发布系统或项目模板；提交必须冻结个人模板最新版本并明确确认公司内部展示与权利声明。
- 非原创市场模板必须提供 HTTP(S) 来源，批准和安装都必须重新校验内容哈希与运行契约。
- 未审核、已驳回、已撤回或已下架模板不得新安装；状态变化不得破坏已有项目副本。
- 市场安装只能由项目负责人执行，必须保留署名和来源，且不得自动改绑或跟随来源更新。
- 市场评分必须来自已安装项目，禁止发布者自评，并通过用户唯一约束和乐观版本阻止重复覆盖。

## 后续迭代顺序

模板治理、可观测性和模板市场阶段均已完成。代码级验收覆盖发布审核、来源权利、运行契约、跨项目独立安装、撤回/下架隔离以及一人一票评分。真实供应商烟测属于部署验收：只有在部署环境配置了可用模型和额度时才执行，不能在自动化测试中伪造供应商 usage 或消耗生产额度。

后续不再有待实现的模板功能阶段。运营期只需积累真实终态任务和人工采纳样本；版本样本不足时继续显示观察提示，达到阈值后使用既有回归告警辅助人工判断。

每个阶段都复用同一套模板身份、不可变版本、权限、绑定优先级与生成快照协议，不为不同模型复制模板；模型差异由适配层处理。
