# 编剧大师完整项目长审核设计

## 背景

编剧大师当前把带有“审核、评审、评分”等词的消息路由到同步审核。该路径使用独立的 Writer Agent LLM 配置：单次 Provider 请求默认超时 180 秒、无自动重试，HTTP 外层默认在 210 秒结束请求。这适合短材料快速点评，不适合几十集或数百集项目审核。

现有实现还存在一项语义缺口：API 会读取关联项目的权威上下文，但同步审核提示词只携带当前会话材料、材料目录、历史对话和本轮问题，没有把关联项目上下文放入模型输入。因此，“审核更新后的项目大纲”目前不能保证模型实际看到了关联项目大纲。

系统已有正式剧本审核后台任务，具备审核记录、JobManager、逐集处理、检查点、轮询、报告和导出能力，但它只接受锁定且引用链一致的 Brief、人物、大纲、Beats 和场次剧本。完整项目长审核需要允许读取当前活动草稿，不能改变正式剧本审核的版本语义。

## 目标

- 普通对话和短材料快速点评继续使用现有同步路径。
- 完整项目审核改为可恢复的后台长任务，不受 180/210 秒同步请求总时长约束。
- 用户在任务开始前能看到本次审核将读取的准确资源、版本、状态、集数和字符数。
- 默认审核提交时的当前活动版本，包括草稿、退回修改稿、已提交稿和锁定稿。
- 支持大纲审核、剧本审核和完整项目审核。
- 根据实际大纲或剧本数量动态分批，批内逐集审核并逐集保存检查点。
- 页面关闭、刷新或重新登录不影响后台任务。
- 保持现有正式剧本审核、快速点评、人工确认和报告导出兼容。

## 非目标

- 不自动改写大纲、Beats 或剧本。
- 不替换模型，不并行请求模型。
- 不新增数据库表，不做数据库迁移。
- 不把完整项目正文写入应用日志或 Job 事件。
- 不改变现有正式剧本审核只接受锁定成果的规则。
- 不把所有快速审核统一改为后台任务。

## 核心概念

### 快速点评

用户要求点评当前会话材料、单段内容或单集内容时，继续调用 Writer Agent 同步 LLM。该路径保持 180 秒 Provider 超时、0 次自动重试和 210 秒外层超时。

### 完整项目审核

用户在已关联项目的会话中明确要求审核完整项目、全部大纲、更新后的项目大纲、全部剧本或完整剧本时，进入预检和后台任务路径。服务端不先调用同步 LLM。

### 当前活动版本

资源选择复用创作工作台的“当前资源”语义：

1. 排除 `superseded`、`historical` 等历史或已替代资源。
2. 优先选择最新的草稿、退回修改稿或已提交版本。
3. 没有可编辑活动版本时，回退到项目当前锁定版本。
4. 同一资源存在多个候选时，依次按版本号和资源 ID 选择最新项。
5. 选择结果必须在预检清单中完整展示，不允许静默选择后只显示笼统名称。

## 用户流程

1. 用户在编剧大师会话中关联或创建项目。
2. 用户输入明确长审核请求，或点击“完整项目审核”。
3. 对话返回“查看本次加载内容”操作卡，不调用同步审核模型。
4. 用户打开预检抽屉，查看项目、审核范围、资源版本、实际集数、字符数、异常和未加载原因。
5. 用户确认后，前端提交预检内容指纹和幂等键。
6. 服务端重新构造预检快照。指纹变化时返回 `409` 和新清单，要求再次确认。
7. 指纹一致时，服务端冻结快照、创建审核记录和后台 Job，并在会话中保存带审核 ID 的状态消息。
8. Worker 按动态批次逐集审核。每集完成后保存检查点，每批完成后保存批次摘要。
9. 用户可以关闭页面。重新进入会话后，状态消息从审核记录恢复真实进度。
10. 全部逐集审核完成后生成跨集、跨批次总报告；报告在会话中展示并支持 Markdown 导出。

## 审核范围

### 大纲审核

读取项目元数据、当前活动 Brief、人物、人物关系和当前活动大纲。审核重点包括全剧结构、单集核心事件、人物进展、冲突、反转、爽点、结尾钩子、相邻集承接和跨集连续性。

### 剧本审核

读取项目元数据、当前活动 Brief、人物、人物关系，以及每个已有剧本对应的大纲、Beats 和当前活动剧本。审核重点包括剧本是否落实上游设计、场景目标、阻力、人物行动、转折、台词、OS、节奏和钩子。

### 完整项目审核

先审核所有现有大纲，再审核所有现有剧本。尚未生成剧本的集数只进行大纲审核。大纲和剧本是两个独立处理阶段，各自根据实际工作单元数量计算批次，不能把两类数量相加后共用一个批次大小。

进度与批次只依据快照中实际存在且可读取的资源数量，不使用 `target_episode_count` 虚报完成度。缺失集号单独列出。

## 快照与版本链

确认任务时冻结完整来源快照。快照至少包含：

- 项目 ID、名称、修订号和目标集数；
- 审核范围；
- Brief、人物、人物关系、大纲、Beats 和剧本的资源 ID、版本、状态、内容和内容指纹；
- 每集资源的上游引用；
- 实际审核集号和缺失集号；
- 预检清单；
- Writer Agent 会话 ID；
- 快照时间和整体来源指纹；
- 动态批次配置。

如果当前活动资源的上游引用与当前 Brief、人物批次、大纲批次或 Beats 不一致，快照仍保留当前内容，同时记录结构化的 `upstream_mismatches`。预检页面明确标记不一致资源；审核报告必须把这种差异作为待核查问题，不能静默排除或自动改用其他版本。

任务运行期间用户继续编辑项目，不改变已冻结快照。要审核最新修改，必须创建新的审核任务。

## 加载内容清单

预检清单分为“本任务冻结内容”和“当前模型请求内容”两个层次。

提交前展示：

- 项目名称和 ID；
- 审核类型；
- Brief ID、版本和状态；
- 人物批次、版本、人物数量和关系数量；
- 大纲批次、版本分布、状态、实际集数范围和字符数；
- Beats 与剧本的版本分布、状态、实际集数范围和字符数；
- 每集对应的大纲、Beats 和剧本版本；
- 缺失集号、空内容、权限不可读和上游版本不一致原因；
- 明确不加载的历史版本、已替代批次和未选择参考；
- 快照时间与内容指纹。

资源项支持展开字段摘要并跳转到源内容页面。预检接口不把完整项目正文写入浏览器日志；内容摘要需做确定性长度限制。

任务运行时展示当前请求实际加载的集号、资源引用、版本、字符数和提示词字符数。这样用户既知道整个任务冻结了什么，也知道当前模型调用具体看到了什么。

## 动态批次与模型请求

每个审核阶段根据该阶段的实际工作单元数量确定批次大小：

```text
1–9 集       batch_size = 1
10–200 集    batch_size = 10
超过 200 集  batch_size = 20
```

最后一批按实际剩余集数执行。例如，205 集大纲拆为 11 批：前 10 批各 20 集，最后一批 5 集；201 集拆为 10 批 20 集和最后 1 集。

批次是 Worker 调度、进度和阶段摘要单位，不是单次 LLM 输入单位。批内仍逐集调用模型：

1. 构造当前集审核输入。
2. 调用 LLM。
3. 规范化并保存逐集结果。
4. 立即写入检查点。
5. 更新批内进度。
6. 批次全部完成后生成批次摘要。

单次大纲审核输入包括当前集大纲、Brief、人物关系、相邻集连续性摘要和此前检查点中的未解决状态。单次剧本审核输入包括当前集剧本、对应大纲与 Beats、Brief、人物关系、相邻集连续性摘要和此前检查点状态。

最终汇总只读取逐集结果和批次摘要，不再次发送全部项目正文。所有模型提示必须明确禁止重写来源内容，要求每条问题引用资源 ID、版本、字段和输入证据。

## 阶段级 LLM 配置

完整项目审核使用独立配置前缀，不继承 Writer Agent 同步对话配置：

```text
PROJECT_REVIEW_LLM_REASONING_EFFORT=high
PROJECT_REVIEW_LLM_TIMEOUT_SECONDS=600
PROJECT_REVIEW_LLM_MAX_RETRIES=2
```

每次逐集请求最多等待 600 秒；一次初始请求加最多 2 次自动重试。整个项目任务没有总时长硬上限。配置非法时回退上述默认值并记录警告，不阻断任务创建。

## 进度与页面反馈

沿用已确认的“双阶段抽屉”布局：

- 提交前显示加载内容清单和冻结快照说明；
- 提交后同一位置切换为后台任务进度。

审核进度 payload 增加可选字段：

- `audit_scope`；
- `stage_kind`；
- `batch_size`、`batch_index`、`batch_total`；
- `batch_start`、`batch_end`；
- `current_episode`；
- `completed_units`、`total_units`；
- `request_started_at`、`request_elapsed_seconds`；
- `request_attempt`、`request_max_attempts`；
- `reasoning_effort`、`prompt_chars`；
- `loaded_resource_refs`；
- `checkpoint_episode`；
- `batch_in_flight`。

页面显示当前审核集号、所属批次、总耗时、当前请求耗时、重试次数、最近检查点和下一步。单次等待超过 8 分钟时显示“模型响应较慢，任务仍在运行”。请求超时进入重试时显示当前尝试次数。关闭弹窗或离开页面不取消任务。

已完成逐集结果允许提前查看，但必须标记为阶段性结果；跨集总报告生成前不能显示最终结论。

## 接口与持久化

在 Writer Agent 会话下增加内部接口：

- 预检完整项目审核；
- 确认并创建审核；
- 查询会话关联审核状态。

在审核接口增加从检查点恢复能力。恢复操作必须带幂等键，重复点击不得创建多个 Job。

不新增数据库表。现有审核记录继续保存状态、Job ID、来源指纹、`source_payload`、阶段性报告、最终报告和错误。`source_payload` 增加：

- `audit_scope`；
- `writer_session_id`；
- `manifest`；
- `batch_policy`；
- 当前活动版本冻结内容。

创建任务时，Writer Agent 会话保存一条包含审核 ID 的助手消息。会话读取接口根据审核 ID补充最新状态、进度和报告，因此 Worker 无需直接写 Writer Agent 数据库。

## 意图路由

长审核必须由确定性条件触发：

- 会话已关联项目；并且
- 用户明确表达完整范围，例如“完整项目”“全部大纲”“所有大纲”“更新后的项目大纲”“全部剧本”“完整剧本”；或
- 用户点击“完整项目审核”。

普通“审核一下”“点评这段”“看看这一集”等不包含完整范围的请求继续走快速点评。服务端路由先于同步模型调用，避免长审核意图再次进入 180 秒路径。

## 审核报告

最终报告包含：

- AI 建议结论和总体摘要；
- 实际审核范围和来源快照；
- 每集问题、严重度、证据和建议；
- 证据对应的资源 ID、版本和字段；
- 人物状态、逻辑、节奏、钩子和跨集连续性问题；
- 大纲设计问题与剧本执行问题的独立分类；
- 上游版本不一致问题；
- 批次摘要和全项目跨集汇总。

报告支持 Markdown 导出。报告只提供建议，不自动修改项目。后续修改必须由用户在对话中明确提出并确认相应动作。

## 权限与安全

预检、创建任务、查看报告和恢复任务分别重新检查：

- 用户拥有 `script.review.generate` 或 `script.review.read` 对应权限；
- 用户能够读取关联项目。

项目创建者、当前项目成员和可管理该项目的角色仍受上述审核权限约束。任务启动后使用冻结快照运行；权限被撤销不会破坏已启动 Worker，但原用户不能继续查看、导出或恢复该审核。

应用日志与 Job 事件只记录资源 ID、版本、状态、字符数、提示词字符数、指纹、批次和耗时，不记录完整正文。浏览器只能读取当前账号有权访问的审核清单和报告。

## 错误处理与恢复

- 预检后项目变化：返回 `409` 和新清单，要求重新确认。
- 重复确认：通过幂等键返回已存在审核和 Job。
- 单次请求超时或可重试服务错误：在同一集最多自动重试 2 次。
- 连续 3 次尝试仍失败：不跳过该集，审核进入可恢复失败状态。
- 恢复任务：保持原快照，从失败集继续，不重新审核已完成集。
- 批次摘要失败：保留逐集检查点，恢复时只重做缺失的批次摘要。
- 最终汇总失败：保留全部逐集和批次结果，恢复时只重做最终汇总。
- 页面关闭或网络中断：不影响 Worker；重新进入后从服务端恢复状态。
- 项目被删除或权限撤销：根据冻结快照完成已启动任务，但禁止无权用户继续读取结果。

## 兼容与发布

- 快速点评保持现有 Writer Agent LLM 配置和同步交互。
- 正式剧本审核保持锁定成果和人工确认语义。
- 新审核通过 `audit_scope` 与现有正式审核区分。
- 现有审核记录缺少新字段时按正式剧本审核解释。
- 不要求数据库迁移。
- 8899 服务重启前先确保当前运行中的长任务进入终态，避免中断现有 Worker。
- 保留工作区中已有 Writer Agent、原创项目、大纲性能和单字段重写修改，不覆盖或回退用户改动。

## 测试

### 单元测试

- 快速点评与完整项目审核意图路由。
- 当前活动版本选择和历史版本排除。
- 大纲、剧本和完整项目范围构造。
- 引用链不一致的保留与标记。
- 1、9、10、200、201、205 集动态批次边界。
- 批内逐集检查点、批次摘要和最终汇总。
- `PROJECT_REVIEW_LLM_*` 独立配置和非法值回退。
- 来源指纹、预检 `409` 和确认幂等。
- 报告规范化和 Markdown 导出。

### 集成测试

- 完整项目审核不调用 Writer Agent 同步 Provider。
- 创建审核记录和 Job，并把审核 ID写入会话消息。
- 每集完成后持久化检查点。
- 从逐集请求、批次摘要和最终汇总三个失败位置恢复。
- 恢复后无重复集号、无重复 Job。
- 项目权限和审核权限在预检、确认、读取和恢复时生效。
- 现有正式剧本审核与人工确认流程保持不变。

### 浏览器测试

- 双阶段抽屉展示。
- 加载清单展开、源内容跳转、缺失集号和引用链异常。
- 当前批次、当前集号、等待时间、慢响应和重试提示。
- 关闭页面后任务继续，重新进入恢复状态。
- 阶段性结果与最终报告状态区分。
- 失败任务显示“从第 N 集继续”。

### 回归测试

运行 Writer Agent、剧本审核、任务权限、创作项目和 Web UI 相关测试，再运行完整 `tests/` 测试集。使用项目 11 的只读快照进行一次端到端基准，核对页面清单、冻结快照、逐集输入引用和最终报告范围一致。

## 验收标准

- 用户在开始前能准确看到审核读取的资源、版本、状态、实际集数和字符数。
- 完整项目审核不会进入同步转圈或因 180/210 秒限制结束。
- 每次模型请求都可追溯实际加载的资源 ID、版本、字段和字符数。
- 201 集阶段采用 20 集批次，最后一批 1 集；批内仍逐集审核。
- 每集完成后结果立即持久化。
- 任意单集、批次摘要或最终汇总失败后，既有检查点不丢失。
- 恢复后从准确失败位置继续，不重复已完成工作。
- 页面显示内容与冻结快照及 Worker 实际输入一致。
- 现有快速点评、正式剧本审核、报告确认和导出保持兼容。
