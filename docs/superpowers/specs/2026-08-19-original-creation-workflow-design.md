# 原创创作工作流设计

## 1. 背景与目标

当前创作链路以仿写为唯一入口：创作项目必须绑定已采纳选题和已批准拆解卡，方向生成提示词也默认存在单一仿写来源。方向之后的 Brief、人物关系、分集大纲、单集 Beats、场次剧本、版本、任务池和审批能力已经可以复用。

本功能将原创提升为与仿写并列的一等创作模式。首期让策划和编剧都能从一句话灵感或题材创建原创项目，由 AI 一次发散 3–5 个差异明显的方向，人工选定并完善 Brief，然后进入现有创作工作流。

后续按以下顺序扩展：

1. 策划已有完整故事构想时直接填写原创 Brief。
2. 导入小说、故事梗概或旧剧本后继续创作。

首期不实现上述两个后续入口，也不在页面展示不可用按钮。

## 2. 产品原则

- 原创项目不伪装成选题或拆解卡，不污染选品、拆解和仿写统计。
- 原创和仿写只在项目输入及方向生成阶段分流；Brief 锁定后的创作、任务和审批链路保持统一。
- 市场参考完全可选。没有参考时可以执行纯原创。
- 市场参考只提供题材、受众、节奏、情绪价值、成本等抽象信号，不作为改编来源。
- 任何市场结论必须可追溯；没有参考时不得虚构榜单趋势或用户偏好。
- 所有生成结果保留种子版本、参考摘要、模型、提示模板和任务记录。

## 3. 用户与入口

### 3.1 页面入口

原创创建能力同时出现在两个页面：

- `/planning/projects`：保留“从选题创建”，新增“创建原创项目”。
- `/writing/projects`：新增“创建原创项目”；“从选题创建”是否可见继续遵循既有权限。

两个页面复用同一个原创创建组件、校验规则和 API。现有两个项目列表应逐步复用共享模板，页面标题和默认筛选由调用方传入，避免策划端与编剧端出现功能漂移。

项目列表增加：

- “创作模式”：原创或仿写。
- “创作来源”：仿写项目显示来源选题，原创项目显示灵感摘要。

### 3.2 轻量创建表单

必填字段只有“一句话灵感或题材”。以下字段选填：

- 项目名称
- 目标平台
- 题材
- 目标受众
- 目标集数
- 单集时长
- 成本等级
- 内容禁区
- 市场参考

市场参考可选择榜单趋势、题材标签或多个用户有权读取的拆解卡。选择区必须显示“市场参考，不是改编来源”，并允许生成前移除。

### 3.3 主流程

```text
一句话灵感
  -> 补充可选约束和市场参考
  -> AI 生成 3-5 个原创方向
  -> 比较、编辑、补生成或派生
  -> 选择一个方向并完善 Brief
  -> 锁定 Brief
  -> 人物关系
  -> 分集大纲
  -> Beats
  -> 场次剧本
```

## 4. 数据模型

### 4.1 创作项目

`creative_projects` 增加以下字段：

- `creation_mode TEXT NOT NULL DEFAULT 'imitation'`
- `bootstrap_status TEXT NOT NULL DEFAULT 'ready'`

首期允许的 `creation_mode` 为：

- `imitation`：现有选题仿写。
- `original`：原创种子发散。

`topic_id` 和 `breakdown_id` 改为可空，并建立一致性约束：

- `imitation` 必须同时具有有效的 `topic_id` 和 `breakdown_id`。
- `original` 的 `topic_id` 和 `breakdown_id` 必须同时为空。
- 不允许出现只设置其中一个来源字段的项目。

迁移时所有既有项目设置为 `imitation` 和 `ready`，保持原来源关系不变。SQLite 需要通过重建项目表完成非空约束调整，并在复制前后校验行数、主键和外键关系。

`bootstrap_status` 用于跨创作库和系统工作流库的创建协调：

- `pending`：项目和种子已经写入，工作流成员或任务仍在建立。
- `ready`：创建完成，可以出现在正常项目列表。
- `failed`：创建失败，等待同一幂等请求重试或后台协调。

正常项目 API 默认不返回非 `ready` 项目，避免用户进入半成品工作区。

### 4.2 原创种子

新增 `creative_seeds`：

| 字段 | 含义 |
| --- | --- |
| `id` | 种子版本 ID |
| `project_id` | 所属原创项目 |
| `version` | 项目内递增版本 |
| `parent_version_id` | 上一个种子版本 |
| `seed_text` | 一句话灵感或题材 |
| `constraints_json` | 平台、题材、受众、集数、时长、成本和禁区 |
| `reference_refs_json` | 用户选择的市场参考资源标识 |
| `status` | `draft` 或 `frozen` |
| `content_fingerprint` | 规范化输入的 SHA-256 指纹 |
| `created_by` | 创建人 |
| `created_at`、`updated_at` | 时间戳 |

尚未参与生成的 `draft` 可以更新。某个种子开始生成后即冻结；之后修改会从冻结版本克隆新 `draft`，不得覆盖旧版本。方向记录永远引用准确的种子版本。

### 4.3 原创方向

继续复用 `creative_blueprints`，新增 `direction_type`：

- `imitation`：现有仿写方向。
- `original`：原创方向。

原创方向的 `source_refs_json` 记录 `seed_id`、种子版本及市场参考 ID；仿写方向继续记录 `topic_id` 和 `breakdown_id`。`generation_meta_json` 记录发送给模型的市场参考摘要、模型、提示模板版本、任务 ID 和校验结果。

人物、关系和 `creative_episodes` 不增加原创专用结构。它们继续通过已锁定 Brief 关联上游。

## 5. 服务与 API

### 5.1 服务边界

新增两个窄职责服务：

- `OriginalProjectService`：验证输入、幂等创建项目和种子、协调成员及初始任务、处理重试。
- `MarketReferenceService`：校验参考读取权限，将参考资源整理为允许进入模型的抽象市场上下文。

现有方向生成服务按 `creation_mode` 选择提示模板和校验器。人物、大纲、Beats 和剧本服务保持统一。

### 5.2 API

保留现有 `POST /api/creative/projects`，继续处理仿写立项，不改变请求和响应契约。

首期新增：

- `POST /api/creative/projects/original`：幂等创建原创项目和首个种子。
- `GET /api/creative/projects/{project_id}/seeds`：读取种子版本。
- `POST /api/creative/projects/{project_id}/seeds/versions`：从当前版本创建新草稿。
- `PATCH /api/creative/seeds/{seed_id}`：更新尚未冻结的草稿。

原有 `POST /api/creative/projects/{project_id}/blueprints/generate` 保持路径不变，根据项目模式选择 `phase4-v3` 或 `original-direction-v1`。请求继续支持 `count=3..5` 和工作流任务 ID，并增加可选的保留方向 ID，以支持“保留部分候选，仅补足剩余方向”。

未来的直接 Brief 和文档导入使用独立入口，例如 `/projects/from-brief` 与 `/projects/import`，不扩大首期原创创建请求。

### 5.3 跨库创建一致性

创作数据位于 SQLite，成员和工作流位于系统数据库，无法依赖单一数据库事务。`OriginalProjectService` 使用幂等业务事务：

1. 完成权限、字段和市场参考校验。
2. 以 `creation_request_id` 在创作库事务中创建 `pending` 项目和首个种子。
3. 幂等建立项目负责人、项目成员和 Brief 工作流任务。
4. 全部成功后将项目标记为 `ready`。
5. 中途失败时保留不可见的 `pending` 或 `failed` 记录；相同请求重试时继续协调，而不是新建项目。

创建服务和后台协调器都必须能够安全重复执行。只有 `ready` 项目进入项目列表和后续生成接口。

## 6. AI 生成设计

### 6.1 模型输入

原创提示模板独立版本化为 `original-direction-v1`。输入分为：

1. 冻结的原创种子。
2. 项目创作约束。
3. 可选的 `market_context`。

`market_context` 只允许包含：

- 目标平台和榜单类型
- 题材及题材趋势标签
- 抽象受众偏好
- 节奏、钩子类型和情绪价值标签
- 成本和制作难度信号
- 参考资源 ID 及快照时间

禁止发送来源作品的角色名、具体台词、完整剧情节点、独特设定表达和长文本摘录。原始参考保留在系统中用于权限控制和追溯，但不直接拼入原创提示词。

### 6.2 方向输出

每次生成 3–5 个方向。每个方向至少包含：

- 暂定名
- 一句话故事
- 核心命题
- 主角、核心欲望、缺陷与压力反应
- 主要阻力和核心冲突
- 世界观、背景和故事发动机
- 前三集钩子
- 主要爽点和情绪回报
- 差异化卖点
- 目标受众和市场适配理由
- 成本等级
- 原创性说明
- 创作风险、假设和待验证问题

候选方向至少应在主角身份、故事背景、冲突发动机、人物关系或情绪回报中的两个维度有明显差异。

### 6.3 校验与修复

服务端执行：

- JSON 和字段结构校验。
- 禁区和必填约束校验。
- 候选间文本重复度与关键维度差异检查。
- 市场结论的参考 ID 校验。
- 禁止来源专有名词和具体表达泄漏的检查。

校验失败时自动修复一次。仍不合格的候选不得静默写入正式方向；可以保存合格候选并返回缺口数量，让用户补充生成。没有市场参考时，市场适配内容必须标记为创作判断，不能表述为已验证事实。

### 6.4 用户操作

策划和编剧可以：

- 整组重新生成。
- 保留部分方向并补足剩余数量。
- 从某个方向派生变体。
- 手工编辑方向。
- 将一个方向完善并锁定为 Brief。

修改已经用于生成的种子时，页面创建新版本并提示后续生成将使用新版本；既有方向继续保留并显示原种子版本。

## 7. 工作流、权限与页面状态

### 7.1 工作流复用

原创不建立独立状态机，继续使用现有项目生命周期：

```text
created
  -> direction_review
  -> brief_locked
  -> characters_locked
  -> outline_locked
  -> beats_in_progress
  -> script_in_progress / completed
```

原创方向被选定并完成时仍作为 `brief` 资源完成现有任务。人物关系、分集大纲、Beats 和场次剧本继续使用现有任务池、领取、指派、版本、提交和审批逻辑。

工作流项目任务允许 `topic_id` 为空，以 `project_id` 作为原创项目唯一归属。需要修改 `ensure_project_task()`、任务匹配和来源校验中假定 `topic_id` 必填的代码，但不复制任务表或状态机。

### 7.2 权限

- 拥有 `project.create` 的策划或编剧都能创建原创项目。
- 创建者自动成为项目负责人和有效项目成员，并获得初始 Brief 编辑能力。
- 有效项目成员按现有规则协作编辑各阶段。
- 项目负责人和系统管理员继续管理成员、任务和审批。
- 市场参考选择受来源资源原有读取权限约束。
- 没有参考读取权限的项目成员不能新增或展开参考原文，即使其拥有项目编辑权。

### 7.3 Brief 页面

原创项目的 Brief 页面包含：

1. 原创种子及版本。
2. 原创方向比较与编辑。
3. 选定方向后的正式 Brief。

原创模式不显示“来源选题”“拆解版本”“仿写理由”等字段；改为显示“原创种子”“市场参考”和“原创性说明”。

## 8. 异常处理

- 重复创建依靠 `creation_request_id` 返回同一项目。
- 同一项目和种子版本同一时间只允许一个方向生成任务。
- 模型失败时保留项目和种子，不写入不完整方向。
- 输出异常自动修复一次，失败原因写入任务日志。
- 参考在任务创建前失效或无权访问时拒绝创建任务，并提示用户移除参考后重试。任务运行期间参考失效时剔除失效参考并继续纯原创，在任务结果中明确列出降级原因，不能静默降级。
- 部分候选不合格时返回已保存候选和缺口，不丢弃合格结果。
- 项目删除继续采用现有软删除，历史方向和生成快照保持可审计。
- 跨库创建失败使用同一请求重试和协调器恢复，非 `ready` 项目不进入普通列表。

## 9. 测试与验收

### 9.1 自动化测试

- 旧项目迁移后全部为 `imitation`，来源关系和访问行为不变。
- 原创项目允许空来源，仿写项目仍强制有效选题和拆解。
- 策划和编剧均可从各自项目页创建原创项目。
- 无 `project.create` 权限时页面和 API 均拒绝创建。
- 重复 `creation_request_id` 不产生重复项目、成员或任务。
- `pending` 和 `failed` 项目不进入普通项目列表。
- 纯原创和带市场参考两条生成路径均能生成 3–5 个方向。
- 市场参考权限、白名单、失效和追溯规则有效。
- 候选结构、差异度、禁区和来源泄漏校验有效。
- 种子冻结、克隆版本、方向派生、整组重生成和部分补生成行为正确。
- `topic_id` 为空时，项目任务仍能领取、指派、完成和审批。
- 原创方向锁定为 Brief 后，人物、大纲、Beats 和场次剧本全链路通过。
- 现有仿写 API、页面、生成任务和历史项目无回归。

### 9.2 业务验收

- 策划和编剧都能在 3 分钟内从一句话灵感创建项目并获得首批方向。
- 每次成功生成 3–5 个结构完整、可独立编辑且明显不同的方向。
- 每个方向都能追溯到种子版本、项目约束、参考摘要、模型和提示模板。
- 原创项目从方向选择到场次剧本不需要伪造选题或拆解卡。
- 页面、导出和审计不会把原创项目误标为仿写、改编或来源剧目。
- 历史仿写项目和现有仿写流程保持兼容。

## 10. 分期边界

### 首期

- 策划页和编剧页的原创创建入口。
- 一句话灵感和轻量约束。
- 可选市场参考。
- 3–5 个原创方向生成、编辑、派生、补生成和选定。
- 与现有 Brief 及后续工作流衔接。

### 第二期

- 完整故事构想直接创建原创 Brief。
- AI 补齐缺失 Brief 字段，但不强制先生成候选方向。

### 第三期

- 导入小说、故事梗概和旧剧本。
- 文档解析、结构识别和人工确认。
- 用户明确选择续写、重构、改编或提炼原创方向后进入相应工作流。

第三期需要单独设计导入版权声明、文档权限、长文本切分和改编来源追踪，不在本规格中提前实现。
