## 排查结果与修复总结

### 根因分析

经过深入排查，共发现 **3 个相互关联的 Bug**，导致"后台生成完毕，前台一直处于'生成中'"的问题：

---

### Bug 1（核心）：`reconcileCreativeGenerationState()` 的短路陷阱

``​`diff
- if (!this.creativeJobStatusRunning() || !this.creativeProjectHasJobResult(...)) return false;
+ if (!this.creativeProjectHasJobResult(project, action, jobId)) return false;
``​`

**问题**：`creativeJobStatusRunning()` 检查 job 状态是否为 `pending/running/stopping`。当后台 job 已成功完成（status=`succeeded`）后，此函数返回 `false`，`!false = true`，直接短路返回。导致这个专门负责"检测项目数据中已有结果→清理 UI 状态"的函数，在 job 完成后的正常场景下**永远无法触发**。

**后果**：job 完成后，`activeAction` 不清除、`jobProgress` 不更新为完成状态、项目数据不刷新。UI 虽然理论上因为 `creativeActionRunning()` 会检查 `creativeJobStatusRunning()` 而返回 false，但实际上由于项目数据也未刷新，整个 reconciliation 链路断裂。

---

### Bug 2：fallback 路径不清理 `activeAction`

在 `syncCreativeJobProgress()` 的 fallback 路径（第 2952-2956 行）中，检测到 terminal status 后会弹 alert 但不清除 `activeAction`。此次修复将 `activeAction = ''` 统一纳入 `reconcileCreativeGenerationState` 中。

---

### Bug 3：`selectCreativeProject` 未 await 导致数据刷新竞态

``​`diff
- if (this.creativeWorkspace.project?.id) this.selectCreativeProject(...);
- alert('创作内容生成完成...');
+ if (this.creativeWorkspace.project?.id) {
+     await this.selectCreativeProject(...);  // 先确保数据刷新
+     if (this.reconcileCreativeGenerationState(...)) return;
+ }
+ alert('创作内容生成完成...');
``​`

**问题**：`selectCreativeProject` 是异步请求（fetch 项目最新数据），但原代码未 `await`，紧接着弹出 `alert()` 阻塞 UI 线程。用户关闭 alert 时，项目数据大概率还未加载完成，看到的是旧数据。
