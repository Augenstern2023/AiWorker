# 全集剧情概览设计规格

## 目标

在“全剧大纲”页面的大纲版本选择区与分集搜索栏之间增加“全集剧情概览”。概览随大纲版本生成和保存，让编剧在进入分集细节前快速掌握全剧核心事件、人物推进、主要冲突、关键反转、剧情亮点与结尾悬念。

本次改动同时支持新大纲自动生成概览，以及为既有大纲单独补充生成概览。补充概览不得重写任何分集大纲。

## 范围

### 包含

- 新大纲生成时同步生成六项结构化概览。
- 旧大纲基于当前批次全部分集内容单独生成概览。
- 草稿批次的概览编辑、校验和原子保存。
- 已锁定批次的概览只读展示。
- 大纲版本创建、克隆和重新生成时的概览继承或隔离。
- 大纲 Markdown 下载中的概览输出。
- 桌面端和窄屏布局、加载、空、错误、禁用及键盘状态。

### 不包含

- 改写或自动修复现有分集大纲。
- 在概览字段和分集字段之间进行实时双向同步。
- 修改现有大纲审批、锁定或版本状态机。
- 新增独立数据库表或数据库迁移。

## 信息结构

概览使用固定的六字段对象：

| 展示名称 | JSON 字段 | 含义 |
|---|---|---|
| 核心事件 | `core_event` | 全剧持续推进并最终收束的核心事件 |
| 人物推进 | `character_progress` | 主要人物的目标、选择、代价与成长变化 |
| 主要冲突 | `conflict` | 贯穿全剧的外部冲突与内部冲突 |
| 关键反转 | `reversal` | 改变观众认知或人物行动方向的全局反转 |
| 剧情亮点 | `highlight` | 最具传播性、情绪价值或视听表现力的段落 |
| 结尾悬念 | `cliffhanger` | 大结局完成阶段收束后保留的后续钩子 |

存储键名为 `series_overview`。六个字段均为去除首尾空白后的非空字符串。

## 页面布局与交互

概览区位于大纲版本选择区下方、分集搜索工具栏上方。它是全剧级信息区，不嵌套在任意分集卡片内。

### 视觉层级

- 使用现有深色工作台的颜色、字号、圆角、边框和表单控件。
- 容器左侧使用蓝色强调线，明确区分全剧概览与下方分集列表。
- 标题栏依次展示“全集剧情概览”、当前大纲版本说明、收起/展开操作和当前状态允许的主操作。
- 展开内容为两列六字段布局，字段顺序按“核心事件、人物推进、主要冲突、关键反转、剧情亮点、结尾悬念”排列。
- 窄屏下折叠为单列，操作区允许换行，不产生横向滚动、遮挡或文字裁切。

### 展开状态

- 有概览时默认展开。
- 用户可在当前页面会话内收起或展开；切换大纲上下文时恢复默认展开。
- 收起后标题和状态仍可见，不在折叠状态中隐藏错误或保存结果提示。

### 编辑状态

- 草稿批次：六项使用带可见标签的文本域，可编辑。
- 任意字段改变后，保存按钮进入待保存状态。
- 保存时一次提交全部六项；任何字段为空时，在对应字段下显示校验提示并阻止请求。
- 保存成功后清除待保存状态并显示非阻塞成功提示。
- 保存失败时保留全部未保存输入，显示错误和重试入口，不重新拉取数据。
- 已锁定或已批准批次：字段只读，不显示保存操作。

### 生成状态

- 尚无分集大纲：显示“生成分集大纲后将自动形成全集概览”，不提供独立生成按钮。
- 当前批次有分集大纲但无 `series_overview`：显示兼容说明和“生成概览”按钮。
- 生成过程中按钮显示进度并禁用重复提交。
- 生成成功后立即以可编辑状态显示六项结果。
- 生成失败时保留原页面与分集内容，显示错误和重试入口。
- 已存在概览时不提供重新生成按钮，避免无意覆盖人工修改。

所有按钮使用语义化 `button` 元素并提供可识别名称；字段标签与文本域显式关联；状态变化通过现有通知机制反馈。焦点样式沿用全站规则。

## 生成流程

### 新大纲

现有大纲生成先规划全剧阶段弧线，再分批生成分集内容。第一阶段响应扩展为：

```json
{
  "series_arc": "供后续分集生成使用的阶段弧线",
  "stages": ["阶段一", "阶段二", "阶段三"],
  "series_overview": {
    "core_event": "主角围绕全剧目标持续行动并完成阶段收束",
    "character_progress": "主角在选择与代价中完成核心成长",
    "conflict": "外部阻力与人物内部矛盾共同升级",
    "reversal": "关键真相改变人物关系与行动方向",
    "highlight": "最具情绪价值和视听表现力的剧情段落",
    "cliffhanger": "阶段结局之后仍待揭晓的后续钩子"
  }
}
```

`series_arc` 与 `stages` 继续承担分集生成上下文，`series_overview` 专门用于用户阅读、编辑和下载。生成校验要求六项齐全且为非空字符串；响应不合格时沿用现有结构修复与重试机制。

### 既有大纲

为当前大纲批次新增独立概览生成动作。输入包含当前批次按集数排序的六项分集字段，以及当前 `series_arc`；输出仅允许为上述 `series_overview` 对象。

该动作只更新批次公共概览，不改变分集字段、集数、版本、状态、上游引用或生成元数据。锁定或批准批次不允许补充生成，以保持锁定内容不可变。

## 存储与一致性

现有实现将批次级 `series_arc` 写入同一批次每条分集记录的 `content_json`。`series_overview` 沿用相同模式，作为批次级公共元数据写入每条记录，避免数据库迁移并保持快照、克隆和下载链路兼容。

仓储层提供批次级更新方法：

1. 校验项目、大纲批次及其可编辑状态。
2. 规范化并验证六项字段。
3. 在一个数据库事务中读取该批次全部分集的 `content_json`。
4. 为每条记录设置同一个 `series_overview` 值。
5. 更新全部记录的 `updated_at`。
6. 任意一条写入失败时整体回滚。

读取时以批次第一条分集记录的 `series_overview` 作为公共值。仓储测试保证同一批次不存在部分更新。旧记录缺少该键时按“无概览”处理；现有 `series_arc` 保持不变。

## API 与权限

新增两个批次级动作：

- `POST /api/creative/projects/{project_id}/outlines/{batch_id}/overview/generate`
- `PATCH /api/creative/projects/{project_id}/outlines/{batch_id}/overview`

生成动作使用现有 `outline.generate` 权限；编辑保存使用现有 `outline.edit` 权限。两者均复用项目可见性、成员阶段范围、工作流任务归属和资源状态校验，不新增权限项。

请求中的项目 ID、批次 ID 和当前活动大纲批次必须一致。对不存在、非当前、已锁定、已批准或无权限的资源，返回现有 API 风格的明确错误，不修改数据。

项目详情响应无需新增顶层数据源；前端从当前批次第一条分集内容读取 `series_overview`，与现有 `series_arc` 的存储方式一致。

## 版本与工作流行为

- 新生成大纲批次具有独立的新概览，不覆盖任何旧批次。
- 从现有大纲创建或克隆新草稿版本时，分集内容连同 `series_overview` 一并继承。
- 草稿概览可编辑；锁定或批准后只读。
- 切换 Brief 或人物关系导致当前大纲失效时，概览随原大纲批次保留，不迁移到新上下文。
- 概览保存不改变项目状态，也不单独创建新版本。

## 下载输出

`build_outline_markdown` 在项目标题与第一集之间增加“全集剧情概览”章节，按固定六项顺序各输出一次。随后保持现有逐集输出结构。

旧批次没有概览时不输出空章节，现有下载内容保持兼容。由于概览在每条分集记录中重复存储，下载逻辑只读取排序后第一条记录，禁止在每集重复输出。

## 错误处理

- 模型响应缺字段、类型错误或空字符串：进入现有结构修复与有限重试；最终失败则返回生成错误，不写入概览。
- 并发重复生成：复用当前创作动作的任务幂等与运行中状态，拒绝同一项目、同一批次的重复动作。
- 保存时批次已被锁定或切换：后端拒绝写入，前端保留输入并提示刷新当前版本。
- 数据库事务失败：整体回滚，不允许同一批次各集持有不同概览。
- 网络错误：保留用户输入和现有概览，允许重试。

## 测试与验收

### 生成与校验测试

- 新大纲阶段规划响应必须包含合法的六项 `series_overview`。
- 缺字段、非字符串和空字符串触发修复或最终失败。
- 旧大纲概览生成只读取当前批次并保持全部分集字段不变。
- 生成失败不写入部分概览。

### 仓储与版本测试

- 批次级保存将同一概览原子写入全部分集记录。
- 已锁定、已批准、非当前或不存在的批次不可更新。
- 克隆草稿继承概览，新生成批次不覆盖旧批次。
- 旧数据缺少 `series_overview` 时仍可读取和下载。

### API 与权限测试

- `outline.generate` 和 `outline.edit` 分别控制生成与保存。
- 项目不可见、阶段范围不匹配、批次不一致和锁定状态返回正确错误。
- 成功响应返回更新后的当前批次概览。

### 页面测试

- 新大纲自动显示六项概览；旧大纲显示“生成概览”入口。
- 草稿可编辑并保存，缺项时显示字段级错误且不发请求。
- 保存失败保留输入；保存成功清除待保存状态。
- 已锁定批次只读且没有保存按钮。
- 收起、展开以及切换大纲上下文后的默认状态正确。
- 分集搜索、批量展开和分集卡片行为不受影响。
- 桌面两列和窄屏单列无横向滚动、重叠或裁切。

### 下载测试

- 有概览时 Markdown 在分集内容前只输出一次六项概览。
- 无概览的旧批次不输出空章节。

## 完成标准

- 用户可在指定位置查看结构清晰的六项全集剧情概览。
- 新大纲自动生成概览，旧大纲可单独补充生成。
- 草稿可安全编辑保存，锁定内容不可修改。
- 概览正确跟随大纲版本，不覆盖旧版本或改动分集内容。
- 页面、API、仓储、生成及下载测试通过，并完成桌面与窄屏视觉检查。
