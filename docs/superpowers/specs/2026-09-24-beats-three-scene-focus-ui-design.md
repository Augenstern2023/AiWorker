# Beats 三场次限制与聚焦式编辑器设计规格

**状态：** 待实现

**日期：** 2026-09-24

**关联文档：**

- `improve/三剑客改造.md`
- `docs/superpowers/plans/2026-09-22-three-tools-ui-performance.md`
- `issue/UI.md`

## 1. 背景

当前 Beats 页面同时展示场景、目标、阻力、情绪、局面、代价、策略、转折和钩子等字段，信息密度过高，标题与正文层级不明显，多行文本容易被压缩。用户需要首先判断“这一集发生在哪里、谁在场、发生了什么转折、结尾留下什么追看点”，而不是一开始阅读完整的结构分析。

本规格新增两项业务约束，并将其转化为统一的数据校验和 UI 交互：

1. 每集 Beats 最多 3 个场次；
2. 首屏优先突出**结尾钩子、场景、人物、转折**，行动目标、阻力、情绪变化、局面变化、代价、对抗策略等字段默认隐藏，但仍可展开编辑。

## 2. 目标与非目标

### 2.1 目标

- 所有生成、编辑、保存、锁定、采纳和导出入口遵守每集最多 3 个场次。
- 不静默截断已有内容；对历史超限数据给出可修复的阻断状态。
- 单集、全集和优化草稿页面使用一致的 Beats 信息层级。
- 让用户无需展开详情即可看清场景、人物、转折和结尾钩子。
- 解决 `issue/UI.md` 中的拥挤、字体层级单一、多行内容展示不全和历史模板提示误导问题。
- 保持现有 FastAPI、Jinja2、Bootstrap 5、Alpine.js、权限、API payload 和深色品牌视觉，不引入新依赖。

### 2.2 非目标

- 不自动合并或改写用户已有 Beats 文本。
- 不改变 Beats 字段的数据结构、版本语义、锁定状态机或上下游引用关系。
- 不删除详细字段；详细字段仅改变默认展示方式。
- 不借 UI 改造顺便重构无关页面、数据库 schema 或运行时服务。
- 不以 3 个场次限制代替完整的剧作质量判断；字段完整性仍由现有校验负责。

## 3. 核心业务规则

### 3.1 场次数量

Beats payload 中 `beats` 数组的长度即本集场次数量，合法范围为 `1..3`。空白自由创作草稿可以暂存 `beats: []`，但完成、锁定或采纳前必须生成至少 1 个合法 Beats。

统一校验边界：

| 入口 | 规则 |
| --- | --- |
| 单集生成 | prompt 明确生成 1-3 个 Beats；服务端最终校验 |
| 批量生成 | 每集独立校验 1-3 个 Beats，不能只校验总数 |
| 顺序创作保存 | 超过 3 个拒绝保存 |
| 自由创作创建/更新 | 空白草稿允许为空；非空 payload 不得超过 3 个 |
| 优化草稿保存/采纳 | Beats 草稿不得超过 3 个 |
| 手动新增场次 | UI 在第 3 个后禁用新增；服务端仍是最终防线 |
| 完成并锁定 | 超限或不满足现有字段校验时拒绝 |
| 历史/legacy 数据 | 读取可兼容；写入、锁定、采纳不得继续产生超限版本 |

### 3.2 超限数据处理

历史上已经存在 4 个或更多场次时：

- 页面显示明确的超限提示，例如“当前 4 个场次，超过每集最多 3 个场次”；
- 禁用保存、完成并锁定、优化采纳等会产生新版本或锁定状态的操作；
- 不自动删除、截断或合并任何场次；
- 用户通过删除或手动合并文本恢复到 3 个以内后，按钮恢复可用；
- 全集视图显示 `4/3` 和警告状态，避免用户误以为数据合规。

## 4. 信息架构与视觉层级

### 4.1 核心字段层

单集编辑器首屏固定展示以下字段，顺序统一为：

1. 场景
2. 人物
3. 转折
4. 结尾钩子

“结尾钩子”是本层的视觉主强调字段；“转折”是次强调字段。字段标签和内容必须具备清晰的字号、颜色、间距和背景层级，不能所有字段使用同一套灰色小字。

建议视觉语义：

- 场景：主文本色，承担当前场次定位；
- 人物：蓝/青色辅助色，承担角色定位；
- 转折：紫色或高亮边框，承担剧情变化提示；
- 结尾钩子：橙色或暖色强调背景/边框，承担追看点提示；
- 正文最小字号 14px，行高 1.6 以上；
- 多行文本区域允许按内容自动增高，不使用不可读的固定短高度。

### 4.2 详细字段层

以下字段默认收起：

- 行动目标
- 阻力
- 情绪变化
- 局面变化
- 代价
- 对抗策略

折叠标题必须直接说明内容范围，例如：

> 展开详细分析：行动目标、阻力、情绪变化、局面变化、代价、对抗策略

展开后保持原字段编辑能力、保存 payload 和字段名称不变。

### 4.3 连续性检查层

连续性变更、道具/信息状态和全剧连续性账本默认收起，放在右侧 Inspect 区域。用户展开后可以继续新增、编辑和删除连续性记录。连续性折叠不应影响核心字段的可视空间。

## 5. 页面设计

### 5.1 单集 Beats

采用 Command / Edit / Inspect 三段式布局：

- 顶部 Command：集数、版本、模板来源、生成、保存、锁定和数量提示；
- 左侧场次导航：最多显示 3 个场次，显示编号、场景名和核心字段完成状态；
- 中间 Edit：当前场次的四个核心字段直接可见，详细字段折叠；
- 右侧 Inspect：连续性检查默认折叠。

数量提示同时显示总规则和当前值：

> 每集最多 3 个场次 · 当前 2 个

超限时切换为错误色，并在按钮上反映不可操作状态。

### 5.2 全集 Beats

每集使用独立卡片，不平铺完整字段。卡片默认显示：

- 集数、版本和状态；
- 场次数量 `2/3`；
- 每个场次的场景；
- 人物；
- 转折；
- **结尾钩子**；
- 打开单集编辑操作。

行动目标、阻力等详细字段不出现在全集摘要中。

### 5.3 优化草稿

优化草稿中的 Beats 编辑器必须复用相同的信息层级：

- 场景、人物、转折、结尾钩子直接展示；
- 详细分析默认折叠；
- 连续性变更默认折叠；
- 新增按钮最多添加到第 3 个场次；
- 保存和锁定采纳前执行相同的 3 场次约束。

### 5.4 历史模板来源

历史记录缺少模板元数据时，统一显示“经典兼容模板”，不显示“历史生成模板记录缺失”等错误性文案。模板来源是辅助信息，不能挤占核心 Beats 内容。

## 6. 数据流与错误处理

### 6.1 生成流程

1. 生成 prompt 明确每集 1-3 个 Beats；
2. 服务端解析 JSON；
3. 统一 validator 检查数组长度、序号连续性和现有字段要求；
4. 校验失败时按现有重试/错误返回流程处理，不保存非法版本；
5. 批量生成按 episode 独立报告错误，不能用一个集的合法结果掩盖另一集超限。

### 6.2 编辑流程

- Alpine 状态实时计算当前 Beats 数量；
- 数量超过 3 时显示错误状态并禁用保存/锁定；
- 用户删除或合并场次后重新计算；
- 服务端返回的 409/422 错误仍通过现有错误提示展示，前端校验不能替代服务端校验。

### 6.3 空数据与只读状态

- 尚未生成：显示空状态和生成入口；
- 自由模式空白版本：允许保存空草稿，但不允许锁定空版本；
- 已锁定版本：核心字段和详细字段均只读；
- 超限历史版本：可浏览和编辑，但不能保存/锁定，直到恢复合规。

## 7. 文件职责边界

实现时限定在以下职责范围：

| 文件 | 职责 |
| --- | --- |
| `creative/script_service.py` | 统一 Beats 数量和字段校验 |
| `creative/prompt_templates.py` | 单集/批量 prompt 的 1-3 场次及核心字段要求 |
| `creative/prompt_registry.py` | 内置模板参数与 Beats 规则保持不超过 3 |
| `creative/free_mode_service.py` | 自由模式创建、更新和保存边界校验 |
| `screenplay_optimization/api.py` | 优化草稿保存和采纳校验 |
| `templates/common/workspace/project_beats.html` | 单集/全集信息层级与折叠结构 |
| `static/js/writing/beats.js` | 数量状态、按钮禁用和场次导航辅助方法 |
| `static/js/writing/optimization_draft.js` | 优化草稿一致的编辑与数量限制 |
| `static/css/workspaces.css` | 核心字段、钩子、折叠、超限和响应式样式 |
| 相关 `tests/` | 后端、静态模板和浏览器行为验证 |

不在本规格中拆分新的前端框架、组件库或构建系统。

## 8. 可访问性与响应式要求

- 折叠使用原生 `<details>/<summary>` 或等价可访问控件；
- 键盘可访问场次导航、核心字段、折叠面板和主要操作；
- 超限提示使用 `role="status"` 或等价的 aria-live 反馈；
- 禁用按钮同时提供可见原因，不只依赖颜色；
- 1440×900：三栏布局完整可用；
- 1024×768：检查区可下移或折叠，不产生页面级横向滚动；
- 390×844：场次导航、核心字段和操作区改为单列，正文不被截断；
- 遵守 `prefers-reduced-motion`，不新增必须依赖动画理解的交互。

## 9. 性能约束

- 不新增运行时依赖和大型资源；
- Beats 页面继续按路由加载所需脚本，不把无关模块加入基础壳；
- 折叠详细字段不应导致重复请求或额外轮询；
- 页面状态更新只重新计算当前资源相关数量，不扫描无关页面数据；
- 继续遵守原计划中的静态资源体积、轮询生命周期和路由级资源加载预算。

## 10. 验证矩阵

### 10.1 后端

- 1、2、3 个 Beats 可通过校验；
- 4 个 Beats 在普通和 legacy 模式均被拒绝；
- 自由模式创建、更新和保存拒绝超限；
- 优化草稿保存和采纳拒绝超限；
- 单集和批量 prompt 都包含 1-3 场次约束；
- 历史无模板来源时归一为经典兼容模板展示。

### 10.2 前端静态检查

- 核心字段四项存在且位于默认可见区域；
- 详细字段位于默认关闭的折叠区；
- 连续性检查默认关闭；
- 存在 3 场次提示和超限状态；
- 保存、锁定和优化采纳操作使用超限状态；
- 不再输出“历史生成模板记录缺失”错误文案。

### 10.3 浏览器验收

使用新端口启动服务，不停止现有 8899 服务，验证：

1. 正常 3 场数据可以浏览、编辑、保存和锁定；
2. 4 场历史数据显示 `4/3`，保存/锁定不可用；
3. 删除或合并到 3 场后操作恢复；
4. 首屏可直接看到场景、人物、转折、结尾钩子；
5. 详细字段默认不可见，展开后可编辑；
6. 全集卡片不再平铺详细分析字段；
7. 多行内容完整显示，字体、间距和颜色存在层级；
8. 1440×900、1024×768、390×844 均无页面级横向滚动；
9. 8899 服务保持可用，8898 页面加载的是新工作区。

## 11. 完成判定

只有同时满足以下条件才算完成：

- 所有后端写入和锁定路径统一执行 3 场次限制；
- 单集、全集、优化草稿三个页面完成相同的核心字段聚焦；
- 详细字段默认隐藏且可恢复编辑；
- 历史超限数据不丢失、可识别、可修复；
- UI.md 中的拥挤、文字层级、长文本可读性和模板提示问题得到验证；
- 定向后端、静态和浏览器测试通过；
- 新端口验收完成且未影响 8899 服务；
- 未引入无关重构、依赖或未授权的工作区改动。
