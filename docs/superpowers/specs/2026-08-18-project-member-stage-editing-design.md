# 项目成员全阶段编辑权限设计

## 目标

任意有效项目成员，无论其全局角色或项目角色，都可在所属项目内查看并编辑全部创作阶段：Brief、人物关系、分集大纲、Beats 和场次剧本。

## 授权边界

- 授权来源是 `project_members` 中该用户在该项目下至少一条 `active` 成员关系。
- 项目成员可查看草稿、生成内容、保存修改、创建版本、完成并锁定全部创作阶段。
- 项目成员可看到、领取和使用该项目的阶段工作流任务；任务已由其他成员领取时仍可协作编辑，审计事件记录实际操作者。
- 成员关系停用或移除后，项目内编辑授权立即失效。
- 非成员继续被拒绝；任何成员关系都不能扩展到其他项目。
- 本规则不授予项目成员管理、项目删除、项目归档、角色管理或全局页面访问权。
- 不修改角色权限表和后台已配置权限；授权在请求时根据项目成员关系动态判定。

## 实现边界

`WorkflowRepository` 提供统一的有效项目成员与项目任务编辑判定。工作流任务列表、领取、开始和创作完成流转复用该判定。Creative API 的动作权限、项目范围、生成任务权限与资源任务校验也复用同一成员判定，避免只修复某一个阶段。

前端继续使用现有创作工作区，不新增控件。项目成员进入任意阶段后可直接执行操作；任务解析逻辑允许复用由其他成员领取的开放任务。403 错误保留后端具体原因，便于识别成员已失效或资源不属于项目等问题。

## 并发与审计

阶段任务仍维持单一状态机和单一 `assignee_id`，避免创建重复阶段任务。第一个成员可以领取池任务；任务进入开放状态后，其他有效成员可协作编辑。每次生成、保存和完成操作仍记录实际 `actor.user_id`，不会把操作者伪装成任务负责人。

## 验证

- 与阶段角色不匹配但属于项目的成员可以领取 Brief 池任务并生成 Brief。
- 项目成员可以编辑由另一成员领取的阶段资源并完成工作流。
- 同一账号对非成员项目仍返回 403。
- 成员停用或移除后立即返回 403。
- 后台角色权限记录在实现前后不发生变化。
