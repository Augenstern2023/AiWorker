# 红果短剧剧评/评分接口分析与解决方案

## 一、结论

当前没有找到红果短剧公开开放平台，也没有发现可公开调用的“剧评/评论列表/评分”接口。现有 WPF 项目和配置中心只能支持红果短剧的搜索、详情、剧集、播放、榜单等数据链路，无法直接获取评论正文、前十高赞评论或官方评分。

## 二、现有项目可获取的数据

项目启动后会请求配置中心：

```text
https://mizhi.kissm.top/pc/con.php
```

配置中心下发红果相关接口：

```text
搜索接口：
http://36.138.76.25:4455/api/api.php?platform=wpf11&action=search

详情接口：
http://36.138.76.25:4455/api/api.php?platform=wpf11&action=detail

剧集接口：
http://43.142.49.190:1789/api/g/wk_app_book.php

播放接口：
http://43.142.49.190:1789/api/g/52_api_play.php
```

可获取字段主要包括：

- 剧名
- book_id
- 封面
- 简介
- 作者/分类
- 总集数
- video_id
- 集标题
- 播放地址
- 爆款榜单数据
- 点赞量、收藏量、评论量等统计字段（取决于接口返回）

不能直接获取：

- 评论正文
- 评论用户
- 评论时间
- 评论点赞数
- 高赞评论排行
- 官方评分
- 评分分布

## 三、红果视频数据拉取链路

现有项目的数据链路如下：

```text
启动客户端
  ↓
请求配置中心 con.php
  ↓
获取 searchUrl / detailUrl / bookUrl / playUrl
  ↓
通过 searchUrl 搜索剧名，得到 book_id
  ↓
通过 detailUrl 获取剧详情
  ↓
通过 bookUrl 获取剧集列表，得到 video_id
  ↓
通过 playUrl 获取 data.video_url
  ↓
客户端用 HTTP GET 下载或播放视频
```

也就是说，项目不是直接访问红果官方公开 API，而是依赖第三方中转接口把红果数据整理成统一 JSON。

## 四、为什么找不到剧评和评分接口

1. 红果短剧目前没有发现面向普通开发者的开放平台或 OpenAPI 文档。
2. 评论数据涉及用户内容、用户信息和互动数据，通常属于高风控数据，不会轻易公开开放。
3. 当前第三方接口主要服务于“找剧、看剧、下载”，不是评论舆情分析，因此只保留 comment_count 等统计字段。
4. 如果红果 App 内部存在评论接口，也大概率需要账号、设备参数、签名、风控校验，不能直接公开调用。

## 五、推荐解决方案

### 方案 1：先做内部热度评分（推荐优先落地）

用现有接口能拿到的点赞、收藏、评论量、榜单排名、发布时间等字段，构建内部“短剧价值评分”。

示例评分模型：

```text
综合热度分 =
  log(点赞数 + 1) * 0.35
+ log(收藏数 + 1) * 0.25
+ log(评论数 + 1) * 0.20
+ 新鲜度分 * 0.10
+ 榜单权重 * 0.10
```

适合用于：

- 爆款短剧筛选
- 短剧选题
- 分镜/解说素材优先级排序
- 自动化榜单
- 内容价值判断

优点是稳定、合规、可立即实现；缺点是它不是红果官方评分，也没有评论正文。

### 方案 2：把 comment_count 作为评论热度代理

即使拿不到评论正文，评论数量仍然可用于判断讨论度。

可以形成简单判断：

```text
评论数高 + 点赞高：传播强
评论数高 + 点赞一般：争议强
收藏高 + 评论低：内容吸引但讨论弱
点赞高 + 收藏低：爽点强但复看价值弱
```

这可以作为短剧筛选的第一版策略。

### 方案 3：小规模抓包验证红果 App 内部评论接口

如果必须拿真实评论，需要用自有账号、自有设备做技术验证：

```text
安卓模拟器/真机
  ↓
安装红果短剧 App
  ↓
登录自有账号
  ↓
使用 mitmproxy / Charles / Fiddler 抓包
  ↓
打开剧集评论区
  ↓
定位评论列表接口
```

重点确认字段：

```text
book_id
video_id
comment_id
content
like_count
nickname
avatar
create_time
cursor
has_more
score/rating（如果存在）
```

如果遇到 TLS pinning，可能需要 Frida 等工具做验证。但如果接口存在强签名、强风控或复杂设备校验，不建议投入过深。

### 方案 4：用抖音等外部评论做口碑补充

如果短剧在抖音、番茄、头条等平台有对应推广视频，可以尝试用剧名或视频标识做映射，分析外部评论。

注意：这不是红果 App 内部剧评，只能作为外部舆情参考。

### 方案 5：商业化场景走授权或第三方数据源

如果需要长期稳定获取评论或评分，建议联系：

- 红果/番茄/字节商务合作
- 巨量引擎/巨量算数相关数据服务
- 短剧数据平台
- 舆情监测数据商

商业化使用时，授权或数据合作比逆向接口更稳定、合规。

## 六、建议执行路线

优先级建议如下：

| 优先级 | 任务 | 目的 |
|---|---|---|
| P0 | 整理现有接口字段并入库 | 建立基础数据池 |
| P1 | 基于点赞、收藏、评论量、榜单排名构建热度评分 | 先解决选剧和排序问题 |
| P2 | 用 comment_count 标记高讨论短剧 | 找出值得重点分析的剧 |
| P3 | 小规模抓包验证评论接口 | 判断是否能获取真实剧评 |
| P4 | 如抓包成本过高，改用抖音外部评论或数据商 | 避免陷入高风险逆向 |

## 七、最终判断

当前项目能够继续复现红果短剧数据链路，但无法靠现有接口补齐“剧评前十”和“官方评分”。最现实的方案是先基于现有统计字段构建内部热度评分；如果业务必须要真实评论，再进行小规模抓包验证或寻找授权数据源。
