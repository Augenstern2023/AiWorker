# 负责项目成员编辑设计

## 目标

在“项目管理 → 负责项目”的操作列增加成员管理入口，让具有 `project.member.manage` 的项目负责人进入独立页面，为具体项目添加或移除项目负责人、创意策划和编剧。

## 交互

- 项目列表操作列保留“打开任务书”，并增加“项目成员”人物图标。
- 成员图标进入现有路由 `/review/projects/{project_id}/members`。
- 成员页顶部提供返回负责项目的入口；主体先展示添加表单，再展示当前成员表格。
- 添加表单按项目角色加载符合条件的启用账号，提交后立即刷新候选人与成员列表。
- 移除操作按具体成员关系 ID 删除单个项目角色；删除前确认，后端继续保护最后一位项目负责人。
- 加载、空列表、接口错误和保存中状态均在页面内明确展示。

## 权限边界

- 列表入口只对系统管理员或拥有 `project.member.manage` 的账号显示。
- 成员列表、候选人、添加和移除接口均要求 `project.member.manage`，并再次校验操作者确实管理该项目。
- 候选接口只返回与 `project_owner`、`creative_planner`、`screenwriter` 对应的启用账号，不扩大身份管理权限。

## 技术方案

- 复用 `workflow.repository.WorkflowRepository` 的成员增删和候选查询。
- 在工作流 API 增加项目范围的候选人读取接口，并为成员列表补充账号显示信息。
- `templates/review/projects.html` 根据 `project_id` 在列表态与成员编辑态之间切换。
- `static/js/review/projects.js` 负责两种页面状态、表单交互和无障碍提示，不引入新依赖。

## 验证

- PostgreSQL API 测试覆盖权限、候选人、显示信息、添加和移除。
- 浏览器测试覆盖操作入口、角色切换、添加、移除、错误与空状态。
- 页面授权测试确认新候选接口只归属于成员管理页。
