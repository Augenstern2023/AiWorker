# 分集大纲单字段 AI 重写设计

日期：2026-08-25
状态：已完成交互确认，待书面规格审查

## 1. 背景与目标

当前分集大纲允许人工编辑每集内容，但缺少针对单个字段的 AI 辅助。策划或编剧为了优化某一项内容，不应重新生成整集或整版大纲。

本功能在每集的六个文本字段旁提供 AI 重写入口。用户可以直接生成，或输入补充提示词后生成。系统先展示原文和候选新稿，只有用户确认采用时才保存。

验收核心：一次 LLM 请求只生成一个指定字段；一次采用操作也只改变该字段。

## 2. 范围

支持以下字段：

| 字段 | 含义 |
| --- | --- |
| `core_event` | 核心事件 |
| `conflict` | 冲突 |
| `character_progress` | 人物推进 |
| `highlight` | 亮点 |
| `reversal` | 反转 |
| `cliffhanger` | 结尾悬念 |

本次不包含：

- 后台 Job、轮询或任务进度记录；
- AI 候选历史表或数据库迁移；
- 多候选并排、整集重写或批量重写；
- 流式输出；
- 对已经生成或锁定内容的批量重写。

## 3. 用户流程

1. 用户在某一集的字段标题旁点击“AI 重写”。
2. 弹窗显示集数、字段名、当前原文和可选提示词。
3. 用户点击“生成新稿”，前端发起同步请求并显示加载状态。
4. 接口返回后，弹窗并列展示当前原文和 AI 新稿。
5. 用户可以修改提示词并重新生成；每次仍只生成该字段。
6. 用户点击“采用新稿”后，系统保存该字段并刷新当前大纲版本。
7. 用户取消或关闭弹窗时，不保存候选内容，也不创建新版本。

## 4. 架构与职责

### 4.1 前端

`templates/common/workspace/project_outlines.html` 为六个字段提供一致的 AI 入口和重写弹窗。`static/js/common/creative.js` 负责弹窗状态、同步请求、预览、重新生成、采用与错误提示。

前端不得从模型响应中合并整集内容；它只接收并展示一个 `candidate_value`。生成期间禁用重复提交。弹窗关闭后，即使在途请求返回，也不得再写入已关闭的弹窗状态。

### 4.2 API

新增两个窄接口：

- `POST /api/creative/episodes/{episode_id}/fields/{field}/rewrite`
- `POST /api/creative/episodes/{episode_id}/fields/{field}/apply-rewrite`

生成接口只调用 LLM 和返回候选，不修改数据库。应用接口不调用 LLM，只负责权限、并发、版本和持久化。

### 4.3 服务层

`creative/script_service.py` 新增独立的单字段重写服务。它复用现有 LLM Provider 和结构化响应解析能力，但不复用用于补齐整集缺失字段的 `_repair_outline_fields()` 语义。

`creative/prompt_templates.py` 新增单字段模板，明确目标字段、上下文边界和唯一输出结构。

### 4.4 Repository

Repository 提供只更新草稿中指定字段的操作，以及“从锁定版复制新草稿并应用单字段修改”的事务操作。复制必须继承集数、全部分集内容和全集剧情概览。

## 5. API 契约

### 5.1 生成候选

请求：

```json
{
  "instruction": "强化危险感，让行动动机更明确"
}
```

`instruction` 可为空。非空提示词应经过首尾空白清理和长度限制。

成功响应：

```json
{
  "episode_id": 123,
  "blueprint_id": 45,
  "field": "core_event",
  "original_value": "当前字段原文",
  "candidate_value": "AI 生成的新稿",
  "source_fingerprint": "服务端生成的来源内容指纹"
}
```

### 5.2 采用候选

请求：

```json
{
  "candidate_value": "AI 生成的新稿",
  "source_fingerprint": "生成接口返回的来源内容指纹"
}
```

成功响应应返回更新后的集、实际写入的 blueprint，以及是否创建了新版本。前端据此刷新版本列表并选中新草稿。

来源指纹由服务端基于来源 blueprint、episode、目标字段和当前字段值确定性构造。应用时重新计算；不一致返回 `409 Conflict`。

## 6. LLM 上下文与输出约束

输入上下文包括：

- 当前集的六个字段，并明确标记唯一目标字段；
- 前一集和后一集的完整大纲，边界集自动省略不存在的一侧；
- 项目锁定 Brief；
- 人物设定和人物关系；
- 用户可选提示词。

默认规则：保留已经确定的事件、人物动机、时间线和前后集衔接，只优化目标字段的表达、节奏和戏剧性。只有用户提示词明确要求改变事件、冲突、反转或悬念时，模型才可以改变相关剧情事实。

同集其他字段和相邻集仅作为约束，不得输出或改写。模型必须只返回：

```json
{"value": "目标字段新稿"}
```

后端只接受包含一个非空字符串 `value` 的结构化结果，不执行额外的修复模型调用。空值、解析失败、额外大纲字段或明显的整集结构均视为生成失败，数据库保持不变。

## 7. 版本与持久化语义

### 7.1 草稿版

采用新稿时原地更新当前 episode 的 `content[field]`。同集其他字段、其他集和全集剧情概览不得变化。

### 7.2 锁定版

生成候选不会解锁、复制或修改锁定版。只有用户点击“采用新稿”时，后端才在同一事务中：

1. 确认来源锁定版仍可派生，且不存在需要优先处理的更新版本；
2. 复制整版为下一个草稿版本；
3. 仅替换新草稿中目标 episode 的目标字段；
4. 保留原集数、所有其他内容和全集剧情概览；
5. 返回新草稿信息，供前端自动切换。

若已有更新版本或来源内容已变化，返回 `409 Conflict`，避免从旧版本产生隐式分支或覆盖新内容。原锁定版始终保持可回看且不可编辑。

## 8. 权限

权限沿用项目既有规则，并由两个新接口分别校验：

- 项目创建者作为本项目负责人，拥有全流程阶段编辑权限，可以生成和采用新稿；
- 系统管理员及具有项目管理权限的项目负责人角色，可以编辑其管理范围内项目；
- 获得相应阶段编辑权限的项目成员可以使用该能力；
- 只有查看权限的成员不能生成或采用，接口返回 `403 Forbidden`。

前端按钮隐藏或禁用仅用于改善体验，不能替代后端授权。

## 9. 交互与错误处理

- 每个字段标题旁显示统一的“AI 重写”按钮。
- 弹窗包含当前原文、可选提示词、生成按钮、新稿预览、重新生成、采用新稿和取消。
- 生成期间显示加载态并禁用重复生成。
- LLM 超时、返回格式异常或空内容时，保留原文和提示词，显示可重试错误。
- 保存或创建版本失败时，候选新稿继续保留在弹窗，用户可以再次采用。
- 来源指纹冲突时提示“该字段已被更新，请重新生成”，不得覆盖当前内容。
- 关闭弹窗不取消已经发出的同步网络请求，但响应返回后不得更新已销毁或已重置的弹窗状态。

## 10. 测试

### 10.1 后端

- 六个合法字段分别可生成，非法字段被拒绝；
- Prompt 只要求目标字段，并包含规定的上下文；
- 空提示词采用默认优化规则，非空提示词正确传入；
- LLM 空值、非 JSON、额外字段或异常不产生数据库写入；
- 草稿采用后仅目标字段改变；
- 锁定版采用后创建下一草稿，原锁定版、集数、其他字段及全集剧情概览不变；
- 无编辑权限返回 `403`；
- 来源内容变化或存在更新版本时返回 `409`。

### 10.2 前端

- 六个字段均有 AI 重写入口；
- 生成期间显示加载状态并阻止重复请求；
- 原文与新稿同时预览，提示词可修改后重新生成；
- 取消不修改内容，采用后立即保存；
- 锁定版采用后切换到新草稿；
- 请求失败不丢失原文和提示词；
- 弹窗关闭后的迟到响应不污染页面状态。

## 11. 验收标准

- 每次模型调用仅生成用户选中的一个字段；
- 模型输出不会自动覆盖原文；
- 用户确认采用后仅目标字段发生变化；
- 锁定版通过新草稿承载修改，原锁定版不变；
- 不引入 Job、轮询、数据库迁移或候选历史；
- 权限、版本冲突和模型失败均不会造成部分保存或内容丢失。
