# 编剧大师动作重试链折叠设计

## 背景

编剧大师会把每次动作和重试分别保存为独立审计记录。页面当前直接渲染会话返回的全部动作，因此原动作失败、后续重试成功时，会同时出现失败卡、成功卡以及已经失效的“重试”入口。

本次只修正展示与交互，不删除或改写审计记录，不改变动作执行、重试和幂等语义。

## 目标

- 同一 `root_action_id` 只显示一张当前结果卡片。
- 当前结果取该重试链中最新创建的动作；后续轮询更新状态时仍保持一张卡片。
- 旧动作收进默认折叠的“查看执行历史（N）”。
- 只允许当前动作提供确认、取消或重试操作，历史项永远只读。
- 后续动作成功后，旧失败动作不再单独显示，也不再提供“重试”。
- 不含重试历史的单动作展示保持不变。

## 方案

采用前端折叠方案。后端继续通过会话接口返回完整动作列表，前端在渲染前按照动作的 `root_action_id` 分组；缺失该字段时以动作自身 `id` 作为分组键，以兼容旧数据。

每组保留服务端列表中的最后一条动作作为当前动作。服务端当前按 `created_at` 升序返回动作，前端仍使用 `created_at`、`updated_at` 和原数组位置做稳定排序，避免异常顺序造成旧动作覆盖最新动作。

不采用以下方案：

- 后端返回折叠结果：会改变现有会话接口合同，并让审计详情与当前状态耦合。
- 修改旧动作状态为 `superseded`：会改写持久化语义，影响审计、恢复和幂等判断。

## 页面结构与交互

当前动作继续沿用现有 `.writer-action-card` 外观、状态色、进度、成果链接和操作按钮。

当组内存在旧动作时，在当前卡片底部追加原生 `<details>`：

- `<summary>` 显示“查看执行历史（N）”，其中 N 为旧动作数量。
- 默认收起，用户点击或使用键盘可展开。
- 历史项按时间倒序展示标题、状态、完成步骤数和时间。
- 历史项不渲染确认、取消、重试或成果操作按钮。
- 历史区域沿用当前卡片的边框和文本色，不新增模态框、抽屉或固定尺寸。

移动端仍随动作卡片自然换行；历史项不使用横向表格，避免窄屏滚动。

## 状态规则

- 单动作：直接展示该动作，行为不变。
- 失败后重试排队或运行：展示重试动作；旧失败动作进入历史且无“重试”。
- 失败后重试成功：展示成功动作；整条链不出现“重试”。
- 最新重试失败：展示最新失败动作，并且仅当它自身 `retryable` 时显示一个“重试”。
- 多次重试：只展示最后一次动作，其余全部进入同一个历史折叠区。
- 轮询：只为当前动作启动轮询；状态更新后重新分组和渲染。

## 数据与安全边界

- 不修改 `writer_agent_actions`、`retry_of_action_id` 或 `root_action_id`。
- 不删除失败记录，也不更改后端返回范围。
- 历史项仅使用服务端已公开的动作视图字段。
- 现有本地 URL 校验、权限检查和重试接口保持不变。

## 验收与测试

浏览器行为测试覆盖：

1. 原动作失败、重试成功时，只出现一张顶层动作卡和零个“重试”按钮。
2. “查看执行历史（1）”可展开，旧失败状态在历史中可见但不可操作。
3. 多次重试时仍只有一张顶层卡，历史数量正确。
4. 最新动作失败且可重试时，只出现一个“重试”按钮。
5. 单动作无重试时不显示历史折叠区，现有确认、取消、轮询和成果链接不回归。

验证范围包括 `tests/test_writer_agent_browser.py`、Writer Agent API 回归和相关 WebGUI 页面测试，并在 8899 发布后用项目 11 的现有重试链做只读页面冒烟检查。
