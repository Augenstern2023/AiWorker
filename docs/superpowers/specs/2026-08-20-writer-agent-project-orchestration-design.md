# 编剧大师对话式项目创作与编排设计

## 1. 背景

当前平台已经具备原创项目、原创方向、Brief、人物关系、全剧大纲、单集 Beats、场次剧本、版本锁定和异步生成能力，但这些能力主要分布在策划项目页和编剧项目页。

“编剧大师”目前是独立诊断工作台：会话只保存材料、消息和评审报告，不关联创作项目，也不能把对话结论安全地写入项目工作流。策划和编剧除了仿写，还需要从灵感、完整故事构想或已有文本开始原创，并希望直接通过对话创建或关联项目，继续生成大纲、Beats 和剧本。

本设计在保留现有评审能力的基础上，把编剧大师扩展为对话式创作入口。模型负责理解、发散和生成结构化成果；所有项目写操作由后端白名单动作和专用编排服务在用户确认后执行。

本规格补充并修订《原创创作工作流设计》中的后续入口与创建者权限。发生冲突时，以本规格的对话编排和 `project_creator` 权限规则为准。

## 2. 目标与成功标准

### 2.1 目标

- 支持从一句话灵感或题材开始，AI 一次生成 3–5 个差异明显的原创方向。
- 支持策划已有完整故事构想时，直接形成原创 Brief，不强制经过方向发散。
- 支持上传小说、故事梗概、旧剧本等材料后继续创作。
- 支持创建新原创项目，或关联当前登录账户有权访问的已有项目。
- 支持用户直接指定目标成果，包括 Brief、人物、大纲、单集或集数范围 Beats、单集或集数范围剧本。
- 支持目标阶段驱动：用户不需要手工逐页走完依赖，编排服务在明确展示计划后补齐创作基线。
- 确保项目权威版本、权限、任务归属、锁定和版本规则不被对话入口绕过。

### 2.2 成功标准

- 策划或编剧可以在编剧大师中完成“灵感 → 方向 → Brief → 项目”的闭环。
- 用户可以说“创建一个 20 集项目并生成全剧大纲”或“为当前项目生成第 1–5 集剧本”，确认计划后得到项目内正式草稿版本。
- 对话生成的项目和成果能在现有策划、编剧项目页面继续编辑。
- 按钮确认和自然语言确认走完全相同的权限、幂等、执行和审计路径。
- 页面刷新、任务失败和网络重试不会重复创建项目或成果版本。
- 创建者拥有本项目全流程创作权限，但不能删除、归档或分配成员。

## 3. 非目标与首版边界

- 不重写现有创作状态机、生成 Worker 或任务系统。
- 不让模型直接调用任意 URL、SQL、仓储方法或管理接口。
- 不做实时多人协同编辑。
- 不做跨项目成果合并。
- 不允许 AI 删除、归档项目或分配项目人员与任务。
- 不因部分失败自动删除已创建的项目或已经生成的版本。
- “可选参考”只使用用户明确选择且有权读取的现有素材；首版不自动扩展为外部网络调研。
- 一个编剧大师会话同一时刻只有一个当前项目；切换项目必须通过明确的关联动作确认。
- 上传继续复用现有 TXT、Markdown、Fountain、RST、DOCX 和可提取文本的 PDF 能力；首版不增加扫描 PDF OCR。

## 4. 产品原则

### 4.1 成果先可见，写入前确认

对话可以生成方向卡、Brief 卡、创作计划卡和成果卡，但模型输出本身不具有写权限。所有项目变更必须先形成持久化动作卡，再由用户确认。

### 4.2 项目成果是权威来源

已锁定的 Brief、人物、大纲、Beats 和剧本是项目权威版本。对话、上传文件和可选参考只是补充材料，不能静默覆盖权威版本。

### 4.3 锁定成果只创建新版本

已锁定成果需要调整时，必须从现有权威版本创建新草稿。若新版本将替换项目活动指针，动作卡必须展示影响；确认前不执行切换。

### 4.4 直接面向目标阶段

用户不必按页面顺序操作。编排服务根据目标阶段生成“创作计划与基线包”，明确列出将复用、生成和锁定的依赖。用户一次确认后，系统按依赖顺序执行。

### 4.5 轻量复用现有能力

首版只增加对话动作账本、项目绑定、材料快照和薄编排层。底层继续复用原创项目服务、创作应用服务、工作流任务和现有 JobManager，不新建一套通用工作流引擎。

## 5. 用户入口与创作模式

### 5.1 页面入口

原创项目入口同时存在于：

- `/planning/projects`：策划项目页。
- `/writing/projects`：编剧项目页。
- `/review/writer-agent`：编剧大师对话工作台。

三个入口使用相同的原创项目契约和权限规则。页面入口保留表单式创建；编剧大师提供对话式创建与后续生成。

### 5.2 对话起点

编剧大师识别四类起点：

1. **一句话灵感或题材**：默认生成 3–5 个原创方向，用户选定后完善 Brief。
2. **较完整的故事构想**：直接整理并补齐原创 Brief，缺失字段由 AI 给出明确假设。
3. **已有小说、故事梗概或旧剧本**：解析全部已上传材料，用户可指定继续到 Brief、大纲、Beats 或剧本。
4. **已有项目**：关联有权访问的项目，从项目当前权威成果继续创作。

### 5.3 创建前最低信息

创建项目之前，动作卡必须形成以下信息：

- 项目名
- 一句话故事或故事核心
- 类型
- 目标平台
- 目标受众
- 集数
- 单集时长
- 成本等级
- 内容边界
- AI 假设

用户没有提供的字段可由 AI 推荐默认值，但必须标记为假设并允许在确认前修改。

### 5.4 原创方向

灵感模式每次生成 3–5 个方向。候选至少应在主角身份、故事背景、冲突发动机、人物关系或情绪回报中的两个维度有显著差异。

用户可以：

- 选择一个方向。
- 保留部分候选并补足其余方向。
- 从某个方向派生变体。
- 修改约束后重新生成。
- 跳过方向比较，直接整理 Brief。

### 5.5 可选参考

可选参考不是创建项目的前置条件。参考只能来自当前账户有权读取的资源，并在卡片中显示名称、类型和版本。参考提供题材、受众、节奏、情绪价值、成本等抽象信号，不自动成为改编来源。

## 6. 目标阶段驱动的创作计划

### 6.1 阶段依赖

正式项目数据继续遵循：

```text
项目
  → Brief
  → 人物关系
  → 全剧大纲
  → 单集 Beats
  → 单集场次剧本
```

Brief、人物和全剧大纲默认整体生成；Beats 和剧本默认按单集或用户指定集数范围生成。用户明确选择全剧时，由后台分批执行。

### 6.2 自动补齐基线

目标为后续阶段时，编排服务按以下规则处理依赖：

1. 优先复用与当前活动指针兼容的已锁定成果。
2. 缺少依赖时，在计划卡中列出需要生成并锁定的前置成果。
3. 用户确认计划后，按顺序创建前置新版本并完成计划中明确列出的锁定动作。
4. 已有权威版本不会因为上传材料或对话建议被隐式替换。
5. 用户明确要求重做某个已锁定依赖时，创建新版本并提示下游成果将变为历史版本。

### 6.3 示例

“创建一个 20 集都市悬疑项目并生成全剧大纲”形成一张计划卡：

```text
创建原创项目
→ 整理并锁定 Brief 基线
→ 生成人物关系并锁定
→ 生成 20 集全剧大纲草稿
```

“为已有项目生成第 1–5 集剧本”形成一张计划卡：

```text
关联项目
→ 复用已锁定 Brief / 人物 / 大纲
→ 补齐并锁定第 1–5 集当前 Beats（如缺失）
→ 生成第 1–5 集场次剧本新版本
```

## 7. 对话与界面设计

### 7.1 编剧大师定位

移除“独立诊断工作台，不关联创作项目或工作流”的限制性提示。编剧大师同时支持：

- 创作讨论与评审。
- 创建原创项目。
- 关联已有项目。
- 生成并写入项目阶段成果。

现有评审报告、材料上传、会话历史和导出能力保持兼容。

### 7.2 项目上下文栏

会话顶部显示当前项目状态：

- 未关联项目：显示“创建原创项目”和“关联已有项目”。
- 已关联项目：显示项目名、创作模式、当前阶段和“打开项目”。
- 切换项目：先生成 `project.link` 动作卡，确认后切换。

项目候选只展示当前账户可读的项目。后端在确认时再次校验，不能信任前端候选列表。

### 7.3 卡片类型

- **方向卡**：3–5 个候选方向及差异标签。
- **Brief 卡**：结构化 Brief、AI 补充项和假设。
- **创作计划卡**：目标阶段、集数范围、依赖、版本切换和实际写入影响。
- **进度卡**：阶段、批次、单集状态、失败项和重试入口。
- **成果卡**：生成版本摘要、上游版本、打开项目和锁定/继续创作操作。
- **冲突卡**：展示项目状态变化、旧预期和重新规划入口。

卡片内容必须使用安全文本渲染，不把模型输出直接拼入 `innerHTML`。

### 7.4 确认方式

按钮确认和自然语言确认必须转换为同一个内部 `ActionCommand`。

自然语言仅在以下条件下直接确认：

- 当前会话存在唯一匹配的待确认动作。
- 动作仍为最新 revision。
- 用户没有同时增加会改变动作的新约束。

“采用这个版本”“按此创建”“开始生成”等可精确匹配动作。“继续”只有在当前存在唯一待确认卡片时才视为确认。存在多张卡片、指代不明或附带新要求时，系统更新卡片或提问，不执行旧动作。

## 8. 架构与组件边界

```text
编剧大师页面
  → Writer Agent API
      → 对话意图与结构化卡片生成
      → WriterActionStore
      → WriterProjectOrchestrator
          → PermissionService / WorkflowRepository
          → OriginalProjectService
          → CreativeApplicationService
          → JobManager
      → 项目与任务页面
```

### 8.1 对话意图与卡片生成

负责把模型结果规范化为：

- 助手回复。
- 结构化创作内容。
- 白名单动作建议。
- 缺失信息和待确认假设。

模型只能输出候选动作数据。服务端必须执行 schema、项目归属、资源类型、集数范围和引用权限校验后，才能持久化动作。

### 8.2 WriterActionStore

负责会话项目绑定、动作、材料快照、执行步骤、幂等结果和错误状态。它不保存项目权威内容的副本；权威内容始终从创作库读取。

### 8.3 WriterProjectOrchestrator

是唯一写执行入口，职责包括：

- 校验会话、动作、项目和权限。
- 解析目标阶段依赖。
- 获取或续建对应工作流任务。
- 调用共享创作应用服务。
- 记录动作步骤与现有 Job ID。
- 对账部分完成状态。
- 生成进度、成果或冲突卡。

编排器不能在服务端自调用 HTTP，也不能复制 creative API 中的权限与阶段判断。creative API 和编排器应共同调用可注入的应用服务。

### 8.4 CreativeApplicationService

从现有路由中抽取窄职责应用方法，统一处理：

- 创建原创项目。
- 直接创建原创项目的首个 Brief 草稿，不要求先调用方向生成接口。
- 确保阶段任务。
- 启动阶段生成。
- 持久化结构化成果为新版本。
- 锁定或选择版本。
- 读取统一 `ResourceRef`。

不同阶段的原始 ID 规则不一致，应用服务统一返回：

```json
{
  "resource_type": "outline",
  "resource_id": "123:outlines-v2",
  "project_id": 123,
  "version": 2,
  "status": "draft",
  "parent_version_id": null,
  "batch_id": "outlines-v2",
  "episode_number": null
}
```

## 9. 数据模型

### 9.1 writer_agent_sessions

在现有会话表增加：

- `project_id INTEGER NULL`：当前关联项目。
- `context_revision INTEGER NOT NULL DEFAULT 0`：材料或项目绑定变化时递增。

历史会话保持 `project_id=NULL`，不重写旧消息或报告。

### 9.2 writer_agent_actions

新增动作表：

| 字段 | 含义 |
| --- | --- |
| `id` | 稳定动作 ID |
| `session_id` | 所属会话 |
| `actor_user_id` | 发起账户 |
| `action_type` | 白名单动作类型 |
| `status` | `pending/queued/running/succeeded/failed/cancelled/expired` |
| `phase` | 当前阶段或执行步骤 |
| `revision` | 卡片修订版本 |
| `project_id` | 目标项目，可空 |
| `target_key` | 服务端计算的冲突范围 |
| `idempotency_key` | 用户动作幂等键 |
| `request_hash` | 规范化动作摘要 |
| `source_snapshot_id` | 材料和项目上下文快照 |
| `expected_context_json` | 预期项目 revision 与上游版本引用 |
| `payload_json` | 校验后的白名单参数 |
| `result_json` | 项目、资源和任务引用 |
| `error_code/message` | 稳定错误信息 |
| `retryable` | 是否允许重试 |
| `job_id` | 现有异步任务 ID，可空 |
| 时间字段 | 创建、开始、结束和过期时间 |

唯一约束为 `(actor_user_id, idempotency_key)`。同 key、同请求摘要返回原动作；同 key、不同摘要返回 `IDEMPOTENCY_KEY_REUSED`。

`pending` 和 `expired` 属于确认前的卡片生命周期；进入执行后，对外执行状态保持 `queued/running/succeeded/failed/cancelled`，具体等待、冲突和部分失败通过 `phase`、`partial` 和结构化错误表达。

### 9.3 writer_agent_action_steps

长链路按步骤持久化：

- `action_id`
- `step_key`
- `stage`
- `episode_start/episode_end`
- `status`
- `operation_id`
- `job_id`
- `resource_refs_json`
- `error_code/message`
- `attempt`

唯一约束为 `(action_id, step_key)`。重试只执行失败或尚未开始的步骤。

### 9.4 writer_agent_source_snapshots

材料快照保存：

- 全部会话材料的名称、顺序、内容指纹和不可变内容引用。
- 用户明确选中的消息范围。
- 当前项目权威 Brief、人物、大纲、Beats 的资源 ID、版本和指纹。
- 可选参考的资源 ID、版本和权限校验结果。
- AI 假设。
- 模型与提示模板版本。

材料优先级固定为：

```text
项目已锁定成果（权威）
> 用户明确选中的对话和全部上传材料
> 可选参考
> AI 明示的假设
```

### 9.5 项目并发版本

`creative_projects` 增加 `revision INTEGER NOT NULL DEFAULT 0`。项目创作参数、状态或活动 Brief/人物/大纲指针变化时递增。动作确认和阶段切换必须使用预期 revision 做乐观并发校验；单集 Beats 与剧本继续同时比较资源 ID、版本和内容指纹。

### 9.6 创作操作幂等

除已有原创项目 `creation_request_id` 外，各阶段创建版本也必须接受稳定 `operation_id`。创作库在创建资源的同一事务中保存 `operation_id → ResourceRef`，重复调用返回已有结果，避免跨存储故障后生成重复版本。

## 10. 权限模型

### 10.1 身份分离

- 项目内身份：`project_creator`，界面名称“项目创建负责人”。
- 平台全局角色：`project_owner`，界面名称“项目负责人（平台角色）”。

两者不能复用同一内部角色码。

### 10.2 权限矩阵

| 身份 | 查看 | 全阶段创作 | 创建版本/确认/锁定 | 分配成员或任务 | 删除/归档 | 范围 |
| --- | --- | --- | --- | --- | --- | --- |
| 项目创建负责人 | 是 | 是 | 是 | 否 | 否 | 自己创建的项目 |
| 策划/编剧项目成员 | 是 | 按既有阶段规则 | 按任务规则 | 否 | 否 | 参与项目 |
| 项目负责人（平台角色） | 是 | 是 | 是 | 是 | 是 | 策划/编剧创建的项目 |
| 系统管理员 | 是 | 是 | 是 | 是 | 是 | 全部项目 |

### 10.3 创建规则

- 任意入口创建项目时，以当前登录账户写入不可变审计字段 `created_by`。
- 同时幂等创建 active `project_creator` 项目成员关系。
- 不给创建账户追加全局 `project_owner` 角色。
- 创建者权限来自 active `project_creator` 关系，不把项目级能力写入全局 `Principal.permissions`。
- 创建者不能自助移除该关系；平台项目负责人或系统管理员可以停用其项目成员关系。停用后创作权限立即失效，`created_by` 审计事实保留。

### 10.4 治理规则

- 删除要求独立的 `project.delete` 权限，授予平台项目负责人和系统管理员。
- 归档要求 `project.archive`。
- 成员增删和创建时分配人员要求 `project.member.manage`。
- 没有成员管理权限的创建者提交非空策划或编剧成员列表时返回 403。
- 项目编辑、阶段生成和锁定集中使用项目级判断，不能继续用 `created_by` 推导删除或成员管理权限。

### 10.5 数据迁移

仅迁移满足以下条件的旧项目成员关系：

```text
project_members.user_id == creative_projects.created_by
AND project_members.project_role == "project_owner"
```

迁移为 `project_creator`。迁移可重复执行，不改变用户的全局角色，不修改其他项目负责人或普通成员关系。

## 11. 动作契约与 API

### 11.1 白名单动作

- `project.create_original`
- `project.link`
- `creative.run_plan`
- `creative.lock`

`creative.run_plan` 使用 `target_stage=brief|characters|outline|beats|script` 和集数范围表达目标，避免为每个阶段复制对话协议。

动作参数至少包含项目模式或项目 ID、目标阶段、集数范围、创作指令、前置成果策略、材料快照 ID 和预期上下文。现有阶段生成接口没有创作指令字段；共享应用服务和 Worker 必须显式接收经过校验的 `generation_instruction`，不能丢弃对话中已经确认的修改要求。

### 11.2 消息接口

保留：

```http
POST /api/writer-agent/sessions/{session_id}/messages
```

响应继续包含完整会话，并为助手消息增加兼容字段：

```json
{
  "message_id": "msg-...",
  "role": "assistant",
  "content": "我已整理创作计划。",
  "action_ids": ["act-..."]
}
```

动作单独存表，不嵌入 `messages_json`。旧客户端忽略新增字段后仍可读取纯文本消息。

### 11.3 动作确认

新增：

```http
POST /api/writer-agent/sessions/{session_id}/actions/{action_id}/decision
```

请求：

```json
{
  "decision": "confirm",
  "expected_revision": 3,
  "client_request_id": "uuid"
}
```

`decision` 首版支持 `confirm` 和 `cancel`。异步执行返回 `202` 及动作状态；同步关联或取消可以返回 `200`。

### 11.4 动作读取

`GET /api/writer-agent/sessions/{session_id}` 返回会话当前动作卡。轮询可以使用：

```http
GET /api/writer-agent/sessions/{session_id}/actions/{action_id}
```

底层 Job 仍使用现有 `/api/jobs/{job_id}`；前端只依赖动作状态，由编排器负责对账 Job 状态。

### 11.5 项目候选

关联候选复用：

```http
GET /api/creative/projects
```

如平台项目负责人或管理员需要管理范围候选，继续由现有项目读取权限过滤，不新增绕过权限的搜索接口。

### 11.6 执行入口

按钮和自然语言最终调用同一个内部命令：

```text
ActionCommand(
  session_id,
  action_id,
  decision,
  actor,
  expected_revision,
  client_request_id
)
```

执行器依次：

1. 校验会话和动作属于当前账户；系统管理员读取会话的能力不替代项目写权限校验。
2. 校验动作仍为 `pending` 且 revision 一致。
3. 原子更新为 `queued`。
4. 重新校验项目读取、创作、工作流任务和参考权限。
5. 比较预期项目上下文。
6. 执行白名单动作并记录步骤。
7. 写入结果消息与审计记录。

## 12. 异步执行与恢复

### 12.1 执行步骤

```text
校验权限与版本
→ 创建或关联项目
→ 固化材料快照
→ 确保阶段任务
→ 复用或生成并锁定计划中的基线
→ 按阶段与集数分批生成目标成果
→ 保存 ResourceRef
→ 返回成果卡
```

### 12.2 批处理

- Brief、人物、全剧大纲整体执行。
- Beats 和剧本按单集保存。
- 全剧 Beats 和剧本默认每 10 集一批。
- 对话输入在任务排队后恢复可用，不使用全局 `isBusy` 阻塞整个会话。

### 12.3 部分失败

- 已成功的项目、基线和单集版本全部保留。
- 动作标记 `failed`，`phase` 和步骤记录指出失败范围；存在部分成果时结果中标记 `partial=true`。
- “仅重试失败项”创建重试动作并引用原动作，只执行失败或未开始步骤。
- 重试前重新校验权限和上游版本；上游变化时禁止沿用旧快照。
- 取消只停止尚未开始或底层允许停止的 Job，不删除已完成版本。

### 12.4 并发冲突

服务端计算 `target_key`，不接受模型提供的权限或冲突范围。典型范围包括：

- `project:{id}:brief`
- `project:{id}:characters`
- `project:{id}:outline`
- `project:{id}:beats:episode:{n}`
- `project:{id}:script:episode:{n}`
- `project:{id}:governance`

全剧动作与覆盖范围内全部单集动作互斥。发现活动冲突时不启动第二个任务，返回冲突动作 ID。

### 12.5 上下文过期

动作确认和每个阶段开始前比较：

- 会话 `context_revision`
- 项目状态与 revision
- `locked_brief_id`
- `character_batch_id`
- `outline_batch_id`
- 对应单集 Beats ID、版本和指纹
- active 项目成员关系
- 工作流任务归属和状态

任何关键项变化时，动作进入不可重试的冲突结果，不写入旧上下文，并生成新的计划卡。

## 13. 错误处理

稳定错误码至少包括：

- `ACTION_NOT_PENDING`
- `ACTION_REVISION_MISMATCH`
- `IDEMPOTENCY_KEY_REUSED`
- `PROJECT_ACCESS_DENIED`
- `PROJECT_NOT_AVAILABLE`
- `REFERENCE_UNAVAILABLE`
- `TASK_ASSIGNED_TO_OTHER`
- `ACTIVE_ACTION_CONFLICT`
- `STALE_PROJECT_CONTEXT`
- `UPSTREAM_REQUIRED`
- `GENERATION_FAILED`
- `RESULT_VALIDATION_FAILED`

错误响应包含：

```json
{
  "code": "ACTIVE_ACTION_CONFLICT",
  "message": "该项目正在生成全剧 Beats",
  "retryable": true,
  "conflicting_action_id": "act-...",
  "current_revision": 12
}
```

权限失败不降级为只读写入或后台服务身份执行。参考失效时停止相关动作并要求用户移除或更换参考，不静默扩大数据访问。

## 14. 审计与安全

每个确认动作记录：

- 登录账户和会话。
- 动作类型、revision 和幂等键。
- 项目和目标阶段。
- 材料快照与可选参考 ID。
- 权限判定和工作流任务。
- 创建、锁定或选择的资源版本。
- Job、步骤、失败和重试关系。

审计记录不保存密钥、Cookie 或模型服务凭据。上传材料继续按会话所有者隔离；管理员能读取会话不代表普通账户可以读取关联项目，项目权限每次独立校验。

## 15. 测试与验收

### 15.1 单元测试

- 对话意图结构化和动作白名单。
- 3–5 个方向的数量、差异和必填字段。
- 自然语言确认的唯一动作匹配。
- 材料优先级、全部附件快照和指纹。
- `project_creator`、平台 `project_owner` 和系统管理员权限矩阵。
- 动作、步骤和创作版本幂等。
- 项目与上游版本比较。

### 15.2 API 与集成测试

- 灵感创建、直接 Brief、文档导入和关联已有项目。
- 按钮与自然语言确认产生相同 `ActionCommand`。
- 创建者自动成为 `project_creator`，重复请求不重复创建成员。
- 直接生成全剧大纲时正确补齐 Brief 和人物基线。
- 直接生成第 1–5 集剧本时正确复用或补齐 Beats。
- 已锁定成果调整只产生新版本。
- 页面刷新后动作和 Job 状态恢复。
- 部分失败只重试失败集数。
- 上游变化、任务被他人领取、参考失效和并发动作返回稳定冲突。
- 旧会话、旧评审报告和仿写项目无回归。

### 15.3 权限测试

- 三个创建入口均写入当前登录账户为 `project_creator`。
- 只有 `project.create` 的账户创建项目后可完成 Brief 到剧本全流程创作和锁定。
- 创建负责人删除、归档、创建时分配成员、后续成员增删和任务分配均返回 403。
- 平台项目负责人无需成为项目成员即可管理策划或编剧创建的项目。
- 系统管理员可管理全部项目。
- 无权用户不能搜索、关联、读取或通过伪造动作 ID 操作项目。
- 停用 `project_creator` 成员关系后立即失去项目创作权限。
- 迁移不改变任何全局角色。

### 15.4 浏览器测试

- 编剧大师显示项目上下文、方向卡、计划卡、进度卡、成果卡和冲突卡。
- 用户可以从成功成果卡打开正确的策划或编剧项目阶段页面。
- 编剧大师原评审、上传和导出流程继续可用。
- 策划项目页和编剧项目页都保留原创创建入口。
- 长任务期间输入框仍可继续对话，单个动作卡独立显示忙碌状态。

### 15.5 业务验收场景

1. 一句话灵感生成 3–5 个方向，选定后完善 Brief 并创建项目。
2. 完整故事构想直接创建原创 Brief。
3. 导入小说、故事梗概或旧剧本后创建项目并继续创作。
4. 关联已有项目并生成目标阶段。
5. 创建项目并直接生成 20 集全剧大纲。
6. 为已有项目生成第 1–5 集剧本。
7. 全剧生成部分失败后，仅重试失败集且不产生重复版本。
8. 上游版本改变后，旧动作被阻止。
9. 已锁定成果不会被静默覆盖。
10. 创建者可全阶段创作但无法进行项目治理。

## 16. 实施顺序与兼容策略

1. 拆分 `project_creator` 与平台 `project_owner`，修正删除、归档和成员分配权限并迁移旧数据。
2. 抽取可由 creative API 与编排器共享的创作应用服务，补齐阶段 `operation_id` 幂等。
3. 扩展 WriterAgentStore，增加项目绑定、动作、步骤和材料快照。
4. 增加动作 schema、自然语言确认解析和 WriterProjectOrchestrator。
5. 扩展编剧大师页面的项目上下文和动作卡。
6. 接入现有 JobManager、状态对账和失败重试。
7. 完成自动化测试和浏览器验收，确认现有评审与仿写流程无回归。

所有新增字段使用可空值或安全默认值；旧会话不迁移历史消息结构。项目页面和现有 creative API 保持兼容，逐步改为调用共享应用服务，避免一次性重写。

## 17. 已确认决策摘要

- 采用“成果卡片 + 专用编排服务”。
- 支持创建新原创项目与关联已有项目。
- 灵感入口一次生成 3–5 个方向，选定后完善 Brief。
- 支持直接 Brief 和导入已有材料。
- 市场及项目参考为可选项。
- 采用轻量首版，复用现有创作与任务系统。
- 用户可直接面向大纲、Beats 或剧本，不局限于方向和 Brief。
- 采用“目标阶段驱动 + 自动补齐创作基线”。
- 项目锁定成果为权威版本，调整只能创建新版本。
- 按钮和自然语言确认统一执行。
- 谁创建项目，谁自动成为项目创建负责人并拥有全阶段创作权限。
- 项目创建负责人没有删除、归档、成员分配和任务分配权限。
- 平台项目负责人和系统管理员可以管理策划或编剧创建的项目。
