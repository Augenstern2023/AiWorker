# WebGUI 登录自启动设计

## 目标

让 AiWorker WebGUI 在当前 Windows 用户登录后自动、静默启动。服务仅监听本机
`127.0.0.1:8899`，不弹出终端窗口，也不自动打开浏览器；用户需要时直接访问
`http://127.0.0.1:8899`。

## 方案

使用 Windows 任务计划程序创建当前用户级任务 `AiWorker WebGUI`。任务在用户登录
15 秒后启动项目内的 PowerShell 启动脚本，使用
`D:\Crawler\AiWorker\.venv\Scripts\python.exe` 运行 Uvicorn，并将工作目录固定为项目根目录。

不直接执行 `WebGUI.py` 的 `__main__` 入口，避免它在每次登录时调用浏览器。WebGUI
应用本身仍由 `WebGUI:app` 提供，手动执行现有批处理文件的行为不受影响。

## 组件

- `scripts/start_webgui_background.ps1`：校验虚拟环境和端口，前台托管 Uvicorn
  子进程并把输出追加到 `logs/webgui-autostart.log`。脚本由任务计划程序隐藏运行，
  因此前台托管不会产生可见窗口，同时任务计划程序能够追踪进程退出。
- `scripts/install_webgui_autostart.ps1`：以当前用户身份注册或更新计划任务，配置
  登录延迟、禁止重复实例、异常退出重试和隐藏窗口。
- `scripts/uninstall_webgui_autostart.ps1`：移除计划任务，不删除应用数据、日志或
  项目文件。

## 启动与异常处理

启动脚本先确认项目虚拟环境中的 Python 存在，再检查 `8899` 端口。端口已经监听时，
脚本记录信息并成功退出，避免重复启动；虚拟环境缺失或端口被非预期程序占用时，
错误写入日志并返回非零退出码。任务异常退出后最多重试 3 次，每次间隔 1 分钟。

日志目录不存在时由启动脚本创建。日志使用追加写入，保留登录启动和异常退出的诊断
信息，但不记录环境变量或凭据。

## 验证

- 安装后确认计划任务存在、触发器为当前用户登录且状态可运行。
- 手动触发任务，确认没有可见终端或自动打开的浏览器窗口。
- 请求 `http://127.0.0.1:8899`，确认 WebGUI 返回成功响应。
- 再次触发任务，确认没有创建第二个监听 `8899` 端口的进程。
- 运行卸载脚本后确认计划任务已移除。
