# 壹凡短剧选品平台 PRD 实施文档

**版本**：V1.0  
**适用阶段**：Phase 3 - Phase 6  
**目标读者**：产品、研发、算法/LLM、数据、内容运营、制作运营  
**关联方案**：[壹凡短剧选品平台改进方案.md](壹凡短剧选品平台改进方案.md)

## 1. 产品定义

壹凡短剧选品平台从榜单采集与分析工具升级为短剧爆款选题与仿制创作中台。产品不直接与通用视频生成工具竞争，而是利用真实榜单、热度变化、评论、分析报告和剧集转写数据，产出可追溯、可编辑、可进入制作的创作方案。

核心闭环：

```text
榜单/剧目数据 -> 爆款识别 -> 结构化拆解 -> 选题评分 -> 仿制方向
-> 创作 brief -> 人物/关系 -> 分集大纲 -> 单集 beats -> 分镜 -> 制作包
-> 外部生成服务预演
```

### 1.1 产品目标

1. 将每日榜单与分析数据转为有证据的候选选题，而非仅展示指标。
2. 让内容运营可以在同一工作流内完成爆款拆解、差异化仿制、剧本策划与分镜交付。
3. 对每个关键生成结果保留来源、版本、人工编辑记录和风险提示。
4. 将视频、配音、剪辑等外部生成能力限定为可替换执行层，避免平台被单一供应商锁定。

### 1.2 非目标

- 首期不直接生成完整长篇/全集剧本。
- 首期不自动发布、投流、剪辑成片或替代人工制作审核。
- 不将来源剧目的角色、台词、剧情表达直接复制为新作品。
- 不承诺获取红果官方评论、评分或未获授权数据。

### 1.3 用户与权限

| 角色 | 核心诉求 | 主要权限 |
| --- | --- | --- |
| 内容运营 | 发现值得跟进的趋势和选题 | 查看榜单、创建/维护选题、生成拆解 |
| 编剧/策划 | 将选题推进为可写可拍方案 | 编辑并锁定 brief、人物、大纲、剧本、分镜 |
| 制作运营 | 获得可执行的拍摄或 AI 预演资料 | 查看已锁定版本、导出制作包 |
| 数据运营 | 校验数据质量与评分逻辑 | 查看来源、指标、异常和评分明细 |
| 管理员 | 管理配置、模型、导出与权限 | 全部权限；维护外部服务凭证 |

首期采用现有本地单用户模式时，上述权限以功能边界记录；多用户部署前不得假定已有鉴权能力。

## 2. 数据与可追溯性

### 2.1 已有数据底座

| 数据源 | 当前能力 | 在创意链路中的用途 |
| --- | --- | --- |
| `TodayRankService` | dy/hg 当期榜单、历史快照、排名变化 | 趋势发现、热度与增长评分 |
| `DramaRepository` / 分析看板 | 剧目指标、题材、卖点、评论和转写统计 | 题材分布、评分特征、候选筛选 |
| 分析报告 | dy/hg 的 Markdown/JSON 分析产物 | 爆款拆解和仿制依据 |
| 评论与 RAG API | 评论、分析报告、转写等检索证据 | 评论共鸣点、引用片段、质量校验 |
| 红果剧目分析 | 视频、音频、字幕/ASR 转写、`script.md` | 前几集钩子、冲突、台词和场景拆解 |

### 2.2 证据规则

每一条爆款拆解、选题评分、仿制方向和生成文档必须记录：来源平台、`job_id`、源文件路径、快照时间、剧目标题、可用指标、引用片段和生成模型/提示模板版本。

当数据缺失时使用以下降级规则：

| 缺失项 | 降级行为 | 页面提示 |
| --- | --- | --- |
| 上一期快照 | 增长分不计入总分并重新归一化 | “无可比历史数据” |
| 评论正文 | 评论共鸣分为未知，不以评论数替代情绪结论 | “仅有评论量指标” |
| ASR/字幕 | 不生成具体钩子或台词结论 | “未获得剧集转写” |
| 点赞/收藏等平台字段 | 使用可用热度字段，标记评分置信度降低 | “部分热度字段缺失” |
| LLM 调用失败 | 保留人工可编辑模板和原始证据 | “生成失败，可重试或手工填写” |

## 3. 核心业务流程与状态

### 3.1 主流程

1. 系统按已有任务或人工触发读取最新榜单、分析产物和转写。
2. 内容运营在“今日爆款”查看新上榜、排名上升和热度增长的剧目。
3. 选择剧目后生成或编辑爆款拆解卡，确认来源与风险。
4. 系统计算候选选题评分，运营将候选项采纳为创作项目。
5. 仿制工坊生成 3-5 个差异化方向；用户选择一个并锁定为 brief。
6. 剧本工坊按顺序生成并锁定人物、关系、分集大纲、beats、单集正文。
7. 分镜工坊将锁定的单集版本转为镜头表，导出制作包。
8. Phase 6 的适配器可将已导出的镜头或配音任务发往外部服务；外部结果仍回写为项目资产。

### 3.2 创意项目状态

```text
待评估 -> 已采纳 -> 方向生成中 -> Brief 已锁定 -> 大纲已锁定
-> 单集开发中 -> 分镜已锁定 -> 已导出 -> 已归档
```

状态只能前进；允许回退到前一已锁定节点创建新版本，不覆盖历史版本。`已归档`项目只读，管理员可恢复。

## 4. 功能需求

### 4.1 今日爆款

**目的**：从榜单中筛出“今天值得跟进”的剧目和选题证据。

页面包括日期/平台筛选、增长类型筛选、新上榜/上升剧目列表、Top10 选题建议和来源指标抽屉。每条建议展示标题、平台、当期排名、变化、热度摘要、推荐分、置信度和一句推荐理由。

操作：查看证据、生成拆解卡、加入选题库。无榜单时提示先抓取或导入快照；数据不完整时仍展示但不得显示虚构的增长或评论结论。

### 4.2 爆款拆解卡

**目的**：将一个来源剧目转为后续创作可复用的最小业务单元。

必填/生成字段：剧名、平台、快照、热度/排名、卖点、题材、目标人群、主角身份、阻力来源、核心冲突、前三集钩子、爽点、情绪曲线、反转节点、评论共鸣点、可仿制元素、风险点、制作难度、来源证据。

用户可逐字段编辑、重新生成、保存草稿、锁定版本。锁定后不能原地修改，只能“基于此版本创建新版本”。未获得转写时，“前三集钩子”和“台词型结论”必须标为推断，不得伪装为事实。

### 4.3 选题评分与选题库

**评分口径（0-100）**：

| 分项 | 权重 | 可实施规则 |
| --- | ---: | --- |
| 热度分 | 25 | 榜单排名、热度、点赞、收藏、评论的归一化组合 |
| 增长分 | 20 | 同平台、同榜单与上一期的排名和可用指标变化 |
| 评论共鸣分 | 15 | 已有评论正文的情绪、争议、代入感；无正文则不计入 |
| 新鲜度分 | 10 | 同期相似题材密度、近 30 天趋势和差异化角度 |
| 可仿制分 | 15 | 可保留结构/爽点且能替换人设、背景、关系的程度 |
| 制作成本分 | 10 | 场景、角色、特效、服化道的反向评分 |
| 平台适配分 | 5 | 目标平台节奏、受众和题材匹配度 |

缺失分项从总权重中剔除后重新归一化，并输出 `confidence`（高/中/低）和评分明细。选题库展示状态、来源剧目、题材、推荐分、可仿制分、成本等级和最近版本；支持采纳、归档、筛选和进入仿制工坊。

### 4.4 仿制工坊

输入为一张锁定的拆解卡或已采纳选题，输出 3-5 个方向。每项必须包含借鉴元素、必须差异化元素、新主角、新冲突、新背景、前三集钩子、主要爽点、目标人群、成本、相似度风险、修改建议和优先级。

相似度风险按低/中/高展示；高风险方向不得直接进入 brief 锁定，必须先填写差异化修改说明。系统原则为“借鉴爽点和结构，不复制剧情、人设、台词或具体表达”。

### 4.5 剧本工坊

剧本工坊以项目为单位，按以下顺序开放：选题 brief、世界观、人物小传、关系、分集大纲、单集 beats、单集正文、台词润色、爽点/反转增强。

每个步骤具备：输入来源选择、生成、编辑、版本对比、锁定、基于锁定版本继续生成、Markdown/JSON 导出。只有上一步存在锁定版本时才能生成下一步；用户可手动创建空白版本以支持人工创作。

首期正文范围限制为单集；系统生成前应显示本集时长、冲突、钩子、反转和结尾悬念目标。

### 4.6 人物、关系、情节与场景库

人物卡字段：角色名、年龄段、身份、外在标签、内在欲望、秘密、关系、成长线、台词风格、造型 prompt、声音 prompt。关系模板和情节模板需带适用题材、冲突类型、风险提示和引用项目。

场景卡字段：名称、成本等级、适用题材、承载冲突、常见镜头、道具、人物容量、特效需求和 AI 视频 prompt 模板。库资产可由项目沉淀，但进入公共资产库前需人工标记为可复用。

### 4.7 分镜工坊与制作包

分镜以已锁定的单集正文/beat 版本为输入。镜头字段：集数、场次、镜号、场景、人物、景别、机位、动作、台词、情绪、道具、光线、时长、视频 prompt、配音 prompt、字幕文本。

允许编辑、排序、拆分/合并镜头和锁定版本。制作包导出为 ZIP，至少包含：项目元数据 JSON、剧本 Markdown、人物卡、场景卡、分镜 CSV/JSON/Markdown、prompt 清单、证据清单和版权风险说明。

## 5. 技术实施规格

### 5.1 子系统边界

新增 `creative/` 子系统，不将创意业务继续堆叠在 `WebGUI.py`：

```text
creative/
  schema.py             # Pydantic/数据实体与版本对象
  repository.py         # SQLite 持久化、事务与版本查询
  topic_service.py      # 榜单筛选、评分、Top10
  hit_breakdown.py      # 拆解和证据归集
  imitation_service.py  # 差异化方向与风险校验
  script_service.py     # 分步剧本生成、锁定和版本链
  storyboard_service.py # 镜头表、制作包
  prompt_templates.py   # 版本化提示模板
  api.py                # /api/creative 路由
```

`WebGUI.py` 仅注册创意路由；前端按模块页面调用 API。耗时 LLM、导出和外部服务任务复用现有 JobManager/事件日志机制。

### 5.2 数据模型

数据库路径：`.runtime/creative/creative.db`。所有业务表包含 `id`、`project_id`（适用时）、`version`、`status`、`created_at`、`updated_at`、`created_by`（预留）、`source_refs_json`。

| 表 | 关键内容 |
| --- | --- |
| `creative_topics` | 来源剧目、评分明细、置信度、状态、推荐理由 |
| `creative_breakdowns` | 结构化拆解字段、证据、风险、锁定版本 |
| `creative_blueprints` | 仿制方向、差异化项、相似度风险、brief |
| `creative_characters` | 人物卡、版本和公共资产标识 |
| `creative_relationships` | 人物关系与模板引用 |
| `creative_episodes` | 分集大纲、beats、正文、锁定版本 |
| `creative_scenes` | 场景卡与公共资产标识 |
| `creative_shots` | 镜头表、prompt、排序和锁定版本 |
| `creative_exports` | 导出任务、版本快照、文件路径、状态 |

禁止更新锁定版本的业务正文；新版本以 `parent_version_id` 指向来源版本。删除项目采用软删除，导出快照永久引用其生成时版本。

### 5.3 API 契约

| API | 行为 |
| --- | --- |
| `POST /api/creative/topics/generate` | 根据平台、日期、数量和评分规则生成候选选题 |
| `GET /api/creative/topics` | 分页查询选题库，支持状态/平台/题材筛选 |
| `POST /api/creative/breakdown` | 为来源剧目或选题创建拆解任务/版本 |
| `POST /api/creative/imitation` | 为锁定拆解或选题生成仿制方向 |
| `POST /api/creative/script-outline` | 创建或生成 brief、人物、关系、大纲、beats、单集正文 |
| `POST /api/creative/characters` | 保存/生成/版本化人物与关系 |
| `POST /api/creative/scenes` | 保存/生成/版本化情节、场景资产 |
| `POST /api/creative/storyboard` | 由锁定单集生成或更新分镜 |
| `GET /api/creative/projects/{project_id}` | 返回项目当前版本、来源、状态和可操作节点 |
| `POST /api/creative/exports` | 创建制作包导出任务 |

写接口返回资源版本或标准异步 Job；LLM/ZIP/外部服务操作不得阻塞 HTTP 请求。响应中的证据统一返回 `source_type`、`job_id`、`source_path`、`captured_at`、`excerpt`。

## 6. 阶段交付

### Phase 3：选题与爆款拆解（MVP）

交付今日爆款、爆款拆解卡、评分系统、候选选题 Top10、选题库、来源证据与基础 API。验收：可从任意已有 dy/hg 快照生成 Top10；每项有评分明细、置信度和至少一个来源；缺失字段不生成虚假结论。

不包含仿制方向、剧本正文、镜头表和外部视频服务。

### Phase 4：仿制与剧本大纲

交付仿制工坊、风险提示、brief、人物/关系、分集大纲和单集 beats。验收：运营可从一个锁定拆解生成多个方向，选定方向后依赖锁定版本生成可编辑大纲；高相似度风险不能直接进入后续生成。

不包含完整全集正文、分镜导出和外部生成调用。

### Phase 5：分镜与制作包

交付单集正文、场景/情节库、分镜工坊、版本锁定和 ZIP 制作包。验收：已锁定单集可生成可编辑镜头表；导出包可离线获得所有必要文本、JSON/CSV、prompt 和风险说明。

不包含直接调用视频、配音或剪辑供应商。

### Phase 6：外部生成服务适配

交付外部视频、图像、配音、字幕/剪辑服务的适配层与预演资产回写。适配器统一具备：凭证保存在本地安全配置、任务异步化、状态轮询/回调、失败重试、取消、费用/额度记录和供应商替换能力。

验收：同一分镜任务可使用至少一个适配器执行并将结果关联回镜头；断网、超时、额度不足和供应商返回错误均能保留可诊断日志，且不会影响核心创意数据。

## 7. 质量、测试与验收

### 7.1 必测场景

- 有完整榜单、评论和转写时生成完整拆解与评分。
- 缺少上一期、评论或转写时按降级规则生成并标识置信度。
- 锁定版本后尝试编辑、重新生成、基于旧版本创建新版本。
- 高相似度风险方向被拦截，填写差异化说明后可继续。
- Job 失败、LLM 超时、导出失败和外部服务失败时的状态、日志、重试和数据完整性。
- 制作包的版本一致性、来源清单、路径安全和下载权限。

### 7.2 业务验收指标

| 指标 | Phase 3 目标 | 后续目标 |
| --- | --- | --- |
| Top10 可追溯率 | 100% 有来源快照/文件 | 100% 有字段级证据 |
| 拆解人工可用率 | 运营评审通过率可统计 | 持续优化提示模板 |
| 选题采纳率 | 记录采纳/淘汰原因 | 形成题材与评分反馈闭环 |
| 版本可追溯率 | 锁定版本 100% 可回查 | 导出/外部结果 100% 关联版本 |
| 风险提示覆盖率 | 仿制方向 100% 输出风险项 | 分镜/导出同步附带风险说明 |

## 8. 风险与治理

- **版权与抄袭**：生成结果必须区分事实来源、借鉴结构和新创内容；禁止输出“直接复刻”指令；高风险方向需人工确认。
- **数据合规**：仅使用已合法接入或用户本地拥有的数据；评论、账号和第三方接口遵守对应平台规则。
- **生成幻觉**：所有事实性判断应附来源；无来源时标为创作建议或推断。
- **成本失控**：LLM 与外部服务任务采用限额、队列、超时和重试上限；导出记录模型与服务消耗。
- **可拍性**：每个方向、场景和分镜均需成本、人物、场景和特效评估，不以文本吸引力替代制作判断。

## 9. 实施依赖与决策

1. Phase 3 开始前完成 `creative/` SQLite 初始化、来源引用规范和基础 LLM 提示模板版本管理。
2. 创意模块直接读取已有榜单、分析和 RAG/ASR 产物，不复制现有采集链路。
3. RAG 页面是否显示不影响创意模块使用既有 RAG API 作为证据检索能力。
4. 外部视频/配音服务仅在 Phase 6 接入；其凭证不入库、不写入导出包、不进入日志。
5. 任何“锁定”动作均是业务承诺点，必须在接口层校验版本与状态，不能仅依赖前端禁用按钮。
