# 编剧领取已设立项目创作阶段设计

## 目标

编剧可查看所有已设立项目的大纲、Beats 和场次剧本；当对应阶段无人处理时，可领取阶段任务并生成、编辑、保存和锁定内容。已由其他编剧处理的阶段保持只读。

## 权限边界

- 新增 `project.write.established.writing`，默认授予 `screenwriter`。
- 权限仅覆盖 `outline`、`beats`、`script` 三个阶段的任务领取。
- 不开放 Brief、人物关系、项目设置、项目成员管理、归档或删除权限。
- 数据库迁移只增量插入权限和默认授权，不覆盖后台现有配置；降级不删除管理员配置。

## 任务领取模型

- 编剧可看到所有已设立项目中、角色匹配且处于 `pool` 的写作阶段任务。
- 同一项目同一阶段存在其他人的 `assigned`、`in_progress` 或 `returned` 任务时，其他池任务不可领取，防止多人覆盖。
- 领取成功与写入 `screenwriter` 项目成员关系处于同一数据库事务；并发领取只有一个成功者，失败事务不留下成员记录。
- 领取后沿用现有任务执行人校验，只有任务执行人能修改、生成、保存和锁定该阶段资源。

## 页面与数据流

大纲、Beats、场次剧本页面继续使用现有 `/writing/projects/...` 路由。页面首次执行生成、保存或锁定动作时，现有任务解析器先查找任务：已有本人任务则继续；无人处理且有池任务则自动领取；没有任务则由阶段初始化接口创建下一任务并领取；其他人正在处理则返回只读冲突。

## 验证

- 工作流测试覆盖跨项目池任务可见、领取后成员写入、非写作阶段不可领取、其他编剧正在处理时不可抢占。
- 创作 API 测试覆盖未加入项目的编剧可初始化并领取大纲任务，但人物关系仍为 403，项目设置仍不可修改。
- 迁移测试和生产角色验证确认权限增量生效且不授予 `project.manage`。
