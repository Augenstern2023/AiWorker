# 导航配置与账号页面访问整改方案

> **2026-07-29 设计修订（优先于以下历史设计）**：以角色页面默认值作为普通账号的基础访问范围，并允许系统管理员在账号级别明确允许或拒绝单页。`role_page_access` 存放角色-页面关系；`user_page_access.is_allowed` 为 `true` 表示允许、`false` 表示拒绝、无行表示继承。账号例外覆盖角色并集，页面全局停用覆盖普通账号例外；系统管理员不受上述限制。
>
> 角色权限页提供页面授权操作及 `/api/admin/roles/{role_id}/pages`；角色修改后由实时仓储查询生效。导航配置仅系统管理员可使用，并将原复选框替换为“继承角色默认 / 明确允许 / 明确拒绝”三态选择。

## 调整后的目标

移除角色对页面访问的全部限制。所有已登录账号默认且始终可以访问个人信息页 `/profile`；除此以外的页面不再因角色自动开放，统一由系统管理员或项目负责人按账号进行配置。

页面配置是简单的账号白名单：勾选账号即允许访问该页面及其页面功能；取消勾选即禁止访问。取消“继承角色、允许、禁止”三态，也不再使用 `page.*` 角色权限决定页面是否可访问。

## 最终规则

1. 未登录用户仍只能进入登录页。
2. 已登录用户始终可访问 `/profile` 和自己的 `/api/profile`。
3. 其他所有页面默认拒绝访问，左侧导航中也不显示。
4. 系统管理员或项目负责人在“导航配置”中为账号勾选页面后，该账号可以访问菜单、直接 URL 和该页面绑定的 API。
5. 取消勾选后，页面、直接 URL 和页面绑定 API 立即拒绝，不依赖重新登录。
6. 系统管理员和项目负责人拥有“导航配置”及其配置接口的固定管理权，确保新账号可以被首次授权；系统管理员同时保留全量页面访问权。
7. 项目负责人是全局项目管理角色：可访问和配置全部项目，不受项目成员归属、任务归属或普通账号数据范围限制；包括项目创建、成员配置、流程配置、内容审核及项目相关数据查看。
8. 除项目负责人外，其他账号的项目归属、任务归属和数据范围等业务校验继续保留；页面授权不会越过这些数据范围规则。

## 数据设计

新增 PostgreSQL 表 `user_page_access`：

| 字段 | 说明 |
| --- | --- |
| `user_id` | 外键指向 `users.id`，删除用户时级联删除 |
| `route` | 已注册页面路由，例如 `/selection/ranks` |
| `created_at` | 授权时间 |
| `updated_at` | 最近配置时间 |

主键为 `(user_id, route)`。存在记录代表允许，不存在记录代表禁止；不保存角色继承、允许或禁止状态。仓储层仅接受 `PAGE_ROUTES` 中已注册的静态页面路由，拒绝无效地址。

新增 Alembic 迁移、`system_database.schema` 定义和查询索引。现有角色中的 `page.*` 权限不再参与页面判断；为避免破坏既有角色数据，首版不删除历史权限记录，只停止使用它们进行页面授权。

## 页面与接口授权

建立显式“页面-接口能力目录”。每个受配置页面登记：

- 页面路由，例如 `/admin/users`。
- 该页操作所需的 API 路径和 HTTP 方法，例如用户查询、新建、编辑、停用、重置密码。

页面 HTML 和登记的 API 采用同一账号白名单判断，避免出现“能打开页面但所有操作失败”的空壳页面。例如项目负责人为某账号勾选“用户管理”后，该账号可完整使用用户管理页；取消勾选后，上述页面和接口一并返回 `403`。

不属于任何页面能力目录的敏感接口仍使用现有业务权限及数据范围校验，不能因页面勾选而意外开放。

## 导航配置页面整改

导航配置不再展示原始数据库输入字段：

- 名称显示为文本；路径和接口权限为只读说明。
- 图标显示预览，并以图标选择按钮替代手工输入框。
- 排序值不再暴露；改为同一导航分组内的上移、下移按钮。
- 启用使用单一开关。关闭代表页面全局停用，普通账号即使已被勾选也不能访问。
- 每个页面增加“账号访问配置”按钮，打开账号清单；使用单个复选框“允许访问此页面”，支持账号名过滤与批量保存。

页面配置按路由统一生效，同一路径出现多个历史导航项时使用同一份账号授权，消除重复记录带来的访问歧义。

## 管理权限与审计

系统管理员与项目负责人可进入导航配置并保存账号页面授权。保存操作必须记录审计日志：操作者、页面、变更前后的账号白名单和结果。

项目负责人配置账号页面时可管理全部项目，并拥有全部项目的访问与配置权；其为其他账号配置页面后，其他账号仍受自身项目成员、任务归属和数据范围校验约束。

## 实施顺序

1. 新增账号页面白名单表与迁移。
2. 增加页面-接口能力目录和统一账号授权判断，移除角色 `page.*` 对页面路由的限制。
3. 调整根路径始终跳转 `/profile`，未配置页面的账号仅看到个人信息入口。
4. 改造导航配置页面为图标选择、上下排序、启用开关和账号授权弹窗。
5. 赋予系统管理员、项目负责人导航配置管理权，并加入审计记录。
6. 自动化测试与局域网手工验收。

## 测试与验收

1. 新账号登录后仅可进入 `/profile`，访问任意未配置页面返回 `403`。
2. 系统管理员或项目负责人勾选页面后，目标账号的菜单、URL 和页面绑定 API 同时可用。
3. 取消勾选后，菜单消失，URL 和页面绑定 API 返回 `403`。
4. 系统管理员始终可管理导航；项目负责人可以配置账号，并可访问、查看和配置全部项目；普通账号仍受项目、任务和数据范围限制。
5. 页面全局停用时，所有普通账号均不可访问；重新启用后恢复已保存的账号授权。
6. 同一路由的重复导航项使用同一授权结果，图标、排序和启用控件符合配置页交互要求。
