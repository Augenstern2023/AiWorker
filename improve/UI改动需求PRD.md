# AiWorker UI 改动需求 PRD

## 1. 背景

当前 AiWorker Web 工作台已包含控制台、参数配置、数据管理、配置编辑等页面，但部分页面仍存在以下问题：

- 参数配置页包含“项目与关键词”“指定 ID”等配置块，和后续配置文件表单化方案存在信息重复。
- 数据管理页当前主要展示部分 JSON 数据文件，未覆盖爬取任务产生的全部数据资产。
- 配置编辑页仍以直接编辑 `data.json` 文本为主，对非技术用户不友好，且缺少字段校验和项目级配置管理能力。

本次改动目标是降低配置成本、提升数据产物可见性，并为音频分析能力提供入口。

## 2. 目标

1. 精简参数配置页，移除冗余的项目、关键词、指定 ID 配置区域。
2. 扩展数据管理页，使其可统一展示爬取产生的所有数据文件。
3. 为音频文件增加分析能力入口，支持语音转文字和音频摘要生成。
4. 重构配置编辑页，从“直接编辑 JSON 文本”调整为“配置表单填写 + JSON 兼容保存”。
5. 保持现有 `data.json` 配置格式不变，避免影响已有爬虫运行逻辑。
6. 清理无实际业务作用的冗余参数，避免用户继续维护无效配置。

## 3. 非目标

- 不调整爬虫核心抓取逻辑。
- 不调整榜单爬取逻辑；榜单爬取仅支持抖音、红果。
- 不变更 `data.json` 的最终存储结构。
- 不重构登录、任务启动、任务停止等控制台能力。
- 不新增数据库表结构；音频分析结果默认只在前端预览，用户点击下载后再保存为文件。

## 4. 用户角色

- 运营用户：通过 Web 工作台配置任务、查看爬取结果、下载数据文件。
- 管理用户：维护项目配置、筛选规则和数据文件。
- 技术用户：需要保留对现有 `data.json` 配置格式的兼容和可追溯能力。

## 5. 需求范围

### 5.1 参数配置页精简

#### 需求描述

在“参数配置”页面中移除以下区域：

- 项目与关键词
- 指定 ID

移除后，页面仅保留基础配置、运行配置、登录相关配置等通用任务参数。

#### 交互要求

- 页面布局应在移除右侧区域后自动重排，避免出现大面积无意义空白。
- 与项目、关键词、指定 ID 相关的输入应迁移到新的“配置编辑”表单或由后端配置文件加载。
- 保存参数时，不应再依赖被移除区域中的字段。

#### 验收标准

- 参数配置页不再展示“项目与关键词”“指定 ID”两个模块。
- 用户仍可正常选择媒体平台、爬取类型、登录方式、保存方式等基础参数。
- 启动任务时，不因移除字段导致前端报错。

### 5.2 数据管理页扩展

#### 需求描述

“数据管理”页面需要展示爬取任务产生的全部数据文件，而不仅限于当前已展示的数据类型。

扫描范围包含任务输出目录下的全部子目录，确保不同平台、不同任务、不同文件类型的产物都能在数据管理页统一检索和展示。

需覆盖的文件类型包括但不限于：

- `.json`
- `.md`
- `.wav`
- `.mp4`
- 其他由爬虫任务生成的文件类型

#### 列表字段

数据列表至少包含：

- 文件名
- 文件路径
- 文件大小
- 修改时间
- 文件类型 / 分类
- 操作

#### 文件分类建议

- 内容数据：JSON、Markdown、CSV、Excel 等
- 媒体文件：音频、视频、图片等
- 任务文件：配置、日志、临时结果等
- 未识别：无法归类的其他文件

#### 操作要求

所有文件应支持：

- 下载
- 按文件类型筛选
- 按文件名或路径搜索

音频文件额外支持：

- 分析

视频、Markdown、JSON 等文件可保留后续扩展入口，但本期不强制要求预览能力。

#### 验收标准

- 数据管理页可递归扫描任务输出目录下的全部子目录，并展示 `.json`、`.md`、`.wav`、`.mp4` 文件。
- 列表中文件类型分类准确，无法识别时展示为“未识别”或“unknown”。
- 文件下载功能对所有展示文件可用。
- 筛选和搜索不会破坏现有下载能力。

### 5.3 音频分析能力

#### 需求描述

在数据管理页中，当文件类型为音频时，操作栏新增“分析”按钮。

点击“分析”后，系统应支持：

- 语音转文字
- 生成音频摘要

音频分析使用现有 LLM 接口完成，不新增本地模型或第三方分析服务接入。

#### 交互流程

1. 用户在数据管理页找到音频文件。
2. 点击“分析”按钮。
3. 系统展示分析状态，例如：待分析、分析中、分析完成、分析失败。
4. 分析完成后在前端预览转写文本和摘要。
5. 用户确认结果后，可点击下载保存分析结果。
6. 点击“分析”后不默认直接保存结果文件。

#### 结果字段

音频分析结果至少包含：

- 原始音频文件名
- 转写文本
- 摘要
- 分析时间
- 分析状态
- 错误信息，若分析失败

#### 验收标准

- 仅音频文件展示“分析”按钮。
- 点击“分析”后有明确的状态反馈。
- 分析成功后可查看语音转文字内容和音频摘要。
- 分析结果默认只在前端预览，不自动写入本地文件。
- 用户点击下载后，才将分析结果保存为文件。
- 分析失败时展示可理解的错误提示，不影响数据管理页其他功能。

## 6. 配置编辑页重构

### 6.1 页面目标

将当前“直接编辑 `data.json` 文本”的配置方式，调整为表单化配置方式。

新的配置编辑页需要：

- 支持加载现有 `data.json`。
- 支持通过表单编辑所有现有参数。
- 支持新增、编辑、删除项目配置。
- 保存后仍生成原格式 `data.json`。
- 保留备份能力。
- 不保留“高级模式”或“源码模式”查看、编辑原始 JSON。

### 6.2 顶层配置表单

配置页应支持编辑 `data.json` 中的顶层参数，包括但不限于：

- `host`
- `video_filter`
- `sleep`
- `autoRun`
- `items`

实际字段以现有 `data.json` 配置结构为准，字段含义和存储格式不变。

### 6.3 项目配置管理

#### 新增项目

页面提供“项目添加”按钮。

点击后，在项目列表中新增一组项目配置表单。

每组项目配置至少包含：

- `project`
- 评论不少于
- 搜索关键词
- 屏蔽关键词
- 有关视频判定
- 黑名单视频判定
- 作品天数
- 白名单地区
- 黑名单地区

`username` 不作为项目配置字段展示或新增。若历史 `data.json` 中已有 `username`，页面加载时应忽略该字段；保存时不再写回项目配置。若上传接口仍需要身份标识，应改由独立的上传配置、登录态或系统默认值提供，不应混入项目筛选配置。

#### 冗余字段清理

配置表单仅展示和业务运行直接相关的字段。对无实际作用、历史遗留或仅用于临时导入的字段，应遵循以下规则：

- 不在表单中展示。
- 新增项目时不生成该字段。
- 保存配置时不写回项目配置。
- 若字段仍被某个旧流程依赖，应先迁移到对应模块的专用配置中，并在 PRD 或实现说明中标明来源。

#### 编辑项目

- 每个项目配置以独立表单块展示。
- 用户可展开、折叠项目配置。
- 长文本字段应使用多行输入框。
- 数字字段应使用数字输入。
- 布尔字段应使用开关或复选框。

#### 删除项目

- 每个项目配置提供删除操作。
- 删除前需要二次确认。
- 删除后保存才写入 `data.json`。

### 6.4 动态校验规则

表单项需要根据运行参数灵活校验。

#### 搜索类型

当爬取类型为“搜索”时：

- 搜索关键词必填。
- 至少需要一个项目配置。

#### 榜单类型

当爬取类型为“榜单”时：

- 不强制配置项目。
- 搜索关键词不必填。
- 榜单爬取逻辑不做改动。
- 榜单爬取仅支持抖音、红果；其他平台选择榜单类型时应给出不可用提示或禁用该选项。

#### 其他类型

当爬取类型为详情、创作者或其他类型时：

- 按现有业务参数要求进行校验。
- 不得出现与当前类型无关的强制必填项。

### 6.5 保存和加载

#### 加载

- 页面进入时默认加载 `data.json`。
- 提供“重新加载”按钮。
- 若 `data.json` 格式异常，应提示错误并阻止覆盖保存。

#### 保存

- 点击“保存修改”时，前端先完成表单校验。
- 校验通过后生成和现有格式一致的 `data.json`。
- 保存前应自动生成备份，或沿用现有备份机制。
- 保存成功后展示成功提示。

#### 验收标准

- 页面不再以大文本编辑器作为主要配置方式。
- 页面不提供“高级模式”“源码模式”或原始 JSON 编辑入口。
- 用户可通过表单完成 `data.json` 的加载、编辑、保存。
- 保存后的 JSON 字段名、层级结构和原格式保持一致。
- 新增、删除、修改项目后，重新加载页面能正确回显。
- 非法配置无法保存，并能提示具体字段。

## 7. 兼容性要求

- 后端读取配置的逻辑不应因 UI 改造而改变。
- 历史 `data.json` 文件应可被新页面正常加载。
- 若历史配置缺少新表单中的可选字段，页面应使用空值或默认值回显。
- 若历史配置包含 `username` 等项目级冗余字段，页面应兼容读取但不继续展示和保存。
- 文件扫描范围应兼容现有数据目录结构，并覆盖任务输出目录下的全部子目录。

## 8. 权限与安全

- 文件下载仅允许下载数据目录或允许目录下的文件，避免路径穿越。
- 配置加载和保存仅允许操作指定配置文件。
- 音频分析不得暴露本地绝对路径给非必要接口。
- 音频分析结果默认不落盘，只有用户点击下载时才保存文件。
- 错误信息不得包含敏感 Cookie、账号、Token 等内容。

## 9. 验收清单

- 参数配置页已移除项目、关键词、指定 ID 相关模块。
- 数据管理页可展示 JSON、Markdown、音频、视频等多类型文件。
- 数据管理页扫描范围包含任务输出目录下的全部子目录。
- 数据管理页支持文件筛选、搜索、下载。
- 音频文件操作栏存在“分析”按钮。
- 音频分析使用现有 LLM 接口，支持转写文本和摘要结果预览。
- 音频分析结果不会默认保存，用户点击下载后才保存。
- 配置编辑页改为表单化编辑。
- 配置编辑页不保留原始 JSON 高级模式。
- 配置编辑页支持加载现有 `data.json`。
- 配置编辑页支持添加、删除、编辑项目配置。
- 项目配置表单不再展示或保存 `username` 等无实际作用字段。
- 搜索类型下搜索关键词必填。
- 榜单类型下项目配置非必填，且榜单爬取仅支持抖音、红果。
- 保存后的 `data.json` 与原结构兼容。
- 保存前或保存时具备备份机制。

## 10. 优先级

| 优先级 | 模块 | 说明 |
| --- | --- | --- |
| P0 | 配置编辑页表单化 | 直接影响用户配置任务的可用性 |
| P0 | 参数配置页移除冗余模块 | 避免重复配置和用户误解 |
| P1 | 数据管理展示所有文件类型 | 提升数据产物可见性 |
| P1 | 文件筛选、搜索、下载 | 保证数据管理基础效率 |
| P2 | 音频分析 | 依赖语音转文字和摘要能力，可分阶段上线 |

## 11. 已确认决策

1. 音频分析使用现有 LLM 接口。
2. 分析结果支持前端预览；点击“分析”后不默认保存，用户点击下载后再保存。
3. 数据管理页扫描范围包含任务输出目录下的全部子目录。
4. 配置编辑页不需要保留“高级模式”查看或编辑原始 JSON。
5. 榜单爬取逻辑不做改动；榜单爬取仅支持抖音、红果。
