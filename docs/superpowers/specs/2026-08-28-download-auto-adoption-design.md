# 下载时自动采纳设计

## 背景

“剧目检索下载”页面仍通过 `resolveSourcePackageWorkflowTask()` 查找、领取并开始
`source_package` 人工任务。当前选品阶段已经迁移为不可变阶段快照，后端
`_job_task_context(..., expected_task_type="source_package")` 也明确允许已采纳选题
在没有工作流任务的情况下创建下载任务。因此，页面提示“先采纳并领取任务”属于
遗留约束，与当前流程不一致。

## 目标

- 用户点击“下载剧集”时，将该动作视为明确的采纳意图。
- 下载入口自动取得一个已采纳选题，再创建下载任务。
- 不创建、领取或启动 `source_package` 工作流任务。
- 保留选题决策与下载任务的审计记录。
- 对重复点击和并发请求保持幂等，不产生同名重复选题。

## 非目标

- 不改变选题库中手动采纳、拒绝和归档的操作。
- 不恢复旧版素材包人工任务流程。
- 不改变下载来源选择、付费内容跳过、剧集选择或下载 Worker。
- 不自动覆盖已拒绝或已归档的人工决策。

## 交互行为

“下载剧集”按钮保持现有位置和视觉样式。点击后沿用现有加载态，并依次显示
“正在采纳选题…”和“正在创建下载任务…”。不增加确认弹窗，因为点击下载本身就是
明确动作。

按规范化剧名处理选题：

| 当前状态 | 行为 |
| --- | --- |
| 不存在 | 创建选题并直接标记为 `adopted` |
| `pending_review` | 自动更新为 `adopted` |
| `adopted` | 复用现有选题 |
| `rejected` / `archived` | 返回冲突，不静默覆盖人工决策 |

冲突提示为“该剧目已被拒绝或归档，请先在选题库恢复后再下载”。采纳失败时不创建
下载任务；采纳成功而下载任务创建失败时保留已采纳状态，用户可直接重试下载。

## 后端设计

在 `CreativeRepository` 增加事务化的下载选题解析方法。该方法使用规范化剧名在
`BEGIN IMMEDIATE` 事务内查重，按上表创建、采纳、复用或拒绝，并在状态发生变化时
写入 `topic_decision` 阶段快照。新选题保存下载搜索提供的最小来源证据，包括平台、
来源 Provider 和剧集引用；不保存令牌或播放地址。

红果下载与抖音降级下载的创建接口允许省略 `topic_id`。省略时，接口在创建 Job 前
调用上述解析方法；传入 `topic_id` 时继续验证剧名和已采纳状态，保持选题库下载入口
兼容。两种路径都不解析或关联 `source_package` 工作流任务。

自动采纳沿用下载接口的 `drama.download` 与 `job.create.selection` 权限边界。审计增加
`selection.topic_adopt_from_download`，记录选题 ID、稳定来源标识和状态变化；下载 Job
继续使用现有 `job.create` 审计。

## 前端设计

`startDramaAnalysis()` 不再调用 `resolveSourcePackageWorkflowTask()`，也不再发送
`workflow_task_id`。它直接把剧名、平台、Provider、剧集引用和所选集数发送到现有
下载 Job 接口，并使用响应中的选题 ID 更新本地下载上下文。

选题库中的全剧下载路径继续发送现有 `topic_id`，行为不变。旧的
`resolveSourcePackageWorkflowTask()` 若没有其他调用方则删除，避免以后重新引入领取
依赖。

## 并发与错误处理

- 规范化标题查重和状态转换在同一数据库事务中完成。
- 两个并发下载请求最多创建一个选题；后到请求复用已采纳选题。
- 已拒绝或归档时返回 HTTP 409 和稳定中文提示。
- 无下载权限时在任何选题写入前返回 HTTP 403。
- Job 冲突沿用现有 HTTP 409，不回滚用户已经表达的采纳意图。

## 测试

后端测试覆盖：不存在、待评估、已采纳、已拒绝/归档、并发同名请求、无权限请求，
并断言没有创建或领取 `source_package` 任务，Job 的 `workflow_task_id` 为空。

前端测试覆盖：下载方法不读取工作流任务、不调用 claim/start、不发送
`workflow_task_id`，并在后端冲突时展示可操作的恢复提示。现有选题库全剧下载测试
继续通过。

验收时运行相关 Pytest，并在桌面与移动视口验证下载按钮的加载态、错误提示和现有
布局没有回归。
