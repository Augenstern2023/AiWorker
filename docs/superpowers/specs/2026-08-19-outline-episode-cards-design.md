# 分集大纲折叠卡片 UI 设计规格

**日期：** 2026-08-19  
**页面：** `/writing/projects/{project_id}/outlines`  
**范围：** 仅优化分集大纲列表区域，不改变页面路由、后端接口、生成流程或版本规则

## 目标

将分集大纲的横向大表格替换为可搜索的纵向剧集卡片列表，消除超长横向滚动，并在不删减任何字段、状态和操作的前提下提高编剧对多集内容的浏览与编辑效率。

## 保持不变的页面区域

- 左侧主导航与顶部项目标题栏保持原位。
- “全剧大纲”“分集大纲”标题及工作流状态保持不变。
- 创作方向、切换方向、人物关系版本、切换版本模块的位置和业务逻辑保持不变。
- 剧本下载、生成/重新生成大纲、完成并锁定、下载当前大纲等顶部操作全部保留。
- Beats 与场次剧本更新记录弹窗保持不变。
- 后端数据结构、保存接口、版本接口和权限规则不变。

## 选定方案

采用单列剧集卡片列表，并在展开区使用高密度双栏字段网格。

- 桌面端：每行两个字段分组，兼顾扫描速度与信息密度。
- 窄屏端：字段网格自动降为单栏，操作区允许换行。
- 页面只产生纵向滚动；卡片及字段不得造成页面横向滚动。

## 列表工具栏

剧集列表右上方增加紧凑工具栏：

1. 搜索框：即时匹配集数和核心事件关键词，忽略输入首尾空格及英文大小写。
2. “全部收起”：收起当前筛选结果中的全部卡片。
3. “全部展开”：展开当前筛选结果中的全部卡片。

搜索结果为空时显示“未找到匹配的分集大纲”，并保留搜索框以便用户修改条件。项目没有大纲数据时继续显示“暂无分集大纲”。切换项目、创作方向或人物关系版本并载入新数据后，卡片恢复默认全部收起状态。

## 卡片收起状态

每集对应一个独立卡片，默认收起。卡片头部始终显示：

- 集数，格式为“第 N 集”。
- 核心事件单行预览；超长文本使用省略号截断，原生 tooltip 展示完整内容。
- 绿色“剧本已完成”徽章，仅在该集已存在当前有效场次剧本时显示，并保持原有跳转能力。
- 蓝色“Beats 更新”或现有更新摘要，仅在该集存在相应更新时显示，点击继续打开原有更新记录弹窗。
- 保存按钮仅在当前大纲为可编辑草稿时显示。
- 打开 Beats 的向右箭头始终显示，并保持原有跳转地址。
- 展开/收起指示按钮始终显示。

卡片头部主区域可点击或通过键盘激活以展开详情。保存、状态徽章、更新记录和跳转按钮使用独立交互区域，不触发卡片折叠。

## 卡片展开状态

展开区完整保留六个原始业务字段，不改变字段键或保存数据：

| 展示标题 | 数据字段 |
|---|---|
| 核心事件 | `item.content.core_event` |
| 冲突 | `item.content.conflict` |
| 人物推进 | `item.content.character_progress` |
| 亮点 | `item.content.highlight` |
| 反转 | `item.content.reversal` |
| 结尾悬念 | `item.content.cliffhanger` |

每个字段使用“标题 + 文本框”的独立分组。文本框保留现有双向绑定，设置稳定的最小高度与最大高度，内容超出最大高度时在文本框内部滚动，不溢出卡片。用户仍可手动调整文本框，但宽度不得突破字段容器。

展开区保留原有单集操作：保存当前集大纲、打开单集 Beats。卡片头部中的剧本状态、更新记录和跳转操作在展开后仍然可见。

## 编辑与版本规则

- AI 生成后的草稿版本可编辑；展开卡片后六个字段均为可编辑文本框。
- 草稿卡片显示单集保存按钮，继续调用现有 `saveProjectEpisode(item)` 保存逻辑和反馈状态。
- 已锁定或已批准版本保持只读，文本框禁用并隐藏保存按钮。
- 锁定版本不允许被直接覆盖；修改必须沿用现有重新生成/新建版本流程，产生新的可编辑版本。
- 本次改造不改变 `creativeResourceEditable(item)` 的判定逻辑。

## 前端状态与方法

大纲页面状态增加：

- `outlineQuery`：当前搜索文本。
- `expandedOutlineEpisodes`：按集数记录展开状态的普通对象，避免依赖 `Set` 的响应式行为。

大纲页面提供以下行为：

- `filteredProjectOutlines()`：从 `currentProjectOutlines()` 派生搜索结果，不修改原数组。
- `outlineEpisodeExpanded(episodeNumber)`：读取单集展开状态。
- `toggleOutlineEpisode(episodeNumber)`：切换单集展开状态。
- `expandAllOutlineEpisodes()`：展开当前筛选结果。
- `collapseAllOutlineEpisodes()`：收起当前筛选结果。
- `resetOutlineEpisodeCards()`：在项目或版本上下文变化后清空搜索和展开状态。

筛选不会丢失编辑内容，因为结果仍引用 `currentProjectOutlines()` 中的原始条目。展开状态与筛选状态属于纯前端视图状态，不提交到后端。

## 视觉规范

- 页面背景沿用深色工作台，并将基准保持在 `#12151d` 附近。
- 剧集卡片使用 `#1e222c`，字段分组使用略深的内层背景。
- 默认边框低对比；hover 和键盘焦点使用淡蓝高亮，不使用大面积发光或卡通效果。
- 主要文字为浅灰白，次要文字为冷灰，分组标题使用蓝色强调。
- 剧本完成徽章使用绿色，Beats 更新徽章使用蓝色。
- 间距、圆角和按钮尺寸保持紧凑，适合高信息密度的 B 端编剧工作台。
- 动画仅用于箭头旋转、边框和详情淡入；`prefers-reduced-motion` 下关闭非必要动画。

## 可访问性与交互边界

- 折叠控制使用真实按钮并维护 `aria-expanded` 与详情区关联。
- 所有图标按钮保留可辨识的 `title` 和 `aria-label`。
- 搜索框具有可见或辅助技术可读的标签。
- 键盘焦点清晰可见，Tab 顺序与页面阅读顺序一致。
- 操作按钮阻止折叠事件冒泡，避免保存或跳转时误收起卡片。
- 小屏字段单栏排列，按钮可换行，触控目标保持可点击。

## 错误与反馈

- 保存继续使用现有错误提示与成功反馈，不新增静默失败路径。
- 搜索仅影响本地展示，不触发请求，因此不存在搜索网络错误状态。
- 页面加载错误和生成任务状态继续由现有创作工作台处理。
- 空数据与无匹配结果使用不同文案，帮助用户区分“尚未生成”和“筛选无结果”。

## 测试与验收

自动化测试覆盖：

1. 默认所有卡片收起。
2. 单卡展开/收起互不影响其他卡片。
3. 全部展开/收起只影响当前筛选结果。
4. 搜索可按集数和核心事件关键词匹配，并正确处理空查询和无结果。
5. 筛选结果继续引用原始条目，编辑不会被复制或丢失。
6. 草稿显示可编辑字段与保存按钮；锁定版本只读并隐藏保存按钮。
7. 六个业务字段、剧本完成徽章、Beats 更新、保存和 Beats 跳转均存在。
8. 收起与展开状态下，状态徽章和操作按钮始终可见。
9. 桌面端双栏、窄屏单栏，页面不产生横向滚动。
10. 卡片 hover、焦点、键盘展开与 reduced-motion 状态可用。

视觉验收使用实际页面数据分别检查桌面宽屏与窄屏，确认长核心事件被截断并可通过 tooltip 查看全文，长字段在卡片内部滚动，控件无重叠或裁切。

## 非目标

- 不改变大纲生成提示词或生成内容。
- 不改变大纲、Beats、剧本的数据库结构和接口。
- 不改变锁定、审批、新建版本或下载规则。
- 不移动人物关系版本模块，不重做侧栏或页面其他工作区。
- 不引入新的前端框架或第三方组件库。
